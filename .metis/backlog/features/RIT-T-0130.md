# check-best-practices: cap and prioritize MISSING_QUANTIFICATION to the highest-value bullets

## Objective **[REQUIRED]**

Raise the signal density of the best-practices `MISSING_QUANTIFICATION` rule.
Today `analyze_best_practices` (`packages/scoring/src/resume_kit_scoring/
best_practices.py`) emits ONE `NEEDS_USER_INPUT` finding for EVERY experience
bullet lacking a number. On a 16-bullet resume that is 16 identical elicitation
prompts — a "wall" that makes the standard walkthrough (`update-best-practices`
/ `build-standard`) low-density and tedious, and none are auto-suggestible (a
metric can never be fabricated). Cap and prioritize to the few bullets where a
metric adds the most, while never silently hiding the rest.

## Backlog Item Details

### Type
- [x] Feature - New functionality or enhancement (UX quality of an existing rule)

### Priority
- [x] P2 - Medium (nice to have)

### Business Justification
- **User Value**: The quantification interview drops from ~16 identical prompts
  to ~3 targeted ones aimed at the bullets that most beg a number, so users
  actually finish it. Progressive disclosure (re-run after applying) still
  surfaces the next batch.
- **Business Value**: Higher completion of the standard baselining step, which
  gates all downstream tailoring.
- **Effort Estimate**: S.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `analyze_best_practices` emits at most `_MISSING_QUANT_CAP` (=3) per-bullet
      `MISSING_QUANTIFICATION` findings, each still `NEEDS_USER_INPUT` and located
      at its exact `(experience, entity_id, bullet_index)` so the user's rewrite
      remains auto-applicable to that bullet (unchanged apply path in standard_fix).
- [ ] Prioritization is deterministic: bullets containing an impact/achievement
      verb (improved, reduced, increased, launched, ...) but no number rank first
      (a metric adds the most there); ties break by resume order (recency).
- [ ] When more than the cap lack quantification, exactly ONE aggregate advisory
      finding (`MISSING_QUANTIFICATION_MORE`, severity `review-note`,
      `NEEDS_USER_INPUT`, section `experience`, NO `bullet_index`) is emitted, its
      message stating how many additional bullets lack a metric. It safely defers
      in `standard_fix` (`_apply_to_location` returns False without a bullet_index).
- [ ] No aggregate finding when the count is at or below the cap.
- [ ] Deterministic: identical input → identical findings and ordering.
- [ ] Existing best-practices + standard_fix + baseline + integration tests pass;
      new tests cover: prioritization order, the cap, and the aggregate note.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- In the bullet loop, keep emitting WEAK_OPENER / FIRST_PERSON / BUZZWORD inline;
  instead of emitting `MISSING_QUANTIFICATION` inline, COLLECT candidates as
  `(order_index, has_impact_verb, location)`.
- After the loop, sort candidates by `(has_impact_verb desc, order_index asc)`,
  take the first `_MISSING_QUANT_CAP`, and emit each as the current per-bullet
  finding. If `len(candidates) > cap`, append the single aggregate note.
- Add `_IMPACT_VERBS: frozenset[str]` and `_MISSING_QUANT_CAP = 3` module
  constants; document `MISSING_QUANTIFICATION_MORE` in the module rule-code list.
- Group-by-role was rejected: `standard_fix._apply_to_location` targets a
  specific `bullet_index`, so a role-level finding could not carry the user's
  quantified rewrite back to a concrete bullet — it would regress the rule from
  applicable to advice-only. Per-bullet cap keeps apply-ability.

### Dependencies
Sibling of RIT-T-0126/0127/0128 (same triage). Independent.

### Risk Considerations
- Silent truncation: mitigated by the aggregate note (explicit remaining count)
  plus standard_fix's documented re-run progressive disclosure.
- Cap value: 3 is a judgement call exposed as a module constant for easy tuning.
- Impact-verb list is a heuristic; a bullet with a real achievement but an
  unlisted verb simply falls to the recency tiebreak — still surfaced if within
  the cap, still counted in the aggregate otherwise. No correctness risk.

**Recommended Agent: sonnet + medium** — single-file analyzer change with the
design fully specified; the apply-path invariant (per-bullet location) is the
one thing to preserve.
