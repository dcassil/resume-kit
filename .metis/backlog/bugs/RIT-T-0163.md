# check-best-practices (analyze-best-practices --resume) misreads the canonical structure format: bullets not detected → false 'zero findings' while build-refine's internal analyzer finds real MISSING_QUANTIFICATION

## Objective **[REQUIRED]**

Fix the read-only best-practices analyzer so that when it is run over a canonical `structure`-format
resume it detects experience bullets and reports the same findings the build-refine pass does. Today
the two disagree:

- `resume_analyze_best_practices` / `analyze-best-practices --resume` (the read-only check that drives
  the `check-best-practices` skill) reads the canonical `structure.json` format incorrectly — it does
  not detect the bullets — and therefore returns **0 findings** ("all clean").
- `build-refine` first *projects* the resume properly and its internal analyzer then finds **16
  MISSING_QUANTIFICATION** items (one per experience bullet) on the exact same input.

The read-only check thus understates findings and gives a false "clean" signal, so a user who runs
`check-best-practices` before tailoring is told there is nothing to fix when there are 16 real items.

Discovered during a baseline debug run on 2026-08-10 (resume-kit 0.9.0 / plugin 1.2.0): a
`check-best-practices` run over `structure.json` returned zero findings, but the immediately-following
`build-refine` reported 16 MISSING_QUANTIFICATION findings on the same resume.

## Backlog Item Details **[CONDITIONAL: Backlog Item]**

- [x] Bug - Production issue that needs fixing

### Impact Assessment **[CONDITIONAL: Bug]**
- **Affected Users**: Anyone who runs `check-best-practices` (read-only) against a canonical
  `structure`-format resume to decide whether to refine — they are told "clean" when it is not.
- **Reproduction Steps**:
  1. Take a resume in canonical `structure.json` form with experience bullets that lack metrics.
  2. Run `check-best-practices` (`resume_analyze_best_practices` / `analyze-best-practices --resume`).
  3. Observe: 0 findings.
  4. Run `build-refine` on the same resume; observe 16 MISSING_QUANTIFICATION findings.
- **Expected vs Actual**:
  - **Expected**: the read-only analyzer reads the canonical structure format the same way build-refine
    does (via the same projection), detects the bullets, and reports the same findings.
  - **Actual**: it fails to detect bullets in the canonical structure format and returns 0 findings.

## Acceptance Criteria **[REQUIRED]**

- [ ] The read-only best-practices analyzer detects experience bullets when given a canonical
      `structure`-format resume — it projects/reads the input the same way build-refine's internal
      analyzer does (single shared projection, no divergent reader).
- [ ] Running `check-best-practices` and `build-refine`'s analysis over the same resume yields the same
      finding set (same rule codes, same count) for the deterministic rules — specifically the 16
      MISSING_QUANTIFICATION items in the reproducer are reported by both.
- [ ] Regression test: a canonical `structure`-format fixture with N metric-less bullets produces N
      MISSING_QUANTIFICATION findings from the read-only analyzer (not 0).
- [ ] Parity test: assert the read-only analyzer and the build-refine internal analyzer return identical
      finding sets for a shared fixture, guarding against future divergence.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Root cause is a format/reader mismatch: the read-only path reads the canonical structure JSON directly
  while build-refine projects it (canonical → BuildDoc/ScoreDoc) before analyzing, so only the build path
  sees the bullets. Fix by making the read-only analyzer run the same projection before analysis.
- Anchors: analyzer + surfaces live at
  `packages/schemas/src/resume_kit_schemas/best_practices.py` (report schema),
  `packages/facade/src/resume_kit_facade/baseline.py` and
  `packages/facade/src/resume_kit_facade/capabilities.py` (facade capability that build-refine and the
  read-only check both call), CLI `packages/cli/src/resume_kit_cli/app.py`,
  MCP `packages/mcp/src/resume_kit_mcp/tools.py`. Find the analyzer entry the read-only capability calls
  and route it through the same projection build-refine uses (see the projection introduced in RIT-I-0017
  / `project_scoredoc`).
- Ideal fix: both paths call ONE analyzer over ONE projected representation, eliminating the possibility
  of divergence rather than patching the reader to also handle canonical format.

Recommended Agent: opus + medium — spans the facade analyzer capability, the projection bridge, and the
read-only vs. build analysis paths; the correct fix unifies them onto one projection. Bounded but
cross-cutting across scoring/facade, and it must not change build-refine's existing behavior.

### Dependencies
- ScoreDoc projection (RIT-I-0017 / RIT-T-0106 `project_scoredoc`) — the representation build-refine
  analyzes over.
- Best-practices analyzer + report schema (RIT-T-0116, RIT-T-0117) and the refine build (RIT-I-0020).
- Overlaps RIT-T-0164 (best-practices output emits null code / resume_version) — same report surface;
  can be worked by the same agent.

### Risk Considerations
- The fix must not change build-refine's findings (which are correct); only the read-only path should be
  brought into agreement.
- Routing the read-only check through projection must stay read-only — it must not mutate or write any
  resume version as a side effect.

*2026-08-10 — Fixed (worktree agent-a4edd9d87970eb9d0).* Root cause confirmed: the read-only surfaces
validated a canonical `structure.json` payload directly with `ResumeDocument.model_validate`, which
succeeds leniently (all fields defaulted) and drops `work[].achievements` because the BuildDoc field is
`workExperience[].description` — so the analyzer saw zero bullets and returned 0 findings. `build_refine`
instead projects canonical → BuildDoc via `project_builddoc_from_canonical` before analyzing, seeing all
bullets. Reproduced directly: `ResumeDocument.model_validate(structure)` → `[]`; the canonical projection
→ the expected `MISSING_QUANTIFICATION` set.
Fix: added a single shared normalization seam `normalize_resume_input(raw)` in
`resume_kit_scoring.projection` (with `is_canonical_resume_payload`) that projects canonical payloads via
the SAME `project_builddoc_from_canonical` bridge build_refine uses, and passes BuildDoc payloads through
unchanged. Routed all read-only surfaces through it — MCP (`_resume_normalized`), CLI
(`io.load_resume_normalized`), API (body accepts raw dict, route normalizes) — and re-exported it from the
facade so downstream layers share one seam. The capability also normalizes defensively. build_refine and
`baseline.py` are UNCHANGED (not in the diff). Added a parity test
(`packages/facade/tests/test_best_practices_readonly_parity.py`) asserting the read-only path and the
build_refine internal analyzer return the identical finding set on a canonical `structure` fixture (7
MISSING_QUANTIFICATION, not 0), plus a root-cause regression test and scoring unit tests for the
normalizer. Gates pass against source: ruff clean, mypy clean (facade/scoring/schemas), pytest green.
