# Stricter 0.15.1 schema: workExperience.title required non-empty breaks build-structure

## Objective **[REQUIRED]**

Decide and implement the correct handling for `workExperience` entries that legitimately have no job
title. The 0.15.1 schema made `workExperience.title` required non-empty, so `build-structure` now
throws `ValidationError(Experience.title)` on entries that 0.13.0 tolerated — surfaced by real
"date-bucket" entries (e.g. a Ventures block that groups activity under a date range with no single
title). Either relax the constraint for these shapes, or provide a deterministic canonicalization that
supplies a valid title, so faithful resumes that parsed and built under 0.13.0 do not hard-fail under
0.15.1.

## Backlog Item Details

### Type
- [x] Bug — schema-tightening regression: input that built under 0.13.0 now hard-fails at build-structure

### Priority
- [x] P2 — Medium. Blocks the structure build for resumes containing titleless/date-bucket experience
  entries; deterministic (no truth risk) but stops the pipeline for affected inputs.

### Impact Assessment
- **Affected Users**: Anyone whose source resume has experience entries without a discrete job title
  (date-bucketed roles, consolidated "Ventures" / side-project blocks, self-employment groupings).
- **Reproduction (from 0.15.1 test run)**:
  1. Parse a resume containing a `workExperience` entry with an empty/absent `title` (a date-bucket
     grouping) — faithfulness passes.
  2. Run `build-structure`.
  3. It throws `ValidationError(Experience.title)` because `workExperience.title` is now required
     non-empty. 0.13.0 tolerated the empty title and built successfully.
- **Expected vs Actual**: Expected — a faithful resume with a titleless date-bucket entry either builds
  (with a deterministic canonical title) or is rejected with a clear, actionable message at parse time,
  not an opaque validation crash at build-structure. Actual — a hard `ValidationError` mid-build.

### Root Cause (to verify against code before fixing)
- The `Experience`/`workExperience` model tightened `title` to required non-empty (identify the exact
  constraint in `packages/core` / schema models and the release that introduced it — 0.15.x). The
  parse/faithfulness path still admits titleless entries, so the failure surfaces downstream at
  `build-structure` rather than at parse.

## Acceptance Criteria **[REQUIRED]**

- [ ] A decision is made and implemented from these options (pick one, justify in the ADR/status):
      (A) relax `title` to optional/allow-empty for `workExperience` and let downstream render handle a
      missing title; (B) deterministically canonicalize a missing title to a stable placeholder derived
      from available fields (e.g. company / date range) during build-structure; or (C) reject titleless
      entries at PARSE time with a clear, actionable error instead of an opaque crash at build.
- [ ] A faithful resume containing a titleless date-bucket experience entry no longer produces an
      opaque `ValidationError(Experience.title)` at `build-structure` — it either builds or fails with a
      clear, early, actionable message.
- [ ] If canonicalization (option B) is chosen, it is deterministic (no LLM) and does not fabricate a
      role the candidate did not hold; the content ledger / faithfulness posture is preserved.
- [ ] Consistency across surfaces: the same input behaves identically via CLI/direct/MCP/API.
- [ ] Regression test with a titleless date-bucket fixture: fails before, passes after; asserts the
      chosen behavior (builds with canonical title, OR clean parse-time rejection).

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Confirm the tightened constraint location and whether the intent of the 0.15.x change was to require
  titles universally or only in a specific stage. Align the parse gate and the build-structure model so
  they agree (do not admit at parse then crash at build).
- Prefer option C or B over A if titles are genuinely required for downstream ATS/render correctness;
  prefer A only if titleless entries are a supported canonical shape.
- Keep it deterministic and provider-free (build-structure is no-LLM).

### Dependencies
- Core schema models (`packages/core`), the build-structure capability
  (`packages/facade/.../capabilities.py`), and the parse/faithfulness gate.
- Source: 0.15.1 re-test "New findings this run" — Stricter schema (0.15.1).

### Risk Considerations
- Do not weaken faithfulness or fabricate a title that misrepresents the candidate's role.
- A schema relaxation (option A) may affect ATS/render assumptions elsewhere — check the export
  renderer's handling of empty `title` before choosing A.
- Watch the [[dev-env-editable-installs]] vendoring landmine when testing.

**Recommended Agent: opus + medium** — a schema/stage-consistency decision touching core models, the
build-structure path, and render assumptions, with a faithfulness constraint; a wrong relaxation can
leak into ATS output.
