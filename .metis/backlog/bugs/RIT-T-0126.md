# check-gaps: warn when tailored and master inputs are near-identical

## Objective **[REQUIRED]**

Make `check-gaps` (the keyword-gap capability, `analyze_keyword_gap` in
`packages/matching/src/resume_kit_matching/keywords.py`) surface an explicit
warning when the `tailored` and `master` resume inputs resolve to near-identical
text. In that degenerate case `injectable_keywords` is always empty and every
missing keyword lands in `non_injectable_keywords`, which reads to a user as
"these are real, unfixable gaps" when in truth the tool simply had no distinct
master to draw from. The signal exists in the skill doc but not in the output.

## Backlog Item Details

### Type
- [x] Bug - Production issue that needs fixing

### Priority
- [x] P2 - Medium (nice to have)

### Impact Assessment
- **Affected Users**: Anyone running check-gaps without a distinct master resume
  (the common case early in onboarding, when tailored == master == the only
  resume on hand). Observed in the canonical end-to-end test run.
- **Reproduction Steps**:
  1. Run the gaps capability with the same resume passed as both tailored and master.
  2. Observe `injectable_keywords == []` and all misses in `non_injectable_keywords`.
  3. Note there is no indication that this is an input-degeneracy artifact.
- **Expected vs Actual**: Expected — output flags that tailored and master are
  near-identical so injectable classification is unreliable. Actual — silent;
  everything presents as a hard non-injectable gap.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `KeywordGapAnalysis` gains a `warnings: list[str]` field (default empty,
      backward-compatible).
- [ ] `analyze_keyword_gap` computes a similarity signal between the resolved
      tailored and master text and appends a specific warning when they are
      near-identical (identical, or above a high similarity threshold).
- [ ] The warning is emitted ONLY in the degenerate case — distinct
      tailored/master inputs produce no warning (no false positives on normal runs).
- [ ] Warning text names the cause and the consequence ("tailored and master
      resolve to near-identical content; injectable classification is unreliable").
- [ ] Unit tests: (a) identical inputs → warning present; (b) clearly distinct
      inputs → warnings empty.
- [ ] Existing keyword/gaps tests still pass.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Add `warnings: list[str] = Field(default_factory=list)` to
  `KeywordGapAnalysis` in `packages/schemas/src/resume_kit_schemas/analysis.py`.
- In `analyze_keyword_gap`, after building `tailored_text` and `master_text`,
  compute near-identity. Prefer a cheap deterministic measure: exact equality
  OR normalized-token-set Jaccard >= 0.98 (reuse the lowercased text already
  computed).
- Append the warning string to a local list and pass into the returned model.
- Keep it deterministic (no LLM, identical inputs -> identical output) to match
  the module's REQ contract.

### Dependencies
None. Self-contained in schemas + matching packages.

### Risk Considerations
- Threshold too low -> false warnings on legitimately similar tailored/master.
  Mitigate with a high threshold (>=0.98) plus the exact-equality fast path.
- Surfaces (facade/CLI/MCP) that serialize `KeywordGapAnalysis` should pick up
  the new field automatically via model dump; verify no surface hardcodes the
  field set.

**Recommended Agent: sonnet + medium** — single-capability change with the
design already specified here; mechanical once the threshold is chosen.
