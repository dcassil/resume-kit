# build-structure crashes on empty company: ResumeDocument allows empty org, canonical Experience forbids it, and the ValidationError is masked as internal_error

## Objective **[REQUIRED]**

Fix two related defects that make `build-structure` crash — opaquely — on a resume that the
`parse-resume` schema explicitly permits. Both must be addressed:

- **B1 — Schema contract mismatch.** `ResumeDocument.Experience.company` defaults to `""` and empty
  is a *documented, intended* value (the parse-resume guidance itself shows `company: ""` for lines
  like a "Career Break" / date-grouped umbrella heading). But the downstream **canonical**
  `Experience.organization` is a required non-empty string. The canonicalizer maps
  `organization=raw.company` directly, so any empty company raises a pydantic `ValidationError` and
  `build-structure` aborts. The two schemas disagree on whether empty org is legal, and the
  canonicalizer does not reconcile the gap.
- **B2 — Error masking.** The bubbling `ValidationError` is swallowed by the CLI/interface layer into
  a generic `"An internal error occurred."` (`internal_error`) with no actionable detail. A schema
  validation failure should surface as a real, specific validation message naming the field and
  entry — not an opaque internal error.

Discovered during a `parse-resume` → `build-structure` debug run on 2026-08-10 (resume-kit 0.9.0 /
plugin 1.2.0). The test resume has 3 `workExperience` entries with `company: ""` — the date-grouped
engagements under the source's `## Ventures & Consulting` heading.

### Impact Assessment **[CONDITIONAL: Bug]**
- **Affected Users**: Anyone whose resume has a work entry with an empty `company` — a shape the
  parse-resume schema sanctions (date-grouped umbrella headings, career-break lines). For them
  `build-structure` crashes outright. More broadly, B2 affects any user hitting *any* ValidationError
  in this code path: they get "An internal error occurred." with no cause.
- **Reproduction Steps**:
  1. Ingest a resume with ≥1 `workExperience` entry having `company: ""` (e.g. entries grouped under a
     single heading with the heading carried in `title` and company left empty).
  2. Run `build-structure` on the base file.
  3. Observe: CLI reports `internal_error` / "An internal error occurred." with no field detail.
- **Expected vs Actual**:
  - **B1 Expected**: the canonicalizer either accepts an empty org (carrying the parse-schema's
    intended emptiness through) or deterministically resolves it (e.g. derives org from the group
    heading / falls back), so `build-structure` completes. **Actual**: `Experience(organization="")`
    raises `ValidationError` and the build aborts.
  - **B2 Expected**: a `ValidationError` surfaces as a `validation`-class error naming the offending
    field/entry (`organization must contain text`, entry index N). **Actual**: masked as
    `internal_error` "An internal error occurred."

## Acceptance Criteria **[REQUIRED]**

- [ ] B1: `build-structure` no longer crashes on a resume with empty `company` entries. Decide and
      implement the reconciliation deliberately (see Technical Approach) — do NOT silently invent an org
      string in the canonicalizer that isn't sourced from the document.
- [ ] The two schemas' contract on empty organization is made consistent and documented: either
      canonical `Experience.organization` permits empty (matching `ResumeDocument`), or the canonicalizer
      has an explicit, documented rule for populating it, and the parse-resume guidance is updated to match
      whichever is chosen.
- [ ] B2: a pydantic `ValidationError` raised anywhere in the build path surfaces as a `validation`
      error code with a specific, actionable message (field + entry), NOT `internal_error`. The generic
      `internal_error` remains only for genuinely unexpected exceptions.
- [ ] Regression test (B1): a `ResumeDocument` with an empty-`company` work entry canonicalizes /
      `build-structure`s without raising.
- [ ] Regression test (B2): a `ValidationError` in the build path maps to the validation error code with
      a message that names the field, not the generic internal-error text.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- **B1** — root cause at `packages/scoring/src/resume_kit_scoring/shape_fix.py:317`
  (`organization=raw.company`). The canonical model is
  `packages/schemas/src/resume_kit_schemas/canonical.py:206` (`organization: str`) with the
  `_required_fields_must_have_text` validator at `canonical.py:218`; the source model is
  `packages/schemas/src/resume_kit_schemas/resume.py:60` (`company: str = ""`). Choose ONE reconciliation
  and apply it consistently:
    - (a) Relax canonical `organization` to allow empty (simplest; matches the source schema's stated
      intent that empty company is legal), OR
    - (b) In the canonicalizer, derive `organization` from the entry's group heading / `title` when
      `company` is empty — but ONLY from real document content, never a fabricated placeholder (truth posture).
  Prefer (a) unless a non-empty org is a genuine invariant the rest of the canonical pipeline relies on;
  if it is, (b) with a sourced value. Flag the decision to Daniel if it changes the canonical invariant.
- **B2** — error mapping lives in `packages/core/src/resume_kit_core/interface.py` (generic exceptions →
  `internal_error`, message "An internal error occurred." around line 149). Catch `pydantic.ValidationError`
  before the generic handler and map it to the existing `validation` error code with the pydantic message
  (or a summarized field+entry form). Mirror the existing test at
  `packages/core/tests/test_interface_mapping.py` (`test_generic_exception_maps_to_internal_error`).

Recommended Agent: opus + medium — spans the schema layer (two disagreeing Experience models), the
canonicalizer, and the core error-mapping boundary; the B1 reconciliation is a real contract decision
with truth-posture implications, and B2 touches shared error handling. Bounded but cross-cutting.

### Dependencies
- Canonical schema + shape schemas from RIT-T-0133 (defines `Experience.organization` as required — this
  bug is the friction from that requirement meeting the source schema's empty-company allowance).
- Non-destructive canonicalizer / `shape_fix.py` from RIT-T-0136 (owns the `organization=raw.company` map).
- Core interface error-mapping contract (`resume_kit_core/interface.py`, `errors.py`).

### Risk Considerations
- If B1 is fixed by deriving org from a heading (option b), it must pull ONLY real source text — a
  fabricated org would violate the faithfulness/truth posture the pipeline enforces elsewhere.
- Relaxing canonical `organization` (option a) must not break downstream consumers that assume a non-empty
  org (exporters, scorers) — audit usages before relaxing.
- B2 must keep `internal_error` for truly unexpected failures; only ValidationError (and kin) should be
  reclassified, so we don't hide real internal bugs behind a validation label.

## Status Updates **[REQUIRED]**

*Field-level diagnosis confirmed against source on 2026-08-10:*
- `resume.py:60` `company: str = ""` (empty allowed) vs `canonical.py:206` `organization: str` +
  `_required_fields_must_have_text` validator (`canonical.py:218`) rejecting empty text.
- Crash site: `shape_fix.py:317` `organization=raw.company`.
- Masking site: `interface.py:149` generic exception → `internal_error` / "An internal error occurred."
- **Discovering agent's manual workaround (NOT the fix):** set `company: "Ventures & Consulting"` (the real
  source `## Ventures & Consulting` heading — a faithful org grouping) on the 3 affected entries in the base
  file, leaving `-original.json` pristine. That unblocked the crash; `build-structure` then gated cleanly on
  unrelated custom-section mappings (`ledger_ok: false`, `structure_path: null`), which is correct behavior,
  not a bug. The workaround is per-resume and does not address B1/B2 in the tool.
