# Faithful-original invariant: no-custom transform belongs only at step 3

## Objective **[REQUIRED]**

Guarantee the ingest → learn → lossy-baseline ordering: `-original.json` must always be FULLY faithful
(retains `customSections` and their headings), and the no-custom transform must happen ONLY at step 3
(`build-structure --omit-custom-sections`). Today RIT-T-0176's parse-resume dedup guidance can lead an
agent to emit a **no-custom original**, which the step-1 faithfulness gate correctly hard-fails on the
dropped section heading (`DROPPED_SPANS`) — killing Flow 1 before evidence is ever seeded.

## Backlog Item Details

### Type
- [x] Bug — a lossy transform leaks upstream into the faithful-ingest step

### Priority
- [x] P1 — High. Hard-blocks Flow 1 at step 1 for any resume with custom sections when the parse output
  drops them; also violates the core "original is immutable + faithful" contract that evidence seeding
  and the content ledger both depend on.

### Impact Assessment
- **Affected Users**: Anyone whose source resume has a custom/non-standard section (e.g. "Technical
  Skills (categorized)", "Domains & Industries") when the parse step omits it.
- **Reproduction**: If parse emits a no-custom `-original.json`, `validate-faithfulness` finds the
  dropped section heading as a run of >=2 consecutive source tokens missing from the JSON →
  `DROPPED_SPANS` (hard-fail), non-zero exit, Step 1 rejects before base/structure/evidence.
- **Expected vs Actual**: Expected — original keeps everything (faithful); no-custom happens at step 3
  where loss is allowed and ledgered. Actual — parse guidance can drop custom at step 1, tripping the
  full-faithfulness gate.

### Root Cause (verified, file:line)
- Faithfulness treats the `customSections` dict KEY (the user's heading) as authored content:
  `packages/ats/src/resume_kit_ats/faithfulness.py:220-223`; a dropped heading is `DROPPED_SPANS`
  (hard-fail) at `faithfulness.py:339-361`.
- RIT-T-0176 added a parse-resume note to not double-write skills into `technicalSkills` AND
  `customSections`; taken literally it can yield a no-custom original. `parse-resume/SKILL.md` still
  promises the original is parsed "faithfully and losslessly," so the guidance is self-contradictory.
- Design intent (confirmed): step 3 `build-structure` uses claim-preservation + content-ledger, NOT
  source faithfulness (`baseline.py:8-12,202,262-263`), and Flow 1 opts into
  `--omit-custom-sections` there. The lossy step is `structure`, not parse.

## Acceptance Criteria **[REQUIRED]**

- [ ] `parse-resume` guidance is corrected so the `-original.json` ALWAYS retains `customSections`
      (headings + content) — fully faithful/lossless. The "don't duplicate skills" concern is moved to
      the structure/render step, never applied to the original.
- [ ] The no-custom transform is documented as belonging exclusively to step 3
      (`build-structure --omit-custom-sections`); parse never omits custom.
- [ ] Regression test: a synthetic no-custom original (custom heading dropped) is REJECTED by
      `validate-faithfulness` (`DROPPED_SPANS`), locking the invariant that originals stay faithful.
- [ ] Regression/flow test: for a resume with a custom section, Flow 1 produces a faithful original
      (custom intact), and the single-Skills-section / no-custom outcome appears only at/after
      `structure` — not at original.
- [ ] No change to the faithfulness gate itself (step 1 stays full-faithfulness) and no change to the
      step-3 claim/ledger gates.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Primarily a `parse-resume/SKILL.md` correction (and any parse capability guidance) to restore the
  faithful-original invariant; align the RIT-T-0176 dedup note to apply downstream only.
- Add the two regression tests (faithfulness rejects a no-custom original; Flow 1 original stays
  faithful). Keep them offline/deterministic.

### Dependencies
- [[RIT-I-0014]] faithfulness gate; [[RIT-I-0019]] shape/ledger; [[RIT-T-0176]] parse dedup guidance

### Risk Considerations
- Do NOT weaken step-1 faithfulness to "fix" this — the gate is correct; the lossy-original path is the
  bug. Keep the fix at the parse-guidance/invariant level.

**Recommended Agent: opus + low** — small, high-leverage invariant fix + two regression tests; wrong
relaxation would undermine the faithful-ingest contract.
