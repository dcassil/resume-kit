# job-hunter bridge: reconcile stale capability dispatch names after RIT-A-0005 rename

## Objective **[REQUIRED]**

Fix the `resume_kit_job_hunter_bridge.bridge` module, which dispatched three
facade capabilities by names that the RIT-A-0005 uniform verb-noun lexicon
rename had retired. Every affected bridge entry point raised
`KeyError` at `REGISTRY[capability]` because the registry no longer holds the
old keys.

## Backlog Item Details

### Type
- [x] Bug - Production issue that needs fixing

### Priority
- [x] P1 - High (job-hunter integration entry points were fully broken)

### Impact Assessment
- **Affected Users**: Any caller of the job-hunter bridge's analyze / validate /
  build-evidence paths (the whole `analyze_resume_for_job`, `validate_truth`,
  and `build_evidence` surface).
- **Reproduction Steps**:
  1. Call `resume_kit_job_hunter_bridge` analyze/validate/build-evidence.
  2. `_dispatch` looks up the stale name in `REGISTRY` → `KeyError`.
- **Expected vs Actual**: Expected — dispatch resolves to the current capability.
  Actual — `KeyError` on `validate-resume-truth` / `identify-resume-gaps` /
  `build-candidate-evidence`.

### Root Cause
RIT-A-0005 renamed several facade capability registry keys (verb-noun lexicon)
but the job-hunter bridge's dispatch strings were not updated in lockstep. The
breakage was MASKED in the working tree because the `.venv` was running a stale
copied umbrella wheel whose registry matched the old bridge names (see
[[dev-env-editable-installs]]); it surfaced only once packages were reinstalled
editable to verify RIT-T-0128.

## Acceptance Criteria **[REQUIRED]**

- [x] `validate-resume-truth` → `validate-facts` in the bridge dispatch.
- [x] `identify-resume-gaps` → `check-gaps` in the bridge dispatch.
- [x] `build-candidate-evidence` → `extract-evidence` in the bridge dispatch.
- [x] `integrations/job-hunter/tests/test_bridge.py` passes (all 5 previously
      failing cases).
- [x] Full suite (packages + integrations + tests) green.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Three one-line string edits in
`integrations/job-hunter/src/resume_kit_job_hunter_bridge/bridge.py`, mapping
each stale dispatch name to its current registry key (verified against the
`REGISTRY` dict in `facade/capabilities.py`). Docstring for the validate path
updated to name the current capability.

### Dependencies
Discovered while completing RIT-T-0128. No functional dependency; independent fix.

### Risk Considerations
- Low: renames only, verified against the live registry keys and the bridge's
  own tests. Follow-up worth considering (NOT in this task): a cross-surface
  parity guard asserting every bridge dispatch name exists in `REGISTRY`, so a
  future rename can't silently strand the bridge again.

**Recommended Agent: haiku + low** — mechanical rename against a known mapping.
