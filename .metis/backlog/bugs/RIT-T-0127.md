# set-active: normalize user-supplied paths to prevent working-dir prefix doubling

## Objective **[REQUIRED]**

Eliminate the path-convention footgun in `set_active`
(`packages/facade/src/resume_kit_facade/project_config.py`). Config pointers
(`active_resume`, `active_job`, and their `*_source` companions) are resolved
downstream as `working_dir(root) / pointer` (see `baseline.build_base` /
`build_standard`, which do `working_dir(root) / config.active_resume`). Users,
following the pattern of the direct-path CLI commands (`match`,
`check-structure`, `analyze-best-practices`, which are cwd-relative via
`io.load_resume`), naturally type `resume-kit/resumes/x.json`. `set_active`
stored that verbatim, so a later `build-base` computed
`resume-kit/resume-kit/resumes/x.json` and failed with a misleading doubled
path. Normalize the stored pointer to the working-dir-relative form the
downstream resolvers require so BOTH the wd-relative (`resumes/x.json`) and the
cwd-relative (`resume-kit/resumes/x.json`) forms a user might type resolve
identically.

### Impact Assessment
- **Affected Users**: Anyone using `set-active` with a path copied from the
  cwd-relative commands or from the parse-resume skill doc (which itself shows
  the `--resume resume-kit/resumes/...` form). Observed in the canonical
  end-to-end test run: set-active "succeeded", then build-base failed later.
- **Reproduction Steps**:
  1. `set-active --resume resume-kit/resumes/x-original.json`
  2. `build-base`
  3. Fails resolving `resume-kit/resume-kit/resumes/x-original.json`.
- **Expected vs Actual**: Expected — the pointer is normalized so build-base
  resolves it. Actual — verbatim store, doubled prefix, misleading failure.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Add `_normalize_pointer(value: str) -> str` in project_config.py:
  - `Path(value).is_absolute()` -> return unchanged (`wd / abs == abs`).
  - Split into parts; if `parts[0] == WORKING_DIR_NAME` and there is more than
    one part -> return `str(Path(*parts[1:]))`.
  - Otherwise return unchanged.
- Apply in `set_active` (and `set_version`) to each non-None pointer before
  assigning to the config model.
- Rationale for lexical-only: pointer is ALWAYS joined with `working_dir(root)`
  downstream, so dropping the wd-name prefix is correct regardless of cwd. This
  avoids the existence-check test breakage and the parse-resume ordering trap.

### Dependencies
Sibling of RIT-T-0126 (finding #4) and RIT-T-0128 (finding #1, job keywords),
all from the same test-run triage. Independent of both.

### Risk Considerations
- Over-stripping: only the exact `resume-kit` first component is stripped, and
  only when it is not the whole path — a resume literally named `resume-kit`
  under wd is not a realistic pointer. Low risk.
- Sources living outside the working dir are typically absolute and pass
  through untouched; relative non-`resume-kit` sources already resolve under wd
  by the existing baseline convention — unchanged.

**Recommended Agent: opus + low** — small, few files, but the resolution
invariant (`working_dir(root) / pointer`) must be preserved exactly.
