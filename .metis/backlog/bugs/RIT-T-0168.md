# align-terminology returns swap_applied:True while truth_passed:False (ambiguous semantics; a truth-failed swap should not look applied) and is silently gated on a missing evidence file

## Objective **[REQUIRED]**

Make `align-terminology`'s result semantics unambiguous and its evidence-gating explicit. Today the
capability calls `validate_resume_truth(updated, evidence)` and, when no `CandidateEvidence` exists, returns
`truth_passed: False` **while still** returning the swapped resume with `swap_applied: True`. That is
contradictory: a swap the truth gate rejected should NOT be reported as applied. Worse, the gating is
silent — the real cause (no evidence file because `extract-evidence` was never run) is not surfaced, so the
caller sees a truth failure with no actionable reason. Fix the result contract so "applied" implies "passed
the gate," and make the evidence precondition explicit.

Discovered during the alias/terminology test run on 2026-08-10: an alias-certified true-synonym swap
(`performance → web performance`) came back `swap_applied: True, truth_passed: False` with an empty
evidence set; the tester (correctly) did not commit it. Root cause confirmed: `align-terminology` calls
`validate_resume_truth(updated, evidence)` with empty evidence, so the gate can't substantiate the new
wording and returns `passed=False`.

### Impact Assessment **[CONDITIONAL: Bug]**
- **Affected Users**: Anyone running `align-terminology` before building evidence (the common case on a
  fresh project). They get a truth-failed result that still looks applied, with no hint that
  `extract-evidence` is the missing precondition.
- **Reproduction Steps**:
  1. On a project with NO `CandidateEvidence` (never ran `extract-evidence`), run `align-terminology` for an
     alias-certified true-synonym swap.
  2. Inspect the result: `swap_applied: True` AND `truth_passed: False`, no explanation of the empty-evidence
     cause.
- **Expected vs Actual**:
  - **Expected**: either the swap is NOT reported as applied when the truth gate fails (applied ⟹ passed),
    OR the capability refuses up front with a clear "no evidence — run extract-evidence first" precondition
    error. The empty-evidence cause is surfaced, not silent.
  - **Actual**: contradictory flags (`swap_applied: True`, `truth_passed: False`) and silent gating on a
    missing evidence file.

## Acceptance Criteria **[REQUIRED]**

- [ ] Result contract is consistent: a swap that fails the truth gate is NOT reported as `swap_applied:
      True`. Define one clear semantic (recommended: `applied` is true only when the change passed the gate
      and would be safe to persist; a rejected swap reports `applied: False` with the rejecting reason).
- [ ] The empty/missing-evidence condition is surfaced explicitly (a precondition error or a named reason on
      the result: e.g. `truth_reason: "no candidate evidence — run extract-evidence"`), not a bare
      `passed: False`.
- [ ] No behavior change to the truth gate itself — this is about the CAPABILITY's result contract and
      precondition messaging, not loosening `validate_resume_truth`.
- [ ] Docs/skill note: `align-terminology` requires evidence; the runbook points at `extract-evidence` as a
      precondition (or the capability performs/needs it) so the gate can substantiate wording swaps.
- [ ] Tests: (1) no-evidence run → not-applied + explicit reason; (2) with-evidence substantiating the swap →
      applied + passed; (3) the two flags can never be `applied:True, passed:False` simultaneously.
- [ ] Gates green for the alignment package (`ruff`/`mypy`/`pytest packages/alignment`).

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Locate the `align-terminology` capability (`resume_kit_alignment` — it calls `validate_resume_truth(updated,
  evidence)`). Gate the `applied` flag on `truth_passed`, or short-circuit with a precondition result when
  evidence is empty. Add a reason field carrying the truth-gate failure cause.
- Reuse the existing evidence + truth surfaces (`resume_kit_evidence`, `validate_resume_truth`); do not
  reimplement truth logic.
- Coordinate the semantics with RIT-I-0022's "yes" path, which ALSO captures evidence before proposing edits
  — the two should share the "evidence-first, then gate" posture.

Recommended Agent: sonnet + medium — a focused result-contract + precondition-messaging fix in one
capability, with the reasoning (applied ⟹ passed; surface the evidence cause) already specified here.

### Dependencies
- `resume_kit_alignment` (align-terminology capability), `validate_resume_truth`, `resume_kit_evidence`.
- Conceptually related to RIT-I-0022 (evidence-first posture) and RIT-T-0166 (once multi-word aliases match,
  the literal swap is often SCORE-NEUTRAL — see note below), and RIT-T-0165 (terminology apply is part of the
  alias-aware flow).

### Score-neutral swap note (context for the flow, not a defect of this ticket)
A terminology swap whose target is ALREADY counted via the alias (e.g. resume "performance" already matches
JD "web performance" through the alias) is score-neutral: mirroring the literal wording does not raise
keyword coverage. The value of such swaps is employer-wording fidelity, not score. The runbook/skill should
set that expectation so users don't expect a score lift from a swap the alias already satisfied. (Genuine
coverage lift for the multi-word cases depends on RIT-T-0166.)

## Status Updates **[REQUIRED]**

*Confirmed 2026-08-10:* `align-terminology` calls `validate_resume_truth(updated, evidence)`; with empty
evidence the gate returns `passed=False`, yet the capability still returns the swapped resume with
`swap_applied: True`. Contradictory contract + silent evidence precondition.

*Fixed 2026-08-10:* Reworked the `accept_terminology_alignment` result contract in
`packages/alignment/src/resume_kit_alignment/accept.py`. The gate now rejects a candidate swap whenever
`truth_after.passed` is False (previously it only rejected on a regressed contradiction, so an
unsupported/no-evidence failure slipped through as `swap_applied: True`). On rejection the swap reverts to
the untouched resume, records a `PolicyRejection(TRUTH_VALIDATION_FAILED)`, and carries a new
`AcceptResult.truth_reason`. Chosen semantic: **`swap_applied` (and a non-empty `applied`) is true ONLY when
the swap passed the truth gate and is safe to persist** — so `swap_applied: True` + `truth_passed: False` is
now impossible by construction. The empty-evidence case is surfaced with the named reason
`"no candidate evidence — run extract-evidence first, then re-run align-terminology"` (contradiction and
unsupported cases get distinct reasons). No change to `validate_resume_truth`. Added three tests
(no-evidence → not-applied + explicit reason; with-evidence → applied + passed; the two flags never
co-occur). Updated the `update-terminology` skill with an extract-evidence precondition note. Gates green:
`ruff check .` (all checks passed), `mypy packages/alignment` (no issues, 9 files),
`pytest packages/alignment` (all pass).
