# Alias-growth collision guard: validate merged payload before write (LexiconError root)

## Objective **[REQUIRED]**

Make commit-time alias growth safe: never persist an alias file that raises `LexiconError` on load, and
never let two mutually-colliding candidates in one commit batch slip through. This is the verified root
cause of the `LexiconError` observed in `POST_TEST_ISSUES.2026-08-11.md`.

## Backlog Item Details

### Type
- [x] Bug — write-path hazard that can persist a corrupt `synonyms.json`

### Priority
- [x] P1 — High. A slipped alias collision writes a corrupt alias file that then raises `LexiconError`
  on EVERY subsequent load of that project — it can effectively brick a project's alias index.

### Impact Assessment
- **Affected Users**: Anyone whose tailoring commits grow aliases (`update-terminology` /
  self-healing alias growth), especially across multiple accepted terminology edits in one session.
- **Reproduction (from code inspection)**:
  1. In one commit batch, two accepted candidates each individually pass the guard but collide with
     each other (e.g. both introduce/claim an overlapping canonical such as "data models").
  2. The guard snapshots the effective index ONCE before the loop and never refreshes, so both pass.
  3. The batch is written via `atomic_write_json` BEFORE structural validation runs, so the corrupt
     merged file persists and raises `LexiconError` on the next load.

### Root Cause (verified, file:line)
- Guard snapshots the effective alias index once before the candidate loop and never refreshes it:
  `packages/facade/src/resume_kit_facade/edit_session.py:482-487`.
- Write happens BEFORE structural validation: `atomic_write_json` at `edit_session.py:544`, then the
  structural check at `edit_session.py:545` — i.e. write-then-validate, not validate-then-write.
- `LexiconError` is raised when the alias index is ambiguous: `packages/terms/.../aliases.py:214`
  (verify exact module path).
- Additional gap: `seed-terminology` / `learn-terminology` are prose skills that append to
  `synonyms.json` directly and never traverse this guard at all — they get NO validation.

## Acceptance Criteria **[REQUIRED]**

- [ ] Alias growth is **validate-before-write**: build a trial `AliasIndex` (or equivalent) from the
      FULL merged payload (existing file + all proposed additions in the batch), confirm it does NOT
      raise `LexiconError`, and ONLY THEN `atomic_write_json`. No corrupt file is ever persisted.
- [ ] Same-batch mutual collisions are caught: if two candidates in one commit batch collide with each
      other (not just with the pre-existing index), the guard rejects/defers the offending addition(s)
      without failing the whole resume commit and without corrupting the file.
- [ ] Unsafe alias additions are SKIPPED/DEFERRED (recorded), and the truthful resume commit still
      succeeds — an ambiguous alias must never block the resume write.
- [ ] The validate-before-write guard lives in a single code-owned alias writer/merge path so ALL
      code writers share it. Investigate whether `seed-terminology`/`learn-terminology` write via a
      capability; if so, route them through the same guard. If they genuinely write raw JSON only in
      prose, either add a code-owned append capability they can call or clearly document the bypass as
      a known limitation (prefer the code path).
- [ ] Regression tests: (a) two mutually-colliding candidates in one batch → no corrupt file, resume
      commit still succeeds, offending alias deferred; (b) a candidate colliding with the existing
      index → deferred, file unchanged/valid; (c) the written file always loads without `LexiconError`.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Refactor the commit-time alias growth in `edit_session.py` so the merged payload is assembled first,
  a trial index is constructed and validated in-memory, and the write is gated on that validation.
  Either validate the whole merged batch once (preferred) or refresh the effective index per candidate
  so intra-batch collisions are visible.
- Keep the existing truth/confirmation semantics; this task is about SAFETY of the write, not relaxing
  what may be added.
- Reuse the existing `LexiconError`/ambiguity check as the validation oracle; do not reimplement
  ambiguity detection.

### Dependencies
- Existing alias index + `LexiconError` (`packages/terms`), edit-session commit path
  (`packages/facade/edit_session.py`), self-healing alias growth from [[RIT-I-0015]].
- Relates to the alias-growth-hardening item deferred in `POST_TEST_ISSUES.2026-08-11.md`.

### Risk Considerations
- Do NOT weaken truth gates or change which aliases are eligible — only make the persistence safe.
- Ensure a deferred/rejected alias is surfaced (logged in the result), not silently dropped.
- Watch the [[dev-env-editable-installs]] vendoring landmine when gating (`uv sync --all-packages
  --reinstall-package resume-kit` then `--no-sync`).

**Recommended Agent: opus + medium** — write-path correctness on the alias/edit-session commit with
new regression tests; a wrong fix can corrupt user state.
