# build-structure shape gate: 'other'/custom sections cannot satisfy the content ledger and there is no summary target at the shape stage, so ledger_ok stays false

## Objective **[REQUIRED]**

Fix the shape-stage content-ledger gate so that a resume whose content lives in "other" /
custom sections can pass `build-structure`. Today the canonicalization ledger gate (`ledger_ok`)
can never be satisfied for such content because:

- **B1 — no canonical home for "other" content.** Content classified as an "other"/custom section
  has no canonical target slot the ledger recognizes as "accounted for", so those content strings
  are counted as *dropped* by the ledger and `ledger_ok` stays `false` (with `structure_path: null`).
  The gate is therefore unsatisfiable for resumes that legitimately carry custom sections.
- **B2 — no summary target at the shape stage.** There is no canonical summary target available when
  the shape pass runs, so summary-like content has nowhere to land and likewise trips the ledger.

Discovered during a `parse-resume` → `build-structure` debug run on 2026-08-10 (resume-kit 0.9.0 /
plugin 1.2.0), immediately after the empty-company crash (RIT-T-0156) was worked around: with the
crash cleared, `build-structure` gated on `ledger_ok: false` / `structure_path: null` driven by
custom-section content that has no satisfiable canonical destination. Note RIT-T-0156's status log
called that gating "correct behavior" for THAT run; this ticket asserts the deeper defect — that the
ledger gate is structurally unsatisfiable for custom/other content, which blocks legitimate resumes.

## Backlog Item Details **[CONDITIONAL: Backlog Item]**

### Type
- [x] Bug - Production issue that needs fixing

### Priority
- [x] P1 - High — blocks `build-structure` (and therefore the whole baseline → refine → tailoring
      pipeline, which is gated behind `structure`) for any resume that carries custom/"other" sections
      or summary-like content the canonical schema does not model with a first-class slot.

### Impact Assessment **[CONDITIONAL: Bug]**
- **Affected Users**: Anyone whose resume has content the parser classifies as an "other"/custom
  section (e.g. "Ventures & Consulting", "Selected Projects", "Community", "Publications") or
  summary-like lead content, when the canonical schema lacks a matching first-class target. For them
  `build-structure` returns `ledger_ok: false` / `structure_path: null` and never completes.
- **Reproduction Steps**:
  1. Ingest a resume with a custom section whose content the shape analyzer routes to "other".
  2. Run `build-structure` on the base file.
  3. Observe: `ledger_ok: false`, `structure_path: null` — the ledger reports unaccounted content
     that has no canonical destination, so the gate never passes.
- **Expected vs Actual**:
  - **Expected**: "other"/custom-section content is *accounted for* by the ledger — routed to a
    canonical customSection/"additional" slot (or an explicit, documented catch-all) — so `ledger_ok`
    can be `true` without dropping or fabricating content; summary content has a shape-stage target.
  - **Actual**: such content is counted as dropped, `ledger_ok` stays `false`, and the structure step
    aborts with `structure_path: null`.

## Acceptance Criteria **[REQUIRED]**

- [ ] B1: a resume with legitimate "other"/custom-section content canonicalizes through
      `build-structure` with `ledger_ok: true` and a non-null `structure_path`, WITHOUT dropping the
      content and WITHOUT fabricating a canonical section — the content is faithfully routed to a
      canonical customSection/additional slot the ledger recognizes.
- [ ] B2: summary-like content has an explicit canonical target reachable at the shape stage (or a
      documented, ledger-recognized holding slot), so it no longer trips the ledger.
- [ ] The content ledger's accounting is made consistent: every content string the parser produced is
      either mapped to a canonical slot the ledger counts as accounted, or surfaced as an explicit,
      user-visible unmapped item — never silently counted as dropped with no destination.
- [ ] Regression test: a `ResumeDocument` containing a custom "other" section and summary content
      canonicalizes with `ledger_ok: true`; the ledger shows zero silently-dropped strings.
- [ ] Decision recorded (in Status Updates or a short ADR note) on whether the fix adds a canonical
      target slot vs. routes to an existing customSection catch-all, with the truth-posture rationale.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Root cause is in the shape canonicalizer + content ledger. Start at
  `packages/scoring/src/resume_kit_scoring/shape_fix.py` (the canonicalizer and its content-ledger
  construction — same module that owns `organization=raw.company` from RIT-T-0156) and the canonical
  schema `packages/schemas/src/resume_kit_schemas/canonical.py` (customSection / summary modeling).
  Trace how "other"-classified content and summary content are (not) mapped to canonical slots and how
  the ledger decides a string is "accounted" vs "dropped".
- Prefer routing "other" content to an existing canonical customSection/additional slot the ledger
  already recognizes, rather than inventing a new schema field, unless summary content genuinely needs
  a dedicated first-class target. Whichever is chosen, the ledger must count that slot as accounted.
- Cross-check against RIT-T-0162 (custom→skills mapping unsatisfiable + lossy) — these two bugs share
  the custom-section handling surface and should be reconciled together to avoid conflicting fixes.

Recommended Agent: opus + high — touches the canonical schema contract, the shape canonicalizer, and
the content-ledger gate semantics that the entire baseline pipeline is gated behind; a wrong choice
here compounds into every downstream tailoring step, and it must be reconciled with RIT-T-0162.

### Dependencies
- Canonical schema + shape schemas (RIT-T-0133), shape analyzer (RIT-T-0135), non-destructive
  canonicalizer + content ledger + hard gates (RIT-T-0136), `build_structure` stage (RIT-T-0137).
- Related open bug RIT-T-0162 (custom→skills mapping) — same custom-section surface.

### Risk Considerations
- Must not "fix" the gate by silently discarding unmapped content — that would defeat the ledger's
  purpose (lossless canonicalization) and the truth posture.
- Adding a canonical target must not break downstream consumers (projection, scorers, exporters) that
  enumerate canonical sections; audit usages before changing the schema.
- Relaxing the gate too far (always `ledger_ok: true`) would hide real content-loss regressions — the
  fix must keep detecting genuinely dropped content.
