# build-structure shape gate: 'other'/custom sections cannot satisfy the content ledger and there is no summary target at the shape stage, so ledger_ok stays false

## Objective **[REQUIRED]**

Fix the shape-stage content-ledger gate so that a resume whose content lives in "other" /
custom sections can pass `build-structure`. Today the canonicalization ledger gate (`ledger_ok`)
can never be satisfied for such content because:

- **B1 — no canonical home for "other" content.** Content classified as an "other"/custom section
  has no canonical target slot the ledger recognizes as "accounted for", so those content strings
  are counted as *dropped* by the ledger and `ledger_ok` stays `false` (with `structure_path: null`).
  The gate is therefore unsatisfiable for resumes that legitimately carry custom sections.
- **B2 — no summary target at the shape stage.** There is no canonical summary target available when
  the shape pass runs, so summary-like content has nowhere to land and likewise trips the ledger.

Discovered during a `parse-resume` → `build-structure` debug run on 2026-08-10 (resume-kit 0.9.0 /
plugin 1.2.0), immediately after the empty-company crash (RIT-T-0156) was worked around: with the
crash cleared, `build-structure` gated on `ledger_ok: false` / `structure_path: null` driven by
custom-section content that has no satisfiable canonical destination. Note RIT-T-0156's status log
called that gating "correct behavior" for THAT run; this ticket asserts the deeper defect — that the
ledger gate is structurally unsatisfiable for custom/other content, which blocks legitimate resumes.

### Impact Assessment **[CONDITIONAL: Bug]**
- **Affected Users**: Anyone whose resume has content the parser classifies as an "other"/custom
  section (e.g. "Ventures & Consulting", "Selected Projects", "Community", "Publications") or
  summary-like lead content, when the canonical schema lacks a matching first-class target. For them
  `build-structure` returns `ledger_ok: false` / `structure_path: null` and never completes.
- **Reproduction Steps**:
  1. Ingest a resume with a custom section whose content the shape analyzer routes to "other".
  2. Run `build-structure` on the base file.
  3. Observe: `ledger_ok: false`, `structure_path: null` — the ledger reports unaccounted content
     that has no canonical destination, so the gate never passes.
- **Expected vs Actual**:
  - **Expected**: "other"/custom-section content is *accounted for* by the ledger — routed to a
    canonical customSection/"additional" slot (or an explicit, documented catch-all) — so `ledger_ok`
    can be `true` without dropping or fabricating content; summary content has a shape-stage target.
  - **Actual**: such content is counted as dropped, `ledger_ok` stays `false`, and the structure step
    aborts with `structure_path: null`.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Root cause is in the shape canonicalizer + content ledger. Start at
  `packages/scoring/src/resume_kit_scoring/shape_fix.py` (the canonicalizer and its content-ledger
  construction — same module that owns `organization=raw.company` from RIT-T-0156) and the canonical
  schema `packages/schemas/src/resume_kit_schemas/canonical.py` (customSection / summary modeling).
  Trace how "other"-classified content and summary content are (not) mapped to canonical slots and how
  the ledger decides a string is "accounted" vs "dropped".
- Prefer routing "other" content to an existing canonical customSection/additional slot the ledger
  already recognizes, rather than inventing a new schema field, unless summary content genuinely needs
  a dedicated first-class target. Whichever is chosen, the ledger must count that slot as accounted.
- Cross-check against RIT-T-0162 (custom→skills mapping unsatisfiable + lossy) — these two bugs share
  the custom-section handling surface and should be reconciled together to avoid conflicting fixes.

Recommended Agent: opus + high — touches the canonical schema contract, the shape canonicalizer, and
the content-ledger gate semantics that the entire baseline pipeline is gated behind; a wrong choice
here compounds into every downstream tailoring step, and it must be reconciled with RIT-T-0162.

### Dependencies
- Canonical schema + shape schemas (RIT-T-0133), shape analyzer (RIT-T-0135), non-destructive
  canonicalizer + content ledger + hard gates (RIT-T-0136), `build_structure` stage (RIT-T-0137).
- Related open bug RIT-T-0162 (custom→skills mapping) — same custom-section surface.

### Risk Considerations
- Must not "fix" the gate by silently discarding unmapped content — that would defeat the ledger's
  purpose (lossless canonicalization) and the truth posture.
- Adding a canonical target must not break downstream consumers (projection, scorers, exporters) that
  enumerate canonical sections; audit usages before changing the schema.
- Relaxing the gate too far (always `ledger_ok: true`) would hide real content-loss regressions — the
  fix must keep detecting genuinely dropped content.

## Status Updates **[REQUIRED]**

*2026-08-10 — Filed from a baseline debug session (resume-kit 0.9.0 / plugin 1.2.0).* Observed after
RIT-T-0156's empty-company crash was worked around: `build-structure` then gated on `ledger_ok: false`
/ `structure_path: null` because custom "other" section content and summary content had no satisfiable
canonical destination. Code anchors identified but not yet root-caused to the exact ledger line:
`packages/scoring/src/resume_kit_scoring/shape_fix.py` (canonicalizer + ledger),
`packages/schemas/src/resume_kit_schemas/canonical.py` (customSection/summary modeling). Not yet
started — needs the reconciliation decision (new slot vs. existing catch-all) before implementation.

*2026-08-10 — Root-caused + fixed (with RIT-T-0162 on the same branch).*

**Pinned root cause.** In `packages/scoring/src/resume_kit_scoring/shape_fix.py`:
- The `for key in sorted(resume.customSections)` loop routed any section whose target was `None` or
  `CanonicalSection.OTHER` to `unresolved_custom_section(...)`, which records every content token with
  `ContentFate.UNRESOLVED`. `UNRESOLVED` is not in `_LEDGER_OK_FATES`, so `content_ledger_ok(...)`
  returned `False` → `build_structure` returned `structure_path: null`. The gate was therefore
  structurally unsatisfiable for any resume carrying legitimate custom/"other" content.
- B2 (summary): NOT actually broken — `_CanonicalBuilder.basics(...)` already routes `resume.summary`
  to `basics.summary` with `ContentFate.MOVED`, and `Basics.summary` exists, so summary content has a
  shape-stage target. Verified by regression test; no code change needed for the summary path.

**Schema decision (made per authorization; thinnest reuse, no new `CanonicalSection` enum member).**
Chosen: **add a minimal canonical holding slot** — `Resume.custom: list[CustomContentSection]`
(new `CustomContentSection{heading, lines}` in `canonical.py`) plus a new accounted ledger fate
`ContentFate.PRESERVED_AS_OTHER`. Untargeted/"other" sections are now routed to
`_CanonicalBuilder.preserve_custom_section(...)`, which keeps their content verbatim as `lines` and
records each token as `PRESERVED_AS_OTHER` with a real `custom[i].lines[j]` target_path (added to both
`_LEDGER_OK_FATES` and `_TARGET_REQUIRED_FATES`, so the gate still catches genuinely dropped content —
a preserved token must point at a real slot). `projection.project_builddoc_from_canonical` round-trips
`Resume.custom` back to BuildDoc `customSections` so nothing is lost downstream.

Rationale / alternatives considered:
- **Reuse existing customSection catch-all (preferred-if-possible per instructions): rejected as
  insufficient.** The BuildDoc `ResumeDocument.customSections` is the catch-all, but the shape stage's
  written artifact is the canonical `Resume`, which had NO field able to hold arbitrary custom content.
  Marking such content "accounted" in the ledger without a canonical destination would silently drop it
  from the artifact — violating the lossless/truth posture. So a canonical holding slot is genuinely
  required for faithfulness; there was no existing canonical slot to reuse.
- **Add a new `CanonicalSection.OTHER`-backed named-collection scaffold (like certifications/awards):
  rejected as heavier.** It would add enum/consumer surface without modeling free-form heading+lines
  content well. The `custom` list with `{heading, lines}` is the minimal faithful shape.

Downstream enumerator audit (before deciding): the only consumer that enumerates the canonical
`Resume` section-by-section is `projection.py` (Resume → BuildDoc); exporters/scorers operate on the
BuildDoc, not the canonical `Resume` directly. Blast radius of the new slot was therefore limited to
`projection.py` (round-trip added) — no exporter/scorer changes needed. `Resume` is `extra="forbid"`,
so the new optional field defaults empty and is backward-compatible with existing artifacts.

Behavior change: untargeted custom sections are now **applied (preserved)** rather than **deferred**;
the analyzer still surfaces the `CUSTOM_SECTION_UNMAPPED` finding for visibility. Updated the affected
E2E assertion in `packages/facade/tests/test_structure_lineage_e2e.py` accordingly.

Truth posture preserved: content is only ever preserved/accounted, never fabricated; sections with a
real canonical target that cannot be auto-applied (e.g. prose mapped to skills) still go UNRESOLVED and
gate correctly (existing `test_prose_heavy_mapped_section_is_deferred_and_refused_by_ledger` stays green).

**Files changed:** `packages/schemas/src/resume_kit_schemas/shape.py` (new `PRESERVED_AS_OTHER` fate),
`packages/schemas/src/resume_kit_schemas/canonical.py` (`CustomContentSection` + `Resume.custom`),
`packages/scoring/src/resume_kit_scoring/shape_fix.py` (routing + preserve + ledger sets),
`packages/scoring/src/resume_kit_scoring/projection.py` (round-trip), regression tests in
`packages/scoring/tests/test_shape_fix.py`, E2E update in
`packages/facade/tests/test_structure_lineage_e2e.py`.
