# content-ledger preserved_in_evidence is asserted, not verified

## Objective **[REQUIRED]**

Make the content ledger's "not silent" guarantee real: when `build-structure --omit-custom-sections`
drops custom content and stamps it `PRESERVED_IN_EVIDENCE`, that label must be a RECEIPT (the content
is actually in the active evidence), not a PROMISSORY NOTE stamped categorically. Today the fate is
applied without checking evidence, so if the seed was skipped/failed the content is silently lost while
the ledger reports `ledger_ok: True`.

## Backlog Item Details

### Type
- [x] Bug — a preservation guarantee that is procedural (ordering convention) rather than enforced

### Priority
- [x] P2 — Medium. Data-loss hazard, but only manifests when `build-structure --omit-custom-sections`
  runs without `seed-full-resume-evidence` having captured the section first (direct call, skipped
  seed, or a silent seed failure). Flow 1 orders them correctly today, so it is latent — but easy to
  trip, as the repro shows.

### Impact Assessment
- **Affected Users**: Anyone who calls `build-structure --omit-custom-sections` outside the Flow-1
  ordering, or whose evidence seed failed silently — custom content is dropped and genuinely lost while
  the ledger claims it was preserved.
- **Reproduction (verified)**:
  1. Empty the active evidence file: `evidence.json = []`.
  2. Run `build-structure --omit-custom-sections`.
  3. Result: `ledger_ok: True`, `claims_ok: True`, fate counts `{moved: 746, deduped: 1,
     preserved_in_evidence: 127}` — 127 dropped custom tokens are labeled `preserved_in_evidence`
     **falsely** (evidence is empty).
- **Expected vs Actual**: Expected — if the omitted content is not actually present in active evidence,
  the ledger should FAIL (or warn loudly), not report clean preservation. Actual — the fate is stamped
  categorically; `ledger_ok` stays True regardless of evidence contents.

### Root Cause (verified, file:line)
- `handoff_custom_section_to_evidence` stamps `ContentFate.PRESERVED_IN_EVIDENCE` categorically for
  omitted custom content: `packages/scoring/src/resume_kit_scoring/shape_fix.py:739` (see also
  the fate enum at `:74` and the count at `:891`).
- `content_ledger_ok` (`shape_fix.py:210`) validates that every token has a fate but NEVER
  cross-references `active_evidence` — so a `preserved_in_evidence` fate is accepted without proof.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

Pick ONE enforcement path (A preferred; B acceptable/complementary), document the choice:

- [ ] **A — Verify the receipt.** When omit stamps `PRESERVED_IN_EVIDENCE`, verify each such token/span
      is actually present in the active evidence (`active_evidence` / `evidence_file`). If not, the
      ledger FAILS (`ledger_ok: False`, non-zero) — or, if a softer posture is chosen, emits a LOUD,
      non-silent warning AND does not claim clean preservation. Default should be fail-closed for
      genuine content loss.
- [ ] **B — Make the ordering unbreakable.** `build-structure --omit-custom-sections` refuses to run
      (clear error) unless the seed has captured the section(s) being omitted — i.e. omit cannot
      proceed without a populated, matching evidence surface. This removes the "caller must remember to
      seed first" footgun.
- [ ] The empty-evidence repro above now FAILS (or warns loudly and does not report clean
      preservation) instead of returning `ledger_ok: True` with 127 falsely-preserved tokens.
- [ ] Flow 1's normal path (seed then omit) still passes green.
- [ ] Regression test encodes the empty-evidence repro and the happy path.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Option A: thread the active evidence (or a token/normalized-span set derived from it) into the ledger
  check so `content_ledger_ok` (or a new `evidence_receipts_ok` gate composed with it) can confirm each
  `preserved_in_evidence` entry is backed. Reuse the existing evidence extraction/normalization so the
  comparison matches how content was seeded (avoid false negatives from normalization drift).
- Option B: add a precondition in the omit path (`build_structure` / `handoff_custom_section_to_evidence`
  caller) that checks the evidence surface covers the omitted sections before stamping the fate.
- Keep deterministic/offline.

### Dependencies
- [[RIT-T-0169]]/[[RIT-T-0176]] (evidence seed + OMIT policy), [[RIT-I-0019]] content ledger. Pairs
  with [[RIT-T-0185]] (faithful-original invariant) — together they make the ingest→learn→lossy chain
  actually safe rather than convention-safe.

### Risk Considerations
- Watch normalization parity: the verification must compare content the same way the seed stored it, or
  it will false-fail on punctuation/case. Reuse the evidence extractor's normalization.
- Do not make Flow 1's happy path slower/flakier; the check should be a set membership, not a re-parse.

**Recommended Agent: opus + medium** — a real gate addition on the content-loss path with careful
normalization parity and a repro-driven test.
