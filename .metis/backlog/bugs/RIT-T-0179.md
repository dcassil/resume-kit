# analyze-best-practices resume_version leaks raw path + breaks surface parity

## Objective **[REQUIRED]**

Make the `resume_version` stamp on the best-practices report a canonical version identity
(`base` / `structure` / `refine` / `original`) resolved uniformly across all surfaces, instead of the
CLI leaking its raw `--resume` filesystem path while the object surfaces stamp `None`. This is the
long-standing pre-existing failure
`tests/interface/test_surface_parity.py::test_core_fields_are_equivalent_across_surfaces[analyze-best-practices]`.

## Backlog Item Details

### Type
- [x] Bug — cross-surface inconsistency + minor information leak

### Priority
- [x] P2 — Medium. Cosmetic (findings are identical across surfaces); it does not affect scoring, but
  it fails the surface-parity guard and leaks an arbitrary local path into report output.

### Impact Assessment
- **Affected Users**: Anyone consuming the `BestPracticesReport.resume_version` field, and CI (the
  parity test has been red on `main` since the `resume_version` stamp landed).
- **Reproduction Steps**:
  1. Run `analyze-best-practices` via CLI with `--resume <path>` and via direct/MCP/API with an inline
     resume object.
  2. Compare the emitted report: CLI stamps `resume_version` = the raw path
     (`.../resume.json`); direct/MCP/API stamp `resume_version = None`.
  3. `test_core_fields_are_equivalent_across_surfaces[analyze-best-practices]` asserts `cli == direct`
     and fails.
- **Expected vs Actual**: Expected — all four surfaces stamp the same canonical version identity (or
  the same `None` when none can be resolved). Actual — CLI stamps a raw path; others stamp `None`.

### Root Cause
`AnalyzeBestPracticesRequest.resume_version` (facade `models.py:235`) is documented (RIT-T-0164) as the
resolved version identity — e.g. the `base`/`structure`/`refine` pointer. But the CLI command
(`packages/cli/.../app.py:978`) wires `resume_version=resume`, where `resume` is the raw `--resume`
path string, not a version identity. The direct/MCP/API surfaces receive a bare `ResumeDocument` and
leave `resume_version` at its `None` default. So the surfaces disagree, and the CLI additionally leaks
a local filesystem path into the report.

## Acceptance Criteria **[REQUIRED]**

- [ ] `resume_version` is resolved to a CANONICAL version label — one of `base` / `structure` /
      `refine` / `original` (or the project pointer name) — NOT a raw filesystem path, on every surface.
- [ ] Resolution is uniform: when the input resume corresponds to a known project pointer
      (`base_resume` / `structure_resume` / `refine_resume` / `active_resume`), all four surfaces stamp
      that same label; when it cannot be resolved (bare object, no project context), all four stamp
      `None`.
- [ ] The CLI no longer stamps the raw `--resume` path; it resolves the path against the active
      `ProjectConfig` pointers and stamps the matching version label (or `None` if unmatched).
- [ ] MCP/API/direct resolve the same way when a project/root context is available; otherwise `None`.
- [ ] No raw local filesystem path appears in `BestPracticesReport.resume_version` output.
- [ ] `tests/interface/test_surface_parity.py::test_core_fields_are_equivalent_across_surfaces[analyze-best-practices]`
      passes, and a regression test asserts the canonical-label resolution (path → label, unmatched →
      None).

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Add a small resolver that maps a resume input (path and/or resolved `ResumeDocument`) to a canonical
  version label using the code-owned `ProjectConfig` pointers
  (`resume_kit_facade.project_config` — `base_resume` / `structure_resume` / `refine_resume` /
  `standard_resume` legacy / `active_resume`). Prefer the most specific matching pointer.
- CLI: replace `resume_version=resume` with `resume_version=<resolved label or None>`.
- Ensure the capability (`analyze_best_practices_capability`) applies the same resolution so
  direct/MCP/API agree; when no root/project is available, `resume_version` stays `None`.
- Keep it deterministic and provider-free (analyze-best-practices is no-LLM).
- Extend the existing `analyze-best-practices` `SurfaceCase` / add a focused unit test for the
  resolver (path matching `refine_resume` → `"refine"`; unmatched path → `None`).

### Dependencies
- Reuses [[RIT-I-0024]] `_shared/config-pointers.md` semantics and the `ProjectConfig` pointer schema
  ([[RIT-I-0014]]). No functional dependency on RIT-I-0025; if RIT-I-0025 later adds tailored/final
  pointers, extend the resolver's label set then.

### Risk Considerations
- Low. Behavior change is confined to the `resume_version` stamp; findings/provenance/schema are
  unchanged. Verify the parity test and the two other `resume_version`-bearing paths (compare-versions
  at `capabilities.py:1490` is a separate, explicit pass-through and must remain untouched).

**Recommended Agent: opus + low** — small, single-field cross-surface fix, but it touches the CLI,
the capability, and parity/regression tests and must resolve against the real ProjectConfig pointers.
