# Documentation/comments inventory from end-to-end pipeline run

## Objective **[REQUIRED]**

Add the high-payoff documentation and code comments identified by running the whole resume-kit pipeline
end-to-end. Every item below is a place where the operator had to guess, grep source, or discover
behavior by trial. Goal: make the contracts discoverable in-repo so future agents/users don't re-lose
that time.

`resume-kit/review/documentation-needs.md`. Prioritized by how much confusion each caused during the run.

## Acceptance Criteria **[REQUIRED]**

Deliver the following documentation (location per item: extend `_shared/*` contract docs, add concept
docs under docs/ or the skills `_shared/`, and add code comments/docstrings where cited). Every claim
MUST be verified against current code before writing.

### 1. config.json (ProjectConfig) — field-by-field contract [HIGH ROI]
- [ ] For every key: meaning · which command writes it · when · path form · may-an-agent-hand-edit-it.
- [ ] Explain `evidence_file` vs `active_evidence` (both point at the same file today — the intended
      distinction, whether they can diverge).
- [ ] State `base_resume` is the same thing as the "base" shorthand (update-structure writes "base",
      update-shape reads `base_resume`).
- [ ] Mark `standard_resume`/`standard_derived_from` as deprecated (renamed to refine) but still
      present/null.
- [ ] Document `final_resume`/`final_derived_from`/`final_job_id`: set by `fit`; and that nothing
      repoints `active_resume` to them (the perfect→export gap).
- [ ] Put the resolution order (refine → structure → base → original) in ONE place, plus which commands
      resolve vs require explicit `--resume`.

### 2. CLI params that were unclear
- [ ] `build-structure --omit-custom-sections`: what it drops + Flow-1 ordering (omitted content must
      already be seeded as evidence first).
- [ ] `export --out` vs `--output json`: `--out` prints "Wrote N bytes"; `--output json` returns base64
      bytes, not a JSON envelope (this breaks naive parsing).
- [ ] `export --allow-over-length` / `max_pages`: where `max_pages` is read from and which entry point
      enforces it (a hand-set config value did not block a raw export).
- [ ] `add-evidence --evidence-file --update-active`: sets the pointer but does NOT append to an
      existing file; document append-vs-overwrite + the `--kind` enum.
- [ ] `set-active`: document the asymmetry — sets resume/job/alias but has no flag for `active_evidence`
      or `final_resume` (only `add-evidence --update-active` / `fit` set those).
- [ ] `identify-gaps`: `--master` required; "injectable" = master OR active_evidence; which the CLI vs
      MCP honors.
- [ ] `match`: `overall_score` (composite) ≠ `ats_score.overall_score`; document the sub_score formulas.

### 3. Output/path conventions — one canonical table
- [ ] Naming `<name>-original|base|structure|refine.json`, `<name>-<jobslug>-final.json`.
- [ ] The two conflicting working-file conventions (`working/<name>.tailored.json` vs
      `working/<session>/resume.json`) and that `working/edit-session.json` is a single session slot
      that collides across jobs. (Reconcile with [[RIT-T-0181]] item D — the code path is
      `working/<name>.tailored.json`.)

### 4. ChangeProposal schema — per-field + per-action [HIGH ROI]
- [ ] `action` enum semantics (`replace|append|reorder|add_skill|remove`).
- [ ] `value: str|list` — for `add_skill` a list value silently no-ops; document the supported shape.
- [ ] `original` may be a list only for `reorder`/`remove`.
- [ ] Path grammar (0-based; `additional.technicalSkills` for skills).
- [ ] Same-path constraint: the review session decides by path, so multiple `additional.technicalSkills`
      changes cannot be decided individually.

### 5. Edit-session lifecycle — a state doc
- [ ] `--mode {interactive|review_at_end|auto}` flows.
- [ ] Commit hard-gate compares working-file hash to opened hash → `working_resume_tampered`; document
      reconcile vs re-open.
- [ ] `decide --action {approve|reject|edit|retry|reduce_freedom|increase_freedom|skip}` + `--reason-code`
      enum.
- [ ] Commit runs an auto-learn-terminology tail that reads `alias_file` (a LexiconError source; link
      [[RIT-T-0180]]).

### 6. Evidence model — a concept doc
- [ ] `CandidateEvidence` shape + full `kind` enum and what each means for injectability.
- [ ] Cross-reference the three names for one capability
      (extract-evidence / build-evidence / candidate_evidence_build; see [[RIT-T-0181]] J5).
- [ ] How `active_evidence` becomes master-equivalent proof; whether `user_confirmed` matters.

### 7. Alias file — format + hazards
- [ ] Shape `{version, aliases{canonical:[variants]}, justifications, provenance}` (provenance optional).
- [ ] Direction: canonical = JD keyword, list = resume surface forms (easy to invert).
- [ ] Hazard: an edit whose text contains an alias canonical throws `LexiconError` at commit → document
      + the unset-alias workaround (link the code fix [[RIT-T-0180]]).
- [ ] Only match/check-* honor it; must be registered via `set-active`.

### 8. Gates & thresholds — "what fails vs warns"
- [ ] Faithfulness error vs warning codes (dropped section headings are `DROPPED_SPANS` errors).
- [ ] `ledger_ok`/`claims_ok` are hard; never trim content.
- [ ] Skills-count budget (30) is informational; `max_pages` is the hard gate — currently reads as
      contradictory (reconcile with the wired export gate from [[RIT-I-0024]]).
- [ ] Interview offer fires on composite < threshold OR any required uncovered.

### 9. Error taxonomy — a reference [HIGH ROI]
- [ ] `LexiconError`, `working_resume_tampered`, `validation_failed` (e.g. Experience.title required),
      and "No such command" (= version skew) — each with cause + resolution.

### 10. Version/compat matrix
- [ ] Which package version each plugin version needs (1.8.0 skills require ≥0.15.x). Turns the silent
      "No such command" dead-end into a fail-fast message.
