# Rename resume-intelligence skills to the RIT-A-0005 lexicon (orchestrated parallel rename + Metis reconcile)

Implements **Decision A** of [[RIT-A-0005]] (the verb-noun skill lexicon + full rename map). Decision B (extracting the shared `_shared/apply-changes.md` runbook) is intentionally OUT OF SCOPE here and will be a follow-up task — this task does the pure rename only. **This is the first task to run before any further resume-intelligence skill work, and MUST land before [[RIT-T-0120]]** so 0120's two new skills (`update-structure`, `update-best-practices`) are authored directly in the new lexicon rather than migrated.

## Objective **[REQUIRED]**

Rename the 14 mis-named `resume-intelligence` skills to their [[RIT-A-0005]] names, update every cross-reference to them across the whole plugin (skill bodies, markdown link paths, the plugin manifest and its description), major-bump the plugin version, land it on `main`, and THEN reconcile every non-completed Metis document so its prose matches the new names. Completed initiatives/tasks are historical record and are left untouched.

### Technical Debt Impact **[CONDITIONAL: Tech Debt]**
- **Current Problems**: Skill names use inconsistent synonym verbs (`inject`/`update`, `identify`/`check`, `build`/`resume-to-json`, `log`/`manage`) so behavior class is not inferable from a name; the list is hard to scan; new skills have no naming rule to follow.
- **Benefits of Fixing**: The list groups by verb at a glance (safe `check-*` vs blocking `validate-*` vs mutating `update-*` vs future-learning `learn-*`); new skills self-place; [[RIT-T-0120]] is de-risked.
- **Risk Assessment**: If not done before RIT-T-0120, two more skills entrench the ad-hoc pattern and the eventual rename is strictly larger. The rename itself is broad (some old names are referenced in up to 15 files), so it must be done atomically to avoid a half-renamed, broken-cross-reference state.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Execution model (as directed)

A single **Claude orchestrator agent** drives the whole task. It runs the skill renames via **parallel worker agents (Codex), one worker per skill rename**, then merges, version-bumps, commits/pushes, and finally fans out a second wave of workers for the Metis reconcile.

**Phase 0 — Orchestrator prep (Claude, single branch `chore/rit-a-0005-skill-rename`).**
1. Create the working branch off `main`.
2. Confirm the 14→ mapping against [[RIT-A-0005]] (authoritative). Produce the exact `old → new` string list the workers and the sweep will use.

**Phase 1 — Per-skill rename (parallel Codex workers, one per skill, DISJOINT file ownership).**
- Collision analysis (done): old names are referenced in up to 15 files, and shared files (`resume-workflow/SKILL.md`, `_shared/prerequisites.md`, `plugin.json`) are referenced by many skills. If every worker also edited every file that mentions its skill, workers would collide heavily on those shared files. Therefore ownership is partitioned so **each worker owns only its own skill's directory**:
  - `git mv` the skill directory `old-name/ → new-name/`.
  - Update the `name:` frontmatter field in the moved `SKILL.md`.
  - Fix the description's verb/wording for its own skill only.
  - Do NOT touch other skills' files or shared files — those are swept centrally in Phase 2.
- Because each worker touches a disjoint directory, this runs safely on the **single branch without collisions — worktrees are NOT required**. (Worktrees remain the fallback only if a future constraint forces workers to edit overlapping files; not expected here.)

**Phase 2 — Central cross-reference sweep (Claude orchestrator, single deterministic pass).**
- After all workers finish, the orchestrator performs ONE global, deterministic find-replace of every `old → new` name across the whole `plugins/resume-intelligence/` tree (prose mentions + markdown link paths + `plugin.json` description + hooks/docs). Each old name is a unique unambiguous string, so this is mechanical and must NOT be parallelized (it edits the shared files every skill references). Apply longest-name-first ordering to avoid partial-substring collisions (none expected among these 14, but order defensively).
- Major-bump `plugin.json` `version` (0.7.0 → 1.0.0).

**Phase 3 — Verify, commit, push (Claude orchestrator).**
- Verify: `grep -rn` each old name across `plugins/` → zero hits; `grep -rn` skill dir names under `packages/` → zero hits (skills aren't imported by code); run any plugin/skill validation + the test suite as a regression guard.
- Commit the whole rename as one change; push; merge to `main` (or fast-forward). Single commit keeps the breaking rename atomic — no half-renamed state on `main`.

**Phase 4 — Metis reconcile (parallel Codex workers, one per doc, AFTER push).**
- The orchestrator enumerates every NON-completed Metis doc that mentions an old skill name (`grep -rn` old names under `.metis/`, minus any doc in a completed phase). It tasks **one Codex worker per such document** to swap old→new names in that doc only (disjoint files → parallel-safe).
- **Do NOT modify completed initiatives or completed tasks** — they are historical record of what was true when done. (Decided ADRs like RIT-A-0005 itself, active/todo tasks, backlog items, active initiatives, and vision ARE updated.)
- Commit the Metis reconcile separately (docs-only) and push.

### Dependencies
- **[[RIT-A-0005]]** — the authoritative rename map and lexicon (decided). This task implements Decision A only.
- **Blocks [[RIT-T-0120]]** — must land first; 0120 then authors `update-structure` / `update-best-practices` in-lexicon.
- Out of scope / follow-up: Decision B (extract `_shared/apply-changes.md` and refactor the `update-*` skills to defer to it) is a SEPARATE later task.

### Risk Considerations
- **Half-renamed state**: mitigated by doing the cross-reference sweep centrally and committing atomically; CI/grep gate proves zero dangling old names before merge.
- **Substring collisions** (e.g. a short new name embedded in a longer string): mitigated by whole-token replacement and longest-first ordering; verified by the zero-hit grep.
- **Markdown link breakage**: link paths (`../old-name/SKILL.md`) are included in the sweep, not just prose; verified by a link-check / grep for `../<old>/`.
- **External consumers**: per RIT-A-0005 these are pre-1.0 internal plugin skills, so a hard rename (not deprecation aliases) is chosen; the major version bump signals the break.
- **Accidental history edits**: the reconcile phase explicitly excludes completed docs; the grep-verification distinguishes completed vs non-completed hits.
