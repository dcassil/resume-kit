# Clone, pin, and test upstream Resume-Matcher

## Parent Initiative

[[RIT-I-0001]] — Phase 0 — Upstream Audit of Resume-Matcher

## Objective

Phase 0 is a research/documentation-only initiative for resume-kit. The upstream donor is Resume-Matcher at https://github.com/srbhr/Resume-Matcher, licensed Apache-2.0. Clone it into the repo-local gitignored directory ./upstream/, pin it to a single concrete commit SHA, run the upstream backend tests, and document reproducible commands and results in references/upstream-audit.md. Do not write any product code. Repo stack is Python 3.12 / uv, but upstream may have its own setup instructions; follow upstream backend test instructions as closely as possible and record any deviations or environment requirements.

### Technical Approach
Start by checking whether ./upstream/ already exists. If it exists, inspect its remote and current SHA before deciding whether to reuse it; do not delete unrelated local changes. Ensure ./upstream/ is ignored by git, but only document or minimally adjust ignore state if necessary and allowed by the existing repo conventions. Prefer upstream's documented backend test commands; if documentation is missing or broken, inspect pyproject/package files and run the narrowest backend pytest command that exercises available tests. Capture enough output in prose or fenced snippets for a reviewer to reproduce the result without committing logs. Keep references/upstream-audit.md focused on audit evidence, not future implementation design.

## Verification Steps

1. Run git -C upstream remote get-url origin and confirm it is https://github.com/srbhr/Resume-Matcher or an equivalent GitHub URL for srbhr/Resume-Matcher.
2. Run git -C upstream rev-parse HEAD and confirm the full SHA exactly matches the SHA recorded in references/upstream-audit.md.
3. Run the recorded backend test command again, or document why it cannot be rerun in the current environment, and confirm the result matches the recorded status.
4. Run git status --short and confirm no upstream source files are staged/tracked in the product repo.
