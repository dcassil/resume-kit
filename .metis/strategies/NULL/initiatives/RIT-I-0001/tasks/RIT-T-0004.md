# Reconcile Phase 0 deliverables and document reviewer spot-check

## Parent Initiative

[[RIT-I-0001]] — Phase 0 — Upstream Audit of Resume-Matcher

## Objective

This final Phase 0 task verifies that the three documentation deliverables are internally consistent, reproducible, and complete against initiative exit criteria. It depends on the upstream audit, attribution ledger, and reuse inventory. It may edit all three reference docs to fix inconsistencies, add missing cross-links, and record the orchestrator/reviewer spot-check evidence. Do not write product code.

## Acceptance Criteria

- [ ] references/upstream-audit.md, references/reuse-inventory.md, and references/attribution.md all record the same pinned full upstream commit SHA and upstream repository URL.
- [ ] references/upstream-audit.md contains reproducible clone and backend test instructions with captured test results.
- [ ] references/reuse-inventory.md classifies every relevant subsystem and every vision-named reuse/adapt/replace/new candidate.
- [ ] references/attribution.md covers every subsystem classified Reuse, Extract, or Adapt in references/reuse-inventory.md.
- [ ] At least three inventory rows are spot-checked against actual upstream files and tests, and the spot-check results are recorded in references/upstream-audit.md or a clearly marked review section in the relevant reference docs.
- [ ] The final docs clearly state Phase 0 wrote no product code and that ./upstream/ is a gitignored reference clone, not distributed product code.

### Technical Approach
Perform consistency checks after tasks 0-2 complete. Reconcile naming differences between inventory and attribution instead of duplicating near-identical subsystem names. Spot-check rows should include varied risk areas, for example one deterministic parser/schema row, one diff/alignment policy row, and one replace/leave-behind web/persistence row. Keep edits limited to references/upstream-audit.md, references/reuse-inventory.md, and references/attribution.md. Do not transition the initiative phase; the orchestrator owns Metis phase changes.

### Constraint (teamwork orchestration)
Implementing agent WRITES FILES ONLY. Do not run git (no add/commit/branch/push). Do not run
repo-wide verification (lint/typecheck/build) — the orchestrator does that per wave. Assume zero
prior context beyond this document.

## Verification Steps

1. Run git -C upstream rev-parse HEAD and compare it against all three reference docs.
2. Run rg for the pinned SHA across references/upstream-audit.md references/reuse-inventory.md references/attribution.md and confirm all three include it.
3. Run rg for each classification label in references/reuse-inventory.md and confirm Reuse, Extract, Adapt, Replace, and New are represented where applicable.
4. Manually compare every Reuse/Extract/Adapt row in references/reuse-inventory.md with references/attribution.md and confirm attribution coverage.
5. Run git status --short and confirm only ./upstream/ plus the three reference docs are affected by Phase 0 work, with no product code changes.
