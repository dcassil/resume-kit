# Prerequisite gates on remaining skills + resume-workflow guide

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0011]]

## Objective **[REQUIRED]**

Make the prerequisite-gate convention universal across the remaining skills, and author the single
orchestration guide that tells an agent the order to run skills in.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] Author a shared, concise Prerequisites-gate CONVENTION (a short reference the skills point to, e.g.
      `plugins/resume-intelligence/skills/_shared/prerequisites.md` OR a documented standard block) so the
      gate is defined once and reused verbatim. Format: resolve inputs from the `resume-kit/` working dir
      (`config.json` `active_resume`/`active_job` → JSON paths, plus skill-specific inputs); if any is
      missing, STOP and name the exact upstream skill to run first.
- [ ] Add that Prerequisites gate to each remaining single-purpose skill that consumes inputs:
      `resume-to-json` (needs a source file), `job-to-json` (needs posting text/URL), `validate-resume-truth`
      (resume JSON + evidence), `build-candidate-evidence` (resume/master JSON), `compare-resume-versions`
      (two resume JSONs + job JSON), `select-best-resume` (candidate resume JSONs + job JSON),
      `export-resume` (resume JSON). `manage-synonyms` keeps its own inputs. Keep each skill single-purpose;
      only add the gate + tighten the description if ambiguous.
- [ ] `plugins/resume-intelligence/skills/resume-workflow/SKILL.md` (slug `resume-workflow`, NEW guide):
      sequences the canonical flow referencing exact slugs — `resume-to-json` + `job-to-json` →
      `check-ats-structure` + `check-keyword-match` + `identify-resume-gaps` → (improve) `inject-keywords`
      and/or `update-terminology` → `validate-resume-truth` → re-run the checks to show deltas →
      `export-resume`. Names each step's gate, marks optional steps, notes `manage-synonyms` grows the
      alias index and that LLM auto-rewrite is disabled. It is a GUIDE (no tool calls of its own beyond
      pointing at skills).
- [ ] Do NOT edit `tests/test_skill_markdown.py` / `README.md` (RIT-T-0081 reconciles). Do NOT edit the
      check/improve skill dirs owned by RIT-T-0078/0079. `claude plugin validate` passes.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + medium` — Touches many skills (consistent gate) + authors the load-bearing orchestration guide
that defines the "one obvious flow." Mechanical per-skill edits but the guide must be accurate and the
gate wording consistent (it's the convention everything else reuses). Medium.

### Technical Approach
- Write the shared gate block first; apply it verbatim to each listed skill's top (after frontmatter,
  before the first step). Read `resume-to-json`/`job-to-json` for the existing working-dir + config.json
  conventions to match exactly.
- The `resume-workflow` guide should read like a runbook: numbered steps, each with "gate:" and
  "optional?" annotations, referencing skills by slug. Keep it short and unambiguous.
- Coordinate slugs with RIT-T-0078 (check-ats-structure, check-keyword-match) and RIT-T-0079
  (inject-keywords, update-terminology) — reference their final slugs.

### Dependencies
- File-disjoint from RIT-T-0077 (packages) and from the check/improve skill dirs (0078/0079) — edits a
  different set of skill dirs + adds `resume-workflow` + `_shared`. Can run in parallel in Wave 1.
- Blocks: RIT-T-0081 (integration references the guide + gate convention).

### Risk Considerations
- **Gate inconsistency**: define once, reuse verbatim; divergent gates are the maintenance smell we are
  removing.
- **Guide drift**: the guide must name the FINAL slugs (post-rename/removal); coordinate with 0078/0079
  and note that removed skills (extract-*, align-resume, check-resume-*) must NOT appear.
- **Scope**: don't turn the gate-add into behavior changes; single-purpose stays intact.

### Verification Steps
1. `claude plugin validate plugins/resume-intelligence` passes.
2. Read-through: every listed skill has the identical gate block; the guide sequences only final slugs
   with gates + optional markers.
