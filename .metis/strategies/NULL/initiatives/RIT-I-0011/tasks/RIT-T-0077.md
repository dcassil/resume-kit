# Expose resume-only ATS structure check across engine + surfaces

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0011]]

## Objective **[REQUIRED]**

Enable the single-purpose `check-ats-structure` skill (RIT-T-0078) by exposing a RESUME-ONLY structural
ATS check as a first-class capability across engine → facade → CLI/MCP/API. This is the NFR-1102
exception in the initiative: the needed logic already exists but is PRIVATE and only reachable through the
job-requiring composite `compute_ats_score`.

Verified: `packages/ats/src/resume_kit_ats/engine.py` has `_compute_section_completeness(resume)` and
`_expanded_recommendations(resume)` — both resume-only, job-independent — but `__all__` exports only
`compute_ats_score` (which requires job keywords and returns the blended composite). No engine scoring
math changes; this only surfaces existing resume-only checks.

## Acceptance Criteria **[REQUIRED]**

- [ ] New public engine function, e.g. `check_ats_structure(resume: ResumeDocument | dict) ->
      resume_kit_schemas.AtsStructureReport`, in `packages/ats`, exported from `resume_kit_ats.__init__`
      `__all__`. It returns ONLY structural signal: `section_completeness: float` (via

      OR reuse an existing minimal shape if one fits; do not overload `ATSScore`.

      the facade `REGISTRY`; exported from facade `__all__`.
- [ ] CLI command `check-ats-structure`, MCP tool `resume_check_ats_structure`, API route
      `POST /check-ats-structure` — thin adapters over the facade, matching existing patterns; registered
      in TOOL_NAMES/HANDLERS, CLI app, API router; expected-set tests (CLI help, MCP stable-tools, facade
      registry/public-exports, cross-surface parity) updated to include the new capability.
- [ ] The existing `compute_ats_score` / `resume_check_ats` composite is UNCHANGED (still available; not
      removed here — the SKILL that wrapped it is removed later in RIT-T-0081).
- [ ] Deterministic; `ruff` + `mypy --strict` clean; full `uv run pytest` engine suite green.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + high` — Adds a new capability across all five surfaces with a hard parity requirement and
registry/expected-set updates; it is the prerequisite the check-skills task builds on. Reuses existing
private logic (no new scoring math), but the cross-surface plumbing + parity + not-disturbing the
composite make it load-bearing. Follows the RIT-T-0074 pattern exactly.

### Technical Approach
- Promote the resume-only structural logic to a public `check_ats_structure`; keep `compute_ats_score`
  calling the same private helpers (no duplication, no math change).
- Mirror the Phase-5/6 capability+adapter pattern end-to-end (read how `check_resume_ats` /
  `suggest_terminology` are wired: facade cap + request model → CLI → MCP tool+registry → API route+router
  → parity test). Add per-surface tests + extend the parity table.
- Update `EXPECTED_CLI_OR_MCP`-style expectations at the PACKAGE test level (cli/mcp/facade) — NOT the
  plugin skill test (that is RIT-T-0081's).

### Dependencies
- Depends on: nothing new (existing ats engine). Blocks: RIT-T-0078 (the skill calls this).
- File-disjoint from RIT-T-0079/0080 (plugin markdown) — can run in parallel with them.

### Risk Considerations
- **Disturbing the composite**: do not change `compute_ats_score` behavior/weights; only extract/expose.
- **Parity drift**: adapters must delegate to one facade cap; enforce with a parity test.
- **Scope creep**: structure-only means NO keyword/coverage fields — keep the report minimal.
