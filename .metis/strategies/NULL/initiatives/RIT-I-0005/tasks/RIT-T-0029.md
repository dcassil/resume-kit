# Implement Verified Skill Targets

## Parent Initiative

[[RIT-I-0005]] — Phase 4 — Controlled Alignment

## Objective

Implement the deterministic verified-skill-target gate from upstream `upstream/apps/backend/app/services/improver.py`. Grounding symbols are `_normalize_skill_key`, `_extract_skill_index`, `_skill_mentioned_in_text`, `_build_allowed_skill_target_keys`, `_extract_jd_skill_index`, `_skill_present_in_resume_text`, and `verify_skill_target_plan` around `improver.py:709` and `improver.py:754`. The RIT-I-0005 invariant is that skill additions are allowed only when already present, explicit verified-JD targets, or evidence-backed; unsupported and duplicate skills must be rejected before any diff can apply.

## Acceptance Criteria

- [ ] Characterization tests first reproduce upstream `verify_skill_target_plan` behavior for existing skills, JD-required/preferred skills, resume-text-supported skills, unsupported skills, duplicates, malformed target lists, and punctuated skills such as `C++` and `C#`.
- [ ] A public deterministic verifier accepts raw planner output, original resume data, job keywords/job description, and optional candidate evidence, returning a schema `SkillTargetPlan` with accepted and rejected targets.
- [ ] Accepted targets record normalized skill, display skill, source (`existing`, `jd_added`, `supported_by_resume`, or `evidence_backed`), and reason.
- [ ] Rejected targets record normalized skill, display skill, source or rejection reason, and reason text.
- [ ] Duplicate skills are collapsed case-insensitively and unsupported skills are rejected.
- [ ] A helper equivalent to upstream `_build_allowed_skill_target_keys` is available for the alignment apply engine without importing from alignment.
- [ ] No LLM or provider imports exist in this package.
- [ ] Every ported source file has the modified-source marker required by `references/attribution.md` using SHA `116f9cc3b00e1ac91734a6c2679bf41ea64a0edc`.
