# Implement Align Resume Orchestration

## Parent Initiative

[[RIT-I-0005]] — Phase 4 — Controlled Alignment

## Objective

Implement the top-level Phase 4 engine `align_resume(...)` required by REQ-407. It wires provider proposal generation from `generation.py` to policy gating, `apply_diffs`, `verify_diff_result`, `calculate_resume_diff`, evidence truth validation, human review state, and before/after scoring through existing `packages/matching` and `packages/ats`. The critical invariant from RIT-I-0005 is that the LLM never directly writes the final document: provider output is proposal-only and must pass policy, application/verification, and truth validation before appearing in an output resume.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria

- [ ] `align_resume(resume, job, evidence, freedom, human_in_loop, provider)` or an equivalent typed API returns a schema `AlignmentResult`.
- [ ] The pipeline order is generation/provider proposal -> policy gate -> apply -> structural verify -> structured diff -> truth validation -> score/ATS impact -> optional review response/result.
- [ ] When `freedom >= 3`, truth validation always runs even if the caller did not explicitly request it.
- [ ] No aligned output contains a claim with `ProvenanceStatus.UNSUPPORTED` or `ProvenanceStatus.CONTRADICTED`; such changes are rejected, stripped, or force unresolved human review.
- [ ] An explicit NFR-405 adversarial test uses `FakeStructuredCompletionProvider` to propose a fabricated factual edit or unsupported claim and proves it never reaches the output resume.
- [ ] Invariant tests cover blocked factual field edits at freedom 10, F>=3 auto truth validation, no unsupported/contradicted claim emission, malformed provider output, no-provider deterministic empty-change path, and human-in-loop requiring input before advancement.
- [ ] Before/after score impact uses existing deterministic APIs from `resume_kit_matching` and `resume_kit_ats` without introducing cycles.
- [ ] No concrete provider, network, or `app.*` import exists in alignment.

## Implementation Notes

Use `packages/alignment/src/resume_kit_alignment/orchestrator.py`. Keep orchestration thin and explicit rather than burying policy/evidence behavior here. If truth validation rejects a change, rerun diff/verification against the stripped result so `AlignmentResult` is internally consistent. For human-in-loop, return or embed the `InterfaceResponse`/review session rather than running an interactive loop; Phase 5 owns CLI/MCP/API wrappers.
