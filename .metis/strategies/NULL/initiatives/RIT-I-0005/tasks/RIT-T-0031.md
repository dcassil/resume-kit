# Build Candidate Evidence Truth Validation

## Parent Initiative

[[RIT-I-0005]] — Phase 4 — Controlled Alignment

## Objective

Implement the new deterministic evidence engine required by REQ-406: `build_candidate_evidence(...)` and `validate_resume_truth(resume, evidence)`. Use the existing schema substrate in `packages/schemas/src/resume_kit_schemas/evidence.py` (`CandidateEvidence`, `EvidenceKind`) and `provenance.py` (`ClaimProvenance`, `ProvenanceStatus`). The truth engine should compose the structural predicates and fabrication checks from the evidence package, and it must classify material claims across the seven statuses: verified, supported, partially-supported, user-confirmed, ambiguous, unsupported, and contradicted.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria

- [ ] `build_candidate_evidence` extracts candidate evidence records from summary, work experience, projects, education, skills, certifications, and optional approved-claim inputs without inventing content.
- [ ] Evidence IDs are stable for deterministic inputs and provenance can refer back to them.
- [ ] `validate_resume_truth` returns a schema `TruthReport` containing `ClaimProvenance` records for material claims and a summary indicating whether unsupported or contradicted claims exist.
- [ ] Tests cover all seven `ProvenanceStatus` values with deterministic fixtures.
- [ ] Structural predicate failures and fabrication violations produce unsupported or contradicted provenance records as appropriate.
- [ ] User-confirmed approved claims can support claims without adding persistence or storage.
- [ ] No LLM, network, concrete provider, `app.*`, or alignment imports exist in this package.

## Implementation Notes

Use `packages/evidence/src/resume_kit_evidence/builder.py` for evidence construction and `truth.py` for provenance classification. Keep matching conservative: exact/casefold text matches can be `VERIFIED` or `SUPPORTED`, explicit user-confirmed evidence can be `USER_CONFIRMED`, partial token overlap can be `PARTIALLY_SUPPORTED`, no match is `UNSUPPORTED`, and structural contradiction/fabrication is `CONTRADICTED`. Do not build a database or approved-claim store; approved claims are function inputs. Do not edit package `__init__.py`.
