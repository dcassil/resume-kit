# Port Diff Application Engine

## Parent Initiative

[[RIT-I-0005]] — Phase 4 — Controlled Alignment

## Objective

Port the deterministic diff application engine from upstream `upstream/apps/backend/app/services/improver.py` into alignment, while delegating path and skill gates to `resume_kit_policy`. Grounding symbols are `apply_diffs` at `improver.py:226`, `_resolve_path`, `_set_at_path`, `_verify_original_matches` at `improver.py:215`, malformed/unsupported rejection branches at `improver.py:289-408`, reorder salvage and omitted-content preservation at `improver.py:335-363`, and skill-addition gates using `_build_allowed_skill_target_keys`. Characterization tests must come before freedom-aware generalization, using `upstream/apps/backend/tests/unit/test_apply_diffs.py` as the source of expected behavior.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria

- [ ] Characterization tests first cover upstream replace, append, reorder, `add_skill`, path-found, original-match, case-insensitive original match, malformed action/value rejection, duplicate skill rejection, unverified skill rejection, and reorder salvage behavior.
- [ ] `apply_diffs` accepts original resume data plus a `ChangeSet` or list of `ChangeProposal`s and returns the result resume, applied changes, rejected changes, and policy/application rejection details.
- [ ] Every proposed change passes through `resume_kit_policy.path_policy` and `resume_kit_policy.skill_targets` gates before mutation.
- [ ] `_verify_original_matches` behavior matches upstream exactly for text actions: missing original passes, non-string expected fails, non-string actual fails, string comparison is stripped and casefolded.
- [ ] Factual-field changes are rejected even at freedom 10 via policy, not by accidental path failure.
- [ ] Reorder salvage preserves omitted original items and only inserts new technical skills that are in verified allowed skill targets.
- [ ] The engine deep-copies the original and does not mutate caller input.
- [ ] Every ported source file has the modified-source marker required by `references/attribution.md` using SHA `116f9cc3b00e1ac91734a6c2679bf41ea64a0edc`.
