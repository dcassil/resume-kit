# Implement Freedom Path Policy

## Parent Initiative

[[RIT-I-0005]] — Phase 4 — Controlled Alignment

## Objective

Implement the deterministic policy subsystem that splits upstream `upstream/apps/backend/app/services/improver.py` path gates out of the mega-module and generalizes them for freedom 0-10. Grounding symbols are `_ALLOWED_PATH_PATTERNS` at `improver.py:80`, `_BLOCKED_PATH_PREFIXES` at `improver.py:94`, `_BLOCKED_FIELD_NAMES` at `improver.py:101`, `_is_path_allowed` at `improver.py:118`, `_is_path_blocked` at `improver.py:123`, `_sanitize_user_input` at `improver.py:48`, `_INJECTION_PATTERNS` at `improver.py:29`, and truthfulness rules from `upstream/apps/backend/app/prompts/templates.py` (`CRITICAL_TRUTHFULNESS_RULES_TEMPLATE`, `CRITICAL_TRUTHFULNESS_RULES`). Requirements REQ-402 and NFR-402 apply: no LLM, no `app.*`, factual fields blocked at every freedom level.

## Acceptance Criteria

- [ ] Characterization tests first reproduce upstream allowed-path and blocked-path behavior at the configured upstream-equivalent freedom level.
- [ ] `evaluate_change_policy(change, freedom)` or equivalent returns a schema `PolicyDecision` for a `ChangeProposal`, including allow/block, reason, path, action, and freedom level.
- [ ] Freedom levels 0-10 are represented by an explicit policy table; lower levels allow narrow edits such as skills-only correction and higher levels allow broader truthful summary/description/cert/language/award edits.
- [ ] Factual identity fields are blocked at every freedom level, including employer/company, title/role, dates/years, name, degree, institution, location, URLs, IDs, and metrics.
- [ ] Education description remains the only editable education path; other education identity fields remain blocked as in upstream `_is_path_blocked`.
- [ ] Prompt-injection sanitizer behavior is ported and tested for the upstream patterns.
- [ ] Truthfulness-rule constants are exposed as deterministic strings or mappings for prompts/orchestration, with no provider dependency.
- [ ] Every ported source file has the modified-source marker required by `references/attribution.md` using SHA `116f9cc3b00e1ac91734a6c2679bf41ea64a0edc`.
