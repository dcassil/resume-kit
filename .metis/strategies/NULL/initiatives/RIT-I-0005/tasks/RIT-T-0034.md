# Adapt Provider Proposal Generation

## Parent Initiative

[[RIT-I-0005]] — Phase 4 — Controlled Alignment

## Objective

Adapt the upstream LLM proposal paths so generation only proposes changes and never writes the final document. Grounding symbols are `generate_resume_diffs` at `upstream/apps/backend/app/services/improver.py:506`, `generate_skill_target_plan` at `improver.py:839`, `_prepare_keywords_for_prompt`, `_prepare_skill_targets_for_prompt`, and prompts `DIFF_IMPROVE_PROMPT`, `DIFF_STRATEGY_INSTRUCTIONS`, `SKILL_TARGET_PLAN_PROMPT`, and truthfulness prompt constants from `upstream/apps/backend/app/prompts/templates.py`. The target boundary is `packages/core/src/resume_kit_core/providers.py` (`StructuredCompletionProvider`, `StructuredCompletionRequest`) and tests must use `packages/core/src/resume_kit_core/testing.py` (`FakeStructuredCompletionProvider`).

## Acceptance Criteria

- [ ] `generate_change_proposals` or equivalent calls only an injected `StructuredCompletionProvider` and returns a schema `ChangeSet` of `ChangeProposal`s plus strategy notes/warnings.
- [ ] `generate_skill_target_plan` or equivalent calls only an injected provider, parses raw target skills, and then runs the deterministic verifier from `resume_kit_policy.skill_targets` before returning a `SkillTargetPlan`.
- [ ] Job description and other user-controlled prompt inputs pass through `resume_kit_policy.sanitizer` before prompt construction.
- [ ] Malformed provider output, missing `changes`, non-list changes, malformed individual changes, and provider failure produce safe empty proposals plus warnings or structured errors; no exception leaks in normal invalid-output cases unless core error semantics require it.
- [ ] Tests use `FakeStructuredCompletionProvider` only; no network, LiteLLM, OpenAI, Anthropic, or `app.*` imports.
- [ ] Tests verify that generated proposals are not applied in this module and that final resume data is never returned from generation.
- [ ] Every ported/adapted source file has the modified-source marker required by `references/attribution.md` using SHA `116f9cc3b00e1ac91734a6c2679bf41ea64a0edc`.
