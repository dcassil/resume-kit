# Add Phase 4 Result Schemas

## Parent Initiative

[[RIT-I-0005]] — Phase 4 — Controlled Alignment

## Objective

Add the minimal missing Phase 4 result models required by RIT-I-0005 without duplicating existing schema substrate. Existing models to reuse are `packages/schemas/src/resume_kit_schemas/change.py` (`ChangeProposal`, `Diff`, `ResumeDiffSummary`, `ChangeSet`), `evidence.py` (`CandidateEvidence`, `EvidenceKind`), `provenance.py` (`ClaimProvenance`, `ProvenanceStatus`), plus `resume.py`, `job.py`, and `analysis.py`. The initiative calls for central models for policy decisions, alignment result envelopes, truth reports, review sessions/decisions, and skill-target plans.

## Acceptance Criteria

## Acceptance Criteria

- [ ] A single new schema module defines `PolicyDecision`, `PolicyRejection`, `AlignmentResult`, `TruthReport`, `ReviewSession`, `ReviewDecision`, and `SkillTargetPlan` or equivalently named minimal models covering the same concepts.
- [ ] The new models compose existing `ChangeProposal`, `ChangeSet`, `Diff`, `ResumeDiffSummary`, `CandidateEvidence`, `ClaimProvenance`, `ProvenanceStatus`, `Warning`, `ATSScore`, `JobMatchReport` or `ScoreDelta` types instead of redefining them.
- [ ] `PolicyDecision` records freedom level, allow/block status, reason code, human-readable explanation, and the relevant path/action.
- [ ] `TruthReport` records per-claim provenance plus a deterministic pass/fail summary that can identify unsupported or contradicted claims.
- [ ] `AlignmentResult` can carry original resume, aligned resume, applied/rejected changes, warnings, unresolved questions, before/after match or ATS results, truth report, and review state without requiring any CLI/API transport model.
- [ ] Schema tests cover validation defaults, status/reason literals or enums, and serialization round-trips.
- [ ] No existing schema files are edited except the new test file and new model module; public exports are deferred to the late export task.

## Implementation Notes

Place all new result types in `packages/schemas/src/resume_kit_schemas/results.py` to avoid collisions with existing `change.py`, `evidence.py`, and `provenance.py`. Use Pydantic v2 and the style from existing schema modules. Keep aliases and field names transport-agnostic. Do not add package exports here; `packages/schemas/src/resume_kit_schemas/__init__.py` is reserved for the late export task.
