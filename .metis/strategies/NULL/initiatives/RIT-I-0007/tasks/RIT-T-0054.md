# Add the MCP resume_export tool

## Parent Initiative

[[RIT-I-0007]] — Phase 6 — Export & Packaging

## Objective

Add a thin MCP adapter for the facade `export-resume` capability in `packages/mcp/src/resume_kit_mcp/tools.py` and expose it through `packages/mcp/src/resume_kit_mcp/server.py`. Follow the existing `TOOL_NAMES`, `HANDLERS`, validation, `_call`, and envelope dumping patterns. The MCP tool name must be `resume_export` and input `resume` is a serialized `ResumeDocument`.

## Acceptance Criteria

- [ ] `TOOL_NAMES`, `HANDLERS`, and server `TOOLS` include exactly one new `resume_export` tool.
- [ ] `resume_export` validates `resume` and `format`, calls `REGISTRY['export-resume']`, and returns the canonical JSON envelope with artifact metadata.
- [ ] The MCP result includes base64-encoded artifact bytes in a transport-appropriate JSON field without putting raw bytes into `InterfaceResponse.artifacts`.
- [ ] MCP tests cover tool registration, PDF and DOCX success, invalid format validation, envelope shape, artifact metadata, and base64 bytes that decode to valid PDF/DOCX signatures.

## Implementation Notes

Keep the adapter thin: no ReportLab/python-docx imports and no renderer logic. Reuse existing `_resume`, `_optional_string`, `_validation_error`, `_dump`, and `CapabilityOptions` patterns. Use a local in-memory `ArtifactStore` injection so the handler can retrieve and base64-encode bytes after the facade returns.
