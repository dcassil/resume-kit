# Implement the python-docx renderer

## Parent Initiative

[[RIT-I-0007]] — Phase 6 — Export & Packaging

## Objective

Implement deterministic DOCX rendering for `resume_kit_export` using `python-docx`, satisfying REQ-601/NFR-604 from `.metis/strategies/NULL/initiatives/RIT-I-0007/initiative.md`. The renderer mirrors the PDF section content for `ResumeDocument.personalInfo`, `summary`, `workExperience`, `education`, `personalProjects`, `additional`, and visible `customSections` from `packages/schemas/src/resume_kit_schemas/resume.py`.

## Acceptance Criteria

- [ ] `render_docx(resume: ResumeDocument, *, options: ExportOptions | None = None) -> bytes` returns valid DOCX bytes loadable by `python-docx`.
- [ ] Identical input and options produce identical bytes or an explicitly documented stable structural fingerprint; core document properties and ZIP entries contain no wall-clock timestamp, random id, or locale-dependent formatting.
- [ ] Structural tests reopen the DOCX with `python-docx` and assert headings, contact fields, summary, bullets, education, projects, additional sections, and custom sections are present in deterministic order.
- [ ] The renderer imports no transport package, no facade package, no provider/LLM package, and no upstream `app` namespace.

## Implementation Notes

Use the `python-docx` API directly: headings, normal paragraphs, and bullet-list paragraph styles. For byte determinism, set core properties to fixed values and normalize ZIP entry metadata if necessary before returning bytes. Keep all DOCX-specific helpers in `docx.py` so PDF work stays file-disjoint.
