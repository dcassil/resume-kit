# Add the API export route

## Parent Initiative

[[RIT-I-0007]] — Phase 6 — Export & Packaging

## Objective

Add the REST adapter for `export-resume` in `packages/api/src/resume_kit_api/models.py` and `packages/api/src/resume_kit_api/routes.py`, registered by `packages/api/src/resume_kit_api/app.py`. Follow the existing POST endpoint style and status policy: request bodies are Pydantic wrappers over schema values, routes translate to facade request dataclasses plus `CapabilityOptions`, and the facade owns all business behavior.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria

- [ ] `ExportResumeBody` accepts `resume: ResumeDocument`, `format: pdf|docx`, shared `_Options`, and any export options supported by `ExportOptions`.
- [ ] `POST /export` calls `REGISTRY['export-resume']` with an injected `ArtifactStore` and returns either the artifact bytes with the correct content type or a JSON envelope containing artifact metadata plus base64 bytes, as selected by an explicit request option or documented default.
- [ ] API tests cover PDF and DOCX success, correct content type when returning bytes, JSON envelope/artifact metadata when returning JSON, invalid body validation, and no-provider behavior.
- [ ] No renderer logic, ReportLab/python-docx imports, CLI imports, MCP imports, or job-hunter bridge imports appear in API code.

## Implementation Notes

Prefer preserving the canonical `InterfaceResponse` body for parity tests and add a clearly named option such as `return_bytes` only if needed for direct binary responses. When returning binary bytes, still derive status from the facade envelope and include artifact id/content type in headers if practical. Keep `_status_for` and `_render` policy intact for ordinary envelope responses.
