# Implement the ReportLab PDF renderer

## Parent Initiative

[[RIT-I-0007]] — Phase 6 — Export & Packaging

## Objective

Implement deterministic PDF rendering for `resume_kit_export` using ReportLab, satisfying REQ-601/NFR-604 from `.metis/strategies/NULL/initiatives/RIT-I-0007/initiative.md`. Render `ResumeDocument.personalInfo` (`name`, `title`, `email`, `phone`, `location`, `website`, `linkedin`, `github`), `summary`, `workExperience[]` (`title`, `company`, `location`, `years`, `description[]`), `education[]`, `personalProjects[]`, `additional` (`technicalSkills`, `languages`, `certificationsTraining`, `awards`), and visible `customSections`.

## Acceptance Criteria

- [ ] `render_pdf(resume: ResumeDocument, *, options: ExportOptions | None = None) -> bytes` returns valid `%PDF` bytes using ReportLab only.
- [ ] Identical input and options produce identical bytes in repeated calls; PDF metadata is fixed and contains no wall-clock timestamp, random id, locale-dependent text, or generated UUID.
- [ ] Structural tests parse produced PDF text with `pdfminer` and assert the header, contact fields, summary, experience bullets, education, projects, additional sections, and custom sections are present in deterministic order.
- [ ] The renderer imports no transport package, no facade package, no provider/LLM package, and no upstream `app` namespace.

## Implementation Notes

Use ReportLab Platypus flowables (`SimpleDocTemplate`, `Paragraph`, `Spacer`, `ListFlowable`/bullet paragraphs, fixed styles, standard fonts). Normalize optional empty fields by omitting blank fragments, not by rendering placeholders. Set deterministic document metadata explicitly and avoid ReportLab APIs that inject creation/modification timestamps unless overridden. Keep all PDF-specific helpers in `pdf.py` so DOCX work can proceed in parallel.
