# Job-aware deterministic rankers (skills/experience/bullets)

## Parent Initiative **[REQUIRED]**

[[RIT-I-0021]] — Phase 2 of 7. **This is the core new logic of the initiative** (REQ-003).

## Objective **[REQUIRED]**

Build three deterministic, **job-weighted** rankers that turn each budget violation from Phase 1
into an ordered list of trim candidates (lowest value first). Given a tailored resume and its
target job description, they score every trimmable unit against the job (reusing
`resume_kit_matching/keywords.py` + the [[RIT-I-0009]] project alias index) and return a
reproducible ordering. **Ties defer to a decision — never a silent coin-flip pick** (NFR-001).
The lowest-ranked units become trim candidates until the budget is met.

## Acceptance Criteria **[REQUIRED]**

- [ ] `rank_skills`, `rank_experience`, `rank_bullets` exist in `packages/scoring`, each pure,
      deterministic, and reproducible for a fixed `(resume, job, policy)`.
- [ ] **Skills ranking:** keep skills matched in the job AND used in experience/summary highest;
      then specific-technical; drop duplicates / umbrella / soft-skill / foundational items first.
      Job-match uses `resume_kit_matching` + the effective alias index (exact+alias, stemming OFF).
- [ ] **Experience ranking:** score by recency ∧ seniority ∧ job-relevance ∧ quantified-outcome;
      **compress-before-remove** — an older low-relevance role yields a compression candidate
      (fewer bullets) *before* a whole-entry removal candidate; continuity preserved unless removal
      is explicitly approved downstream.
- [ ] **Bullet ranking:** keep quantified-impact + architecture/leadership/scope highest; drop
      tool-only / redundant bullets first.
- [ ] **Tie → defer:** equal-ranked units are emitted as a deferred/ambiguous group, never
      silently ordered against each other. Verified by a table test.
- [ ] Rankers consume Phase 1 `BudgetViolation`s to know how many units to propose per dimension;
      they do **not** apply anything (application is Phase 4).
- [ ] Per-ranker table tests over crafted `(resume, job)` pairs assert exact ordering for each
      rule, including tie→defer and compress-before-remove.

## Implementation Notes **[REQUIRED]**

### Technical Approach
- New modules `resume_kit_scoring/rank_skills.py`, `rank_experience.py`, `rank_bullets.py` plus a
  small shared scoring helper. Each ranker is a pure function returning an ordered list of trim
  candidates with a stable secondary sort key so ordering is fully deterministic.
- Reuse `resume_kit_matching` keyword/alias machinery for job-weighting — do NOT reimplement
  matching. Load the effective alias index via the existing [[RIT-I-0009]]
  `load_effective_alias_index` path so grown, user-confirmed aliases count.
- Candidates should be representation-only (identify the unit + why it ranked low + whether it is a
  trim vs compress vs defer candidate). The `ChangeProposal` construction happens in Phase 4.
- Ties: detect equal composite scores and mark the group `defer` rather than imposing an order.

### Dependencies
- **HARD dependency on [[RIT-I-0019]]** (`ResumeShapePolicy`) and **Phase 1 [[RIT-T-0142]]**
  (`BudgetViolation`). Reuses `resume_kit_matching` + [[RIT-I-0009]] alias index (already on main).
- RIT-I-0019 **not yet merged to main** — do not start until it lands.

### Risk Considerations
- Determinism is the top risk: any set iteration or dict ordering leaking into the result breaks
  reproducibility. Use explicit, total sort keys and cover with a "same input → same output" test.
- Over-fitting rules to the fixture: keep rules readable and rule-per-test so intent is auditable.

### Recommended Agent
`opus + high` — the substantive new logic the whole stage is built to enable; correctness and
determinism here are load-bearing for every trim decision.
