# Budget enforcer + stage-appropriate content ledger

## Parent Initiative **[REQUIRED]**

[[RIT-I-0021]] — Phase 1 of 7.

## Objective **[REQUIRED]**

Build the deterministic **budget enforcer** for the `perfect`/`fit` stage: a pure function
that reads the [[RIT-I-0019]] `ResumeShapePolicy` budget fields (informational pre-job) and a
tailored resume, and emits one **violation** per over-budget dimension with the overage amount —
*without* trimming anything (REQ-002). Also extend the [[RIT-I-0019]] `ContentLedger` with the
**stage-appropriate** allowed-reason set for `perfect` and its accounting gate (REQ-006): unlike
`structure`/`refine`, this stage *permits* content removal, but only when accounted for.

This is the foundation every later phase consumes: rankers (Phase 2) close the gap the enforcer
quantifies; `build_perfect` (Phase 4) uses the ledger gate to prove no unaccounted loss.

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `budget_enforce(resume, policy) -> list[BudgetViolation]` exists in `packages/scoring`
      (`resume_kit_scoring`), pure and deterministic, no LLM, no network.
- [ ] Emits one violation per over-budget dimension covering **all** shape-policy budgets:
      `skills_count`, `experience_entries`, recent-job bullets, older-job bullets, `bullet_words`,
      `summary_words`, `max_pages` (page budget carried as an *informational* estimate here — the
      hard render gate is Phase 5).
- [ ] Each `BudgetViolation` records: dimension key, the budget limit, the actual count, and the
      overage amount (actual − limit). No trimming or selection logic lives in the enforcer.
- [ ] Budgets are **project-overridable** via the existing `ResumeShapePolicy` override path from
      [[RIT-I-0019]] (no new config surface invented).
- [ ] `ContentLedger` allowed-reason set is extended for this stage to:
      `present_after | moved | deduped | dropped_by_explicit_decision | dropped_by_ranked_budget | compressed`.
      The `structure`/`refine` posture (which forbids the `dropped_*` reasons) is unchanged for
      those stages — the expanded set is scoped to `perfect`.
- [ ] A ledger **accounting gate** asserts every removed token is accounted for by one of the
      allowed reasons; an unaccounted loss **fails** the gate (hard).
- [ ] Unit tests: violation math (hit + clean per dimension), overage correctness, project
      override honored, and ledger gate (accounted drop passes; unaccounted loss fails; each new
      reason exercised).

## Implementation Notes **[REQUIRED]**

### Technical Approach
- New module `resume_kit_scoring/budget_enforce.py` (or package-local equivalent) exporting
  `budget_enforce` + a `BudgetViolation` model (Pydantic v2, in `packages/schemas` if it must cross
  the package boundary — follow the existing scoring/schemas split).
- Read budgets off the `ResumeShapePolicy` produced by [[RIT-I-0019]]; treat the object as the
  single source of budget truth. Do **not** duplicate default numbers — pull them from the policy.
- Extend the [[RIT-I-0019]] `ContentLedger` in place (same shape) with a stage/reason-set parameter
  so `structure`/`refine` keep their stricter allowed set and `perfect` gets the expanded one.
  Prefer an explicit `allowed_reasons` argument or a stage enum over branching on strings.
- Enforcer is a **quantifier only** — it must contain zero ranking/selection logic (that is
  Phase 2). Keep the seam clean so rankers and the enforcer are independently testable.

### Dependencies
- **HARD dependency on [[RIT-I-0019]]** (`ResumeShapePolicy` budget fields + `ContentLedger`).
  RIT-I-0019 is **not yet merged to main** (in-flight on `feat/rit-i-0019-structure-pass`).
  **Do not start coding until RIT-I-0019 lands on main** (per the initiative's deferral decision).
- No dependency on [[RIT-I-0020]] for this phase.

### Risk Considerations
- If `ResumeShapePolicy` budget field names/shape shift during RIT-I-0019 finalization, this
  module must track them — bind to the policy object, not copied constants, to minimize churn.
- Keep the ledger change backward-compatible: `structure`/`refine` tests must stay green.

### Recommended Agent
`opus + high` — foundational; downstream rankers, `build_perfect`, and the ledger gate all depend
on getting the enforcer/ledger seam right.
