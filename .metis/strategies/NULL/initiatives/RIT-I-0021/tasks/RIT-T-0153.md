Prove the whole stage end to end on a real fixture, reconcile docs, and cut the release. An

## Implementation Notes **[REQUIRED]**

### Technical Approach
- Integration test lives in the standard integration location; deterministic ranking (no
  network/LLM; compression phrasing mocked) but a **real renderer** for the page-gate path,
  confined to `packages/export`.
- Follow the established publish flow from prior initiatives (see orchestration memory): bump root
  `pyproject` version → `git tag -a vX.Y.Z` → push tag → `publish.yml` (OIDC); bump
  plugin + marketplace versions; note that `uv tool`/index cache lags ~15–30s; restart Claude Code
  after publish so the MCP server + plugin reload.
- This task is the orchestrator's release step — the merge to `main`, version bumps, and publish
  are performed by the orchestrator (not worker agents), per AGENTS.md git ownership.

### Dependencies
- **Depends on all prior phases** (RIT-T-0142, 0148, 0149, 0150, 0151, 0152) and, transitively, on
  RIT-I-0019 + RIT-I-0020 being merged to main.

  merge→bump→publish flow for this initiative; still verify the branch is green before tagging.
