# Surfaces + perfect/fit skill + resume-workflow wiring

## Parent Initiative **[REQUIRED]**

[[RIT-I-0021]] — Phase 6 of 7. Owns REQ-012 and NFR-005 (surface parity).

## Objective **[REQUIRED]**

Expose `build_perfect` across every surface with cross-surface parity, add the conversational
`perfect`/`fit` plugin skill (reusing the edit-session decision UX), and wire `perfect` into
`resume-workflow` as the final step after tailoring — with export enforcing the Phase 5 page-gate.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] **CLI:** `resume-tool fit` (alias `perfect`) drives `build_perfect`, supporting interactive
      and `--auto-fit` modes and the export override flag.
- [ ] **MCP:** `resume_build_perfect` tool with the same parameters and results as the facade.
- [ ] **API:** parity entry for `build_perfect`.
- [ ] **Parity (NFR-005):** facade/CLI/MCP/API produce identical ranked candidates, identical
      finals, and identical lineage for the same `(resume, job, policy)` — enforced by parity tests.
- [ ] **`perfect`/`fit` plugin skill** (resume-intelligence plugin): single-responsibility,
      self-gating (has a `_shared/prerequisites.md`-style gate requiring a `tailored` resume + active
      job), reuses the existing edit-session decision UX for keep/drop/compress. Interactive =
      ranked candidates + per-item decisions; auto-fit = default ranking, logged + gated.
- [ ] **`resume-workflow` guide updated** so `perfect` is the final step after tailoring and before
      export, and export enforces the page hard-gate.
- [ ] Skill + surface docs updated; no fabrication of unavailable options.

## Implementation Notes **[REQUIRED]**

### Technical Approach
- Thin adapters only — CLI/MCP/API delegate straight to the `build_perfect` facade; no business
  logic in the surfaces (matches the established adapter pattern in this repo).
- The plugin skill mirrors the existing improve-phase skills' shape: prerequisites gate → invoke
  the capability → present the reused edit-session decision UX. Do not build new decision UI.
- Update the `resume-workflow` runbook skill to name `perfect` as the final tailoring step and to
  state the export page-gate as the closing gate.

### Dependencies
- **Depends on Phase 4 [[RIT-T-0150]]** (`build_perfect`) and **Phase 5 [[RIT-T-0151]]** (export
  gate). Reuses the edit-session decision UX ([[RIT-I-0015]]) and the plugin skill conventions
  ([[RIT-I-0011]]).

### Risk Considerations
- Parity is easy to break across four surfaces — the parity tests are the acceptance gate; run the
  same `(resume, job, policy)` through all four and diff.
- Plugin changes require a plugin version bump + reload/restart to take effect (handled in Phase 7).

### Recommended Agent
`opus + medium` — multi-surface but follows the known adapter + skill pattern.
