# Compression: claim-gated length rewrites (no truncation)

## Parent Initiative **[REQUIRED]**

[[RIT-I-0021]] — Phase 3 of 7. Owns REQ-007 and half of the [[RIT-I-0020]] handoff (REQ-010).

## Objective **[REQUIRED]**

Turn over-length units (summary over `summary_words`, bullets over `bullet_words`) into
**claim-gated rewrite candidates** that shorten while preserving every claim and the meaning —
routed through the same truth+claim gates as `refine`/`align-resume`. **Naive string truncation is
prohibited** (REQ-007): a compression that would drop a claim must FAIL the gate and be surfaced as
a rewrite that could not be made truthfully, not silently cut. Implements the relocated
`SUMMARY_TOO_LONG` as the summary length-budget path (REQ-010).

## Acceptance Criteria **[REQUIRED]**

- [ ] `compress` module in `packages/scoring` produces a rewrite candidate for an over-length
      summary or bullet: shorter text under budget, same claims, same meaning.
- [ ] Every compression is routed through the existing **truth + claim gates** (reuse the
      `refine`/`align-resume` truth path from [[RIT-I-0015]]/[[RIT-A-0001]]); a rewrite that drops
      or contradicts a claim **fails** the gate (hard) — no fabrication, no claim loss.
- [ ] **No truncation:** there is no code path that shortens by cutting characters/words without
      passing the claim gate. A test asserts truncation-style loss is rejected.
- [ ] `SUMMARY_TOO_LONG` (relocated from [[RIT-I-0020]]'s `refine` pass) is consumed here as the
      summary length-budget → compression path.
- [ ] Any LLM assist for phrasing is confined and separable (mockable in tests), consistent with
      the existing analyzer/align contract (NFR-001); the deterministic path has no per-item LLM.
- [ ] Unit tests: a valid compression passes the gate; a claim-dropping compression fails; the
      summary and bullet paths each covered; LLM phrasing mocked.

## Implementation Notes **[REQUIRED]**

### Technical Approach
- New `resume_kit_scoring/compress.py` producing rewrite candidates. Reuse the truth/claim
  validation already used by `refine`/`align-resume` (do not build a new gate) — call into the
  existing `resume_kit_ats`/truth path.
- The compressor proposes; it does not apply. Emitted candidates become compression
  `ChangeProposal`s in Phase 4 and are applied through the shared runbook there.
- Confine any LLM phrasing behind the existing provider `Protocol` so tests inject a stub; the
  gate (truth/claim) is the deterministic arbiter regardless of phrasing source.

### Dependencies
- **Depends on [[RIT-I-0020]]** for the relocated `SUMMARY_TOO_LONG` finding + the finalized
  `refine` truth/claim gate location. **RIT-I-0020 has not started / no branch yet.**
- Also depends on Phase 1 [[RIT-T-0142]] (length violations) and the [[RIT-I-0015]] truth path
  (on main).
- Do not start until RIT-I-0020's refine truth-gate + SUMMARY_TOO_LONG relocation land on main.

### Risk Considerations
- The claim gate must be the *same* one `refine` uses, or truth semantics diverge. Bind to it;
  do not copy.
- Guard against a "compression" that technically preserves claims but changes emphasis/meaning —
  cover with a meaning-preservation test case.

### Recommended Agent
`opus + medium` — substantive but fits the known truth-gate pattern; the reused gate does the
heavy correctness lifting.
