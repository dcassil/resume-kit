# Export page hard-gate on real render

## Parent Initiative **[REQUIRED]**

[[RIT-I-0021]] — Phase 5 of 7. Owns REQ-009.

## Objective **[REQUIRED]**

Add a page-count **hard gate** at export so no over-length resume is ever submitted. `perfect`
estimates pages during the fit pass (informational warning only), but the authoritative check is
against the **real render**: `resume_kit_export`/`resume_export` measures the rendered page count
and hard-gates if it exceeds `max_pages`, with a user override flag. Real measurement comes from
the renderer (fonts/margins/template determine real pages), not a JSON heuristic.

## Acceptance Criteria **[REQUIRED]**

- [ ] `resume_kit_export` gains a page-count check against the `max_pages` shape-policy budget,
      computed from the **rendered** document (not a JSON estimate).
- [ ] `export`/`resume_export` **hard-gates** (non-zero / blocking result) when rendered pages
      exceed `max_pages`, with a clear over-length message and an explicit user **override flag**
      that allows the export through.
- [ ] `perfect` (Phase 4) surfaces an **informational page estimate warning** during the fit pass;
      it does not block — the block lives only at export on the real render.
- [ ] The page measurement stays **renderer-confined** per the export boundary invariant
      (extends [[RIT-I-0007]] export); no rendering logic leaks into scoring/facade.
- [ ] Unit tests with a **stub renderer**: over-length render → gate blocks; within-budget →
      passes; override flag lets an over-length export through; the message is clear.

## Implementation Notes **[REQUIRED]**

### Technical Approach
- Extend the existing export path in `packages/export` (`resume_kit_export`). Get the page count
  from the renderer output, not from counting JSON. Keep the check inside the export boundary.
- Add an override parameter that threads from the facade/CLI/MCP surfaces (wired in Phase 6) down
  to the gate. Default is enforce; override bypasses with a logged acknowledgement.
- Provide a stub/mock renderer hook so unit tests can assert gate behavior without a real PDF
  toolchain, while the integration test (Phase 7) exercises the real renderer.

### Dependencies
- Depends on [[RIT-I-0019]] `ResumeShapePolicy` (`max_pages`) and the existing [[RIT-I-0007]]
  export subsystem (on main). Independent of Phases 2–4, so it can proceed in parallel with them
  once RIT-I-0019 lands.

### Risk Considerations
- The whole reason this is a *separate* gate is that JSON estimates lie about real pages — do not
  let a heuristic sneak in as the hard gate. The hard block MUST use the render.
- Renderer determinism across environments: pin/relax as the export subsystem already does; the
  stub keeps unit tests hermetic.

### Recommended Agent
`opus + medium` — contained to the export package with a clear boundary; moderate reasoning.
