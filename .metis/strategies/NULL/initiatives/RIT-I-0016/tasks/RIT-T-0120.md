# Plugin skills + resume-workflow gating tailoring behind standard

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0016]]

## Objective **[REQUIRED]**

Author the conversational plugin skills for the baselining flow (`original → base → standard`) and wire them into the `resume-workflow` guide so that **all job-specific tailoring is GATED behind the existence of a `standard` version** (or an explicit, recorded user override). This is Phase 5's skill + workflow slice of RIT-I-0016: it surfaces the baselining capabilities added by the prior phases (facade/CLI/MCP/API capabilities exposed in RIT-T-0119) as single-responsibility skills, and it changes the `resume-workflow` ordering so the mandatory pre-tailoring phase runs first. After this task, a user driving resume-kit through the plugin cannot begin keyword/JD tailoring on a resume that has not first been baselined, unless they explicitly opt out.

## Acceptance Criteria **[REQUIRED]**

- [ ] A skill exists under `plugins/resume-intelligence/skills/` that runs the **ATS structural check + `base` fix** for a resume: it invokes the extended `resume_check_ats_structure` capability, presents findings, and drives the `base` fixer in **both** `auto` and `interactive` modes (user's choice), writing `<name>-base.json` behind the faithfulness gate. The skill states explicitly that `auto` applies only deterministic, truth-preserving fixes and defers judgment items.
- [ ] A skill exists that runs the **generic best-practices score** on `base`, producing the best-practices report with each flagged item shown as `auto_suggestible` vs `needs_user_input` (per the RIT-T-0116 severity taxonomy). It does not itself apply edits.
- [ ] A skill exists that drives the **`standard` walkthrough**: it iterates the flagged items on the RIT-I-0015 edit-session orchestrator, auto-suggests fixes where possible, elicits user facts for `needs_user_input` items, routes every rewrite through the truth gate, logs accept/reject via the feedback log, and on completion writes `<name>-standard.json` and points config's `standard` pointer at it.
- [ ] `resume-workflow` (`plugins/resume-intelligence/skills/resume-workflow`) is updated so the **baselining phase (ingest → base → standard) is documented as running BEFORE any job-specific tailoring step** (`check-keyword-match`, `inject-keywords`, `align-terminology`, `identify-resume-gaps`).
- [ ] In `resume-workflow`, every tailoring step is **gated on `standard` being present** (or an explicit user override that is recorded), using prerequisite-gating phrasing that matches the existing gate pattern in the guide (e.g. how tailoring already gates on an active job / faithful `original`).
- [ ] The `base`/structural-check skill **reuses RIT-I-0017's single "what the ATS sees" report** (owned by RIT-I-0017) rather than printing a second, independent ATS-view of the resume.
- [ ] All new skill docs are **internally consistent**: no skill claims a behavior the underlying capability does not provide (e.g. the walkthrough skill must not claim it can fabricate metrics; the `auto` fix skill must not claim it rewrites wording).
- [ ] Each new skill is **single-responsibility**, mirroring the structure/frontmatter/section conventions of the existing `check-ats-structure` and `inject-keywords` skills (naming, invocation, capability-call pattern, output shape).

## Documentation Sections **[CONDITIONAL: Documentation Task]**

### User Guide Content
- **Feature Description**: A pre-tailoring baselining phase that gets the resume itself into good shape — structurally ATS-clean (`base`) and best-practices-strong (`standard`) — before any job enters the picture. `standard` then becomes the default resume for all tailoring.
- **Prerequisites**: A faithfully-ingested `original` (RIT-I-0014) exists; the baselining facade/CLI/MCP capabilities from RIT-T-0119 are available; the RIT-I-0015 edit-session orchestrator is present for the walkthrough.
- **Step-by-Step Instructions**:
  1. Run the structural-check + `base` skill; choose `auto` (unattended, faithfulness-safe) or `interactive` (approve each fix). Result: `<name>-base.json`.
  2. Run the best-practices score skill on `base`; review flagged items classified auto-suggestible vs needs-input.
  3. Run the `standard` walkthrough skill; answer targeted questions for needs-input items, accept/reject suggestions. Result: `<name>-standard.json` set as the tailoring default.
  4. Proceed to tailoring — now gated: it runs against `standard`.

### Troubleshooting Guide
- **Tailoring appears blocked**: This is expected when no `standard` exists. Complete the baselining phase, or explicitly override (the override is recorded).
- **Second ATS view appears**: A regression — the `base` skill must surface RIT-I-0017's "what the ATS sees" report, not emit its own.
- **Error Messages**: "No `standard` version — baselining required before tailoring (or pass an explicit override)" indicates the gate is working as designed.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Mirror the existing single-responsibility skills. Use `plugins/resume-intelligence/skills/check-ats-structure` as the template for the structural-check + `base`-fix skill and `plugins/resume-intelligence/skills/inject-keywords` as the template for the walkthrough-style interactive skill. Each new skill calls exactly one baselining facade capability (surfaced in RIT-T-0119) and orchestrates the conversation around it. Update `plugins/resume-intelligence/skills/resume-workflow` to (a) insert the baselining phase ahead of the tailoring phase and (b) add the `standard`-present prerequisite gate to each tailoring step, reusing the same gate phrasing already used for the active-job / faithful-`original` prerequisites so the guide stays consistent. Do not rebuild the "what the ATS sees" report — reference/reuse the RIT-I-0017-owned one.

### Dependencies
- **Blocked by [[RIT-T-0119]]**: needs the baselining capabilities surfaced across facade/CLI/MCP/API before skills can call them.
- Reuses RIT-I-0017's "what the ATS sees" report; reuses the RIT-I-0015 edit-session orchestrator + hard write gate for the `standard` walkthrough.

### Risk Considerations
- **Gate too aggressive** — legitimately blocking users with a good `original`. Mitigation: the explicit, recorded override path.
- **Doc/behavior drift** — a skill overstating capability (e.g. implying fabrication). Mitigation: the internal-consistency acceptance criterion and the doc-consistency verification below.
- **Duplicate ATS view** — accidentally printing a second ATS report. Mitigation: explicit reuse criterion.
