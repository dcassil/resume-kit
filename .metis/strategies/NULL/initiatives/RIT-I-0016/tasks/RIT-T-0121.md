# End-to-end integration test (original to base to standard) + README/docs reconcile + version bump

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0016]]

## Objective **[REQUIRED]**

Prove the full `original → base → standard` lineage end-to-end over a real fixture resume, reconcile the README/docs to the shipped baselining behavior, and bump the package version. This is the closing task of RIT-I-0016 (Phase 6): it turns the per-phase unit coverage into a single integration test that exercises ingest through `standard`-as-default, asserts the three artifacts and config state, and confirms the deterministic path runs with no network/LLM. It also removes any stale documentation claims and records the version bump per repo convention.

## Acceptance Criteria **[REQUIRED]**

- [ ] An **end-to-end integration test** reuses an existing fixture resume (e.g. the Staff-FS resume used in prior integration tests) and runs the full lineage: ingest → `original` → `base` (auto) → best-practices report → simulated walkthrough acceptance → `standard`.
- [ ] The test asserts `base` **passes the ATS structural check AND the faithfulness gate** relative to `original`.
- [ ] The test asserts the **best-practices report is produced with correct classification** — every flagged item is tagged `auto_suggestible` or `needs_user_input`, and at least one of each class appears for the fixture.
- [ ] The test drives a **simulated walkthrough acceptance** (auto-suggestible items accepted; needs-input items resolved with supplied test facts), all rewrites passing the truth gate, and asserts `<name>-standard.json` is written.
- [ ] The test asserts the **three artifacts exist** (`<name>-original.json`, `<name>-base.json`, `<name>-standard.json`) and that **config points correctly**: `standard` pointer set and resolved as the tailoring default (`standard ?? base ?? original`).
- [ ] The **deterministic path runs with no network and no live LLM** — any LLM-assisted soft judgment is mocked/stubbed; the test passes offline.
- [ ] **README/docs updated** to describe the baselining phase and the `original/base/standard` model (including that `standard` is the default tailoring input); **no stale claims** remain that imply tailoring runs directly off `original`.
- [ ] **Version bumped** per repo convention (from the current `0.6.0` in `pyproject.toml`); umbrella/lockfile updated if applicable and a version/lockfile diff is present.
