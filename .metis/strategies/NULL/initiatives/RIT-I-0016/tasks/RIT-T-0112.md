# Harden commit_session: fresh post-apply truth revalidation before base/standard rely on the write gate

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0016]]

## Objective **[REQUIRED]**

Make `commit_session`'s truth gate authoritative over the FINAL assembled resume, not just over per-change provenance seeded at proposal time. Today `_contradicted_paths` (`packages/facade/src/resume_kit_facade/edit_session.py`, ~lines 649-657) refuses a commit only if a change's *pre-seeded* `state.review_session.claim_provenance` carries a `ProvenanceStatus.CONTRADICTED` entry. That provenance was computed when each change was individually PROPOSED. It never re-runs truth validation against the document produced by `apply_diffs` once all accepted changes are assembled together. RIT-I-0016's `standard` walkthrough applies many user-fact-derived rewrites in one session, so a claim can become contradicted only in the *combination* (e.g. two bullets that each looked supported but together assert conflicting scope/dates). This task hardens the shared write gate — the same gate `base` and `standard` will lean on — by adding a fresh, deterministic, post-apply truth recompute as the authoritative final check, while preserving the existing per-change provenance check as a fast pre-gate. It is foundational: no `base`/`standard` producer should depend on the write gate until the gate verifies the assembled artifact.

## Acceptance Criteria **[REQUIRED]**

- [ ] `commit_session` assembles the post-apply working document (the dict returned by `apply_diffs` over the accepted `ChangeProposal`s) and runs a FRESH truth validation over that assembled document via the existing deterministic `resume_validate_truth` validator — not only the seeded `claim_provenance`.
- [ ] Any claim the fresh recompute marks `CONTRADICTED` refuses the commit with a machine-readable hard-gate error (same shape/`_raise_gate` convention as the existing gate, per [[RIT-A-0001]]) whose payload names every offending JSON path.
- [ ] The refusal propagates to a non-zero CLI exit code on the commit path (parity-consistent across facade/CLI).
- [ ] Backward compatible: the existing per-change `_contradicted_paths` provenance check is preserved and runs FIRST as a fast pre-gate; the fresh assembled-doc recompute is the authoritative final gate. A session that passes both today still commits with no behavior change.
- [ ] The recompute path is deterministic and fully offline — no network/LLM call — reusing the existing deterministic truth validator; running the same session twice yields identical gate results.
- [ ] A regression test proves a session with two changes that are each individually `SUPPORTED` by seeded provenance but yield a `CONTRADICTED` claim once assembled together is refused at commit (and would have wrongly committed under the old provenance-only gate).
- [ ] A documented **freshness contract** is added to the `commit_session` / `_contradicted_paths` docstring stating: the write gate's authoritative truth check is always computed over the assembled post-apply document, provenance is only an advisory fast pre-check, and no version may be persisted whose assembled form fails truth validation.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Entry point: the `commit_session` path in `packages/facade/src/resume_kit_facade/edit_session.py`. Keep `_contradicted_paths` as the fast pre-check; add an authoritative step after it.
- Assemble the final doc with `apply_diffs` (`packages/alignment/src/resume_kit_alignment/apply.py:250`) over the accepted changes — reuse the same assembly the commit already performs so the gate validates exactly the bytes that would be written; do not build a parallel/second assembly.
- Run the assembled dict through the deterministic `resume_validate_truth` validator (same validator the truth gate already uses; RIT-T-0095 CONTRADICTED/UNSUPPORTED semantics). Collect every path whose status is `CONTRADICTED`.
- Refuse via the existing `_raise_gate("...", ...)` shape so CLI/MCP/API error handling and exit codes stay uniform (consistent with [[RIT-A-0001]] hard-gate refusal). Include the offending paths in the machine-readable payload.
- Gate policy: `UNSUPPORTED` retains its current handling; only `CONTRADICTED` hard-refuses the commit (do not tighten UNSUPPORTED behavior in this task).
- Do NOT add per-item LLM calls; the recompute must run in the deterministic validator path only (NFR-001/NFR-002 of RIT-I-0016).

### Dependencies
- None blocking. RIT-I-0015 (the edit-session orchestrator this hardens) is already completed; this task is carried in RIT-I-0016 because 0016 is the first consumer that assembles many changes at once. Can start immediately.

### Risk Considerations
- Risk: recompute cost on large sessions. Mitigation: it is deterministic and runs once per commit over the already-assembled doc, not per change.
- Risk: divergence between the doc validated and the doc written. Mitigation: validate the exact `apply_diffs` output that is persisted (single assembly).
- Risk: over-refusing (flagging pre-existing `original` contradictions unrelated to the session). Mitigation: keep the gate's scope to the same CONTRADICTED semantics the existing gate uses; add a test asserting a clean session with no new contradictions still commits.

## Test Cases **[CONDITIONAL: Testing Task]**

### Test Case 1: Combination-only contradiction refused at commit
- **Test ID**: TC-001
- **Preconditions**: An edit session with two accepted `ChangeProposal`s, each seeded as `SUPPORTED` in `claim_provenance`, that together produce a `CONTRADICTED` claim in the assembled document.
- **Steps**:
  1. Build the session state with both changes accepted and provenance seeded SUPPORTED.
  2. Call `commit_session`.
  3. Inspect the raised hard-gate error payload.
- **Expected Results**: Commit is refused; error payload lists the offending path(s); no `standard`/version artifact is written.
- **Actual Results**: Implemented and passing — see `test_edit_session.py::test_assembled_truth_gate_refuses_combination_contradiction` (refused with `gate_code=truth_contradicted_assembled`, offending path `additional.technicalSkills[0]`, no artifact written) and `::test_assembled_truth_gate_allows_clean_session` (clean session commits, UNSUPPORTED not escalated).
- **Status**: Pass

### Test Case 2: Clean session still commits (backward compat) + CLI exit code
- **Test ID**: TC-002
- **Preconditions**: A session whose assembled document has no CONTRADICTED claims.
- **Steps**:
  1. Commit via facade — assert success and artifact written.
  2. Run a session with a combination contradiction through the CLI commit path.
- **Expected Results**: Clean session commits unchanged; contradicted session yields a non-zero CLI exit and the machine-readable error.
- **Actual Results**: Implemented and passing — see `test_edit_session.py::test_assembled_truth_gate_refuses_combination_contradiction` (refused with `gate_code=truth_contradicted_assembled`, offending path `additional.technicalSkills[0]`, no artifact written) and `::test_assembled_truth_gate_allows_clean_session` (clean session commits, UNSUPPORTED not escalated).
- **Status**: Pass
