# Extend check_ats_structure: job-independent structural ruleset + issue codes + fix affordances (reads ScoreDoc)

## Parent Initiative

[[RIT-I-0016]]

## Objective

Extend the existing deterministic, job-independent ATS structural check (`check_ats_structure` in `packages/ats/src/resume_kit_ats/engine.py`) with the fuller structural ruleset derived from the **job-INDEPENDENT slice** of the consolidated ATS dos/donts, and attach to every finding a **machine-readable issue code** plus a **fix affordance** flag (`deterministic-auto-safe` vs `needs-judgment`). These codes/affordances are the contract the `base` fixer (RIT-T-0115) consumes to decide what it may auto-apply versus defer.

This is an **enrich, don't rewrite** task: the existing deterministic `section_completeness` seed-score contract and the "deterministic seed, enriched recommendations" shape (per RIT-A-0003 / NFR-001) are preserved unchanged; new rules are added around them. All rule inputs are read from **ScoreDoc** — the canonical ATS view produced by RIT-I-0017's `project_scoredoc(BuildDoc) → ScoreDoc` (schema RIT-T-0105, projection RIT-T-0106) after the ats repoint (RIT-T-0108) — using its canonical sections / entities / zoned index. No rule may read raw BuildDoc fields (e.g. `additional.technicalSkills`) or perform hand-rolled section segmentation.

## Acceptance Criteria

Each rule below is table-driven and ships with at least **one positive (hit) fixture and one negative (clean) fixture**; each emitted finding carries a **stable issue code** and a **fix-affordance flag** (`deterministic-auto-safe` | `needs-judgment`).

- [ ] **Section naming & order** — Detects and codes (1a) non-conventional section names (e.g. "My Superpowers" for Skills) against the conventional-name table, and (1b) unexpected section order. Read from ScoreDoc canonical sections. Rename findings are `deterministic-auto-safe`; ambiguous/unknown sections are `needs-judgment`.
- [ ] **Entry separation** — Detects employer / title / location / date-range separation problems within experience entries (missing or fused fields) from ScoreDoc entities. Coded; affordance `needs-judgment` where the split is not unambiguous.
- [ ] **Date format presence AND consistency** — Detects (3a) missing dates, (3b) mixed formats across the document (month-vs-year, e.g. "Jan 2020" alongside "2020"), and (3c) a future graduation/certification date presented as completed. Coded; normalization to a single canonical format is `deterministic-auto-safe`, future-date-as-completed is `needs-judgment`.
- [ ] **Contact completeness AND prohibited PII** — Detects (4a) contact completeness gaps: name, phone, professional email, city+state, readable (non-masked) links; and (4b) prohibited PII: street address, DOB/age, marital status, SSN, and references / "references available on request". Completeness gaps are `needs-judgment` (user must supply the fact); PII stripping is `deterministic-auto-safe`.
- [ ] **Placeholder / template / leftover-AI-prompt scan** — Detects placeholder and template text (e.g. "[Your Name]", "Lorem ipsum", "Company Name Here") and leftover AI-prompt fragments (e.g. "As an AI language model", "Here is your resume"). Coded; removal of unambiguous placeholders is `deterministic-auto-safe`.
- [ ] **Extended `_FORMATTING_RISK_PATTERNS`** — Extends the existing `_FORMATTING_RISK_PATTERNS` (~line 338) with the visual-element donts that are detectable from parsed text (e.g. non-standard bullet glyphs, emoji, tab/pipe-column artifacts, symbol dividers). Each new pattern is coded; affordances assigned per pattern.
- [ ] **Seed-score contract unchanged** — A regression test proves the existing `section_completeness` seed score and its output shape are byte-for-byte unchanged for a fixture that predates this task (enrichment is purely additive).
- [ ] **Reads ScoreDoc only** — A test asserts the engine's structural rules consume ScoreDoc (sections/entities/zoned index) and no rule reads raw BuildDoc fields.
- [ ] **Deterministic / offline** — Every rule is deterministic and requires no network or LLM; identical input yields identical coded output across runs.

## Implementation Notes

### Technical Approach
- Build on `packages/ats/src/resume_kit_ats/engine.py`. Keep `check_ats_structure` (~line 514) as the entry point and preserve its resume-only / job-independent character and the `section_completeness` seed contract.
- Make the ruleset **table-driven**: a registry of `(code, detector, affordance)` entries so RIT-T-0115 can key its auto/defer decision off `code` + `affordance` rather than parsing prose. Each detector takes ScoreDoc and returns zero or more findings.
- Enrich the emitted report into an `AtsStructureReport` carrying per-issue `code` + `affordance` alongside the existing `section_completeness` + `recommendations`. `recommendations` stays populated for humans; codes/affordances are the machine channel.
- After RIT-I-0017's repoint (RIT-T-0108), `_extract_all_text` (~line 93) and the former `additional.technicalSkills` read (~line 213) source from ScoreDoc; author all new rules against ScoreDoc from the start so nothing is written against BuildDoc and reworked.
- Section canonicalization decisions here feed RIT-I-0017's `customSections → KeywordZone` mapping (RIT-T-0106) — keep the conventional-name table the single source of truth so projection and normalization agree.
- Adopt the initiative's severity taxonomy (hard-gate / warning / recommendation / review-note / out-of-scope-future) for finding severity; the code+affordance pair is orthogonal to severity.

### Dependencies
- **Blocked by RIT-T-0106** (ScoreDoc projection) and **RIT-T-0108** (ats repoint onto ScoreDoc) — must land first so new rules are authored against ScoreDoc, never BuildDoc.
- Consumed by **RIT-T-0115** (the `base` fix driver), which acts on these codes + affordances.

### Risk Considerations
- Authoring rules before the repoint would force a costly rewrite from BuildDoc to ScoreDoc — mitigated by the `blocked_by` ordering.
- Mis-tagging a `needs-judgment` fix as `deterministic-auto-safe` could let RIT-T-0115 auto-apply a meaning-altering change — mitigated by conservative default (unknown ⇒ `needs-judgment`) and per-affordance tests.
- Accidental drift in the seed score — mitigated by the dedicated unchanged-seed regression test.

## Verification

- Table-driven unit tests per rule under `packages/ats/tests`, each with a positive (hit) and a negative (clean) fixture, asserting the emitted issue code and affordance flag.
- A regression test asserting the `section_completeness` seed score / output shape is unchanged from a pre-task fixture.
- A test asserting rules read ScoreDoc (sections/entities/zoned index) and no rule reads raw BuildDoc fields.
- A determinism test: same input → identical coded output across repeated runs, no network/LLM.
