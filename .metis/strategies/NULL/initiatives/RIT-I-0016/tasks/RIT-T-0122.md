# Bounded source-file (PDF/DOCX) layout parse-risk detector into the base structural report (REQ-011, conditional)

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0016]]

## Objective **[REQUIRED]**

Add a **bounded, ingest-time source-file (PDF/DOCX) layout parse-risk detector** whose findings surface as **WARNING-severity** items in the `base` structural report. The current structural engine (RIT-T-0115 and prior) operates on parsed JSON plus a text scan and **structurally cannot see** the source file's columns, tables, text boxes, header/footer content, or image-only/scanned pages. This task adds a small detector that inspects the source PDF/DOCX at the ingest/extract boundary and emits warnings for parse-risk layouts. It is the "render-catching gap" that RIT-A-0002 and RIT-I-0018 explicitly defer here (REQ-011). It is **CONDITIONAL and scoped small**: if analysis shows any single detector is large/complex, that detector is documented and **deferred to a follow-on initiative** rather than expanded within this task.

**Conditional note**: This task is deliberately bounded. It never becomes a full document-renderer re-implementation. If the work balloons, the cut line is recorded here and the excess is split out to a follow-on initiative — expanding this initiative is out of scope.

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [x] At ingest, a **bounded detector inspects the source PDF/DOCX** (not the parsed JSON) and flags each of: (a) multi-column layout, (b) tables used to hold resume content, (c) text boxes, (d) header/footer content, and (e) image-only / scanned pages (no extractable text layer).
- [x] Each finding surfaces as a **WARNING-severity item** in the `base` structural report, using the RIT-T-0116 severity taxonomy. **No finding is ever a hard gate** — warnings never block writing `base`.
- [x] The detector is **deterministic and bounded**: for a fixed source file it produces the same findings, and it does **not** re-implement a document renderer or perform full layout reconstruction.
- [x] Detection runs at the **ingest/extract boundary** where the source file is read, and reads the source bytes/structure — it does not attempt to infer layout from the already-parsed JSON.
- [x] If, during implementation, any single detector (e.g. multi-column or table-content detection) proves large/complex, it is **documented and deferred to a follow-on initiative**, and this task **records the cut line** (which detectors shipped, which were deferred and why) in its Status Updates.

## Documentation Sections **[CONDITIONAL: Documentation Task]**

### User Guide Content
- **Feature Description**: At ingest, resume-kit inspects the actual source file (PDF/DOCX) for layouts that commonly break ATS parsing — multiple columns, content in tables, text boxes, header/footer content, and scanned/image-only pages — and warns about them in the `base` report.
- **Prerequisites**: The `base` structural report exists (RIT-T-0115) and the RIT-T-0116 severity taxonomy is in place.
- **Step-by-Step Instructions**:
  1. Provide a resume; ingest reads the source file.
  2. Review the `base` structural report for parse-risk WARNINGS.
  3. Fix the layout in your source document (warnings are advisory, not blocking).

### Troubleshooting Guide
- **A parse-risk warning appears but the resume parsed fine**: warnings are advisory signals of common ATS-parser hazards, not hard failures; the user may proceed.
- **Error Messages**: These are WARNING items, never gate/blocking errors — a blocking behavior here is a regression.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Inspect at the ingest/extract boundary — where source files are read — rather than at the JSON layer. Use bounded, well-scoped inspection: cheap structural signals from the PDF/DOCX (e.g. presence of table objects, text-box/shape objects, header/footer streams, column geometry heuristics, and absence of a text layer indicating a scanned page). Keep each detector minimal and deterministic; emit WARNING items into the existing `base` structural report via the RIT-T-0116 taxonomy. Do **not** build a renderer or reconstruct full layout. If a single detector needs disproportionate effort, ship the cheap ones and defer the expensive one to a follow-on initiative, recording the decision.

### Dependencies
- **Blocked by [[RIT-T-0115]]**: extends the `base` structural report produced there.
- Consumes the RIT-T-0116 severity taxonomy (WARNING severity).
- References REQ-011 ownership deferred here by RIT-A-0002 and RIT-I-0018.

### Risk Considerations
- **Scope balloon** — a detector (esp. multi-column/table-content) turning into layout reconstruction. Mitigation: the conditional cut-line clause; defer to a follow-on initiative.
- **False positives** — over-flagging clean resumes. Mitigation: TC-002 clean-fixture assertion; conservative heuristics.
- **Accidental hard gate** — a warning wired as blocking. Mitigation: explicit "never a hard gate" criterion and TC-001 assertion that `base` still writes.

## Status Updates **[REQUIRED]**

### 2026-08-06 — Design locked; implementation in progress

**Architecture decided:**
- New detector module `packages/ats/src/resume_kit_ats/parse_risk.py`:
  `detect_source_parse_risks(content: bytes, filename: str) -> list[AtsStructureFinding]`.
  Reads SOURCE bytes (not JSON), deterministic, never raises (returns `[]` on parse failure),
  no renderer/layout reconstruction. Each finding: `severity=WARNING`, `fix_affordance=NEEDS_JUDGMENT`.
- Wired into `build_base` (`packages/facade/src/resume_kit_facade/baseline.py`): after
  `check_ats_structure(original)`, read `config.active_resume_source` (if PDF/DOCX + exists),
  run the detector, merge risk findings into a new (frozen) `AtsStructureReport`, and feed that to
  `apply_auto_fixes`. Because findings are `needs_judgment`, they land in `BuildBaseResult.deferred`
  and never gate — `base` still writes. Claim-preservation gate unaffected (findings don't mutate the doc).

**Cut line (conditional scope-split exercised):**
- **SHIPPED** — DOCX (via python-docx, cheap XML inspection): tables (`SOURCE_LAYOUT_TABLE`),
  text boxes (`SOURCE_LAYOUT_TEXTBOX`, `txbxContent` in body XML), header/footer content
  (`SOURCE_LAYOUT_HEADER_FOOTER`), multi-column (`SOURCE_LAYOUT_MULTICOLUMN`, `w:cols w:num>1`);
  and PDF **image-only / no text layer** (`SOURCE_LAYOUT_IMAGE_ONLY`, empty deterministic extraction).
- **DEFERRED to a follow-on initiative** — PDF multi-column, PDF table-content, and PDF text-box
  geometry detection: these require layout reconstruction, out of this bounded task's scope.

### 2026-08-06 — Implemented, verified, complete

**Architecture correction during review:** the first cut placed the detector in `packages/ats` and imported
`python-docx`, which **violated the render-lib boundary** (REQ-604/NFR-602: `reportlab`/`docx` are confined to
`packages/export`) — caught by `tests/boundary/test_interface_boundaries.py`. Fixed properly (not by loosening
the rule): the detector now lives in **`packages/document-parser`** (`parse_risk.py`) — which already owns
extraction — and inspects DOCX via the **standard-library `zipfile` + light XML string scan** (a `.docx` is a
zip of WordprocessingML parts), so no `python-docx` import leaks into an engine package. The PDF image-only path
reuses this package's own `extract_resume_text`. The `ats` package and its pyproject were reverted to untouched.

**Final shape:**
- `packages/document-parser/src/resume_kit_document_parser/parse_risk.py` — `detect_source_parse_risks(content, filename)`:
  DOCX (zipfile): tables (`<w:tbl>`), text boxes (`txbxContent`), header/footer real text (`word/header*|footer*.xml`
  with a non-empty `<w:t>` run), multi-column (`<w:cols w:num="N">`, N>1); PDF: image-only (`SOURCE_LAYOUT_IMAGE_ONLY`,
  empty deterministic extraction). Codes: `SOURCE_LAYOUT_{TABLE,TEXTBOX,HEADER_FOOTER,MULTICOLUMN,IMAGE_ONLY}`.
  All findings `severity=WARNING`, `fix_affordance=NEEDS_JUDGMENT`, ≤1 per code. Never raises → `[]` on any fault.
  Exported from the `resume_kit_document_parser` package `__init__`.
- `build_base` (facade) merges the risk findings (resolved from `config.active_resume_source`, PDF/DOCX + exists)
  into a new frozen `AtsStructureReport` before `apply_auto_fixes`; they flow to `BuildBaseResult.deferred` and
  **never gate** — `base` still writes; claim-preservation gate unaffected.

**Cut line (conditional scope-split exercised):**
- **SHIPPED** — all four DOCX detectors + PDF image-only.
- **DEFERRED to a follow-on initiative** — PDF multi-column, PDF table-content, PDF text-box geometry (require
  layout reconstruction; out of this bounded task's scope). Recorded in the `parse_risk.py` module docstring.
