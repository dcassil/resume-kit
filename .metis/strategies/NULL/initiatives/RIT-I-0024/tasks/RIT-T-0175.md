# T1: Wire page-budget gate into export + override contract

## Parent Initiative **[REQUIRED]**

[[RIT-I-0024]]

## Objective **[REQUIRED]**

Make the rendered `max_pages` gate a real, enforced hard gate on export. Today `finalize-resume` claims
export enforces it, but the facade `export_resume` capability renders directly and never calls the page
budget check that already exists in `packages/export`. Wire it in across facade/CLI/MCP/API, fail
closed, and add an explicit, auditable override.

## Acceptance Criteria **[REQUIRED]**

- [ ] `export_resume` (facade `capabilities.py`) invokes the existing page-budget check
      (`packages/export/.../page_gate.py`, `check_page_budget`) against the rendered document.
- [ ] When the rendered resume exceeds `max_pages` and no override is set, export FAILS CLOSED: a failed
      result/report and a non-zero CLI exit (mirroring existing hard-gate exit behavior).
- [ ] An explicit override (`allow_over_length` request field + `--allow-over-length` CLI flag + MCP/API
      param), default false, permits an intentional over-length export and RECORDS the override in the
      result so it is auditable.
- [ ] The failure path is consistent across direct/CLI/MCP/API (surface parity).
- [ ] The `finalize-resume` skill doc's page-gate claim is now truthful (no doc change required beyond
      confirming accuracy; adjust wording only if needed).
- [ ] Regression test: an over-length fixture fails export before override and succeeds with override.

## Implementation Notes **[REQUIRED]**

### Technical Approach
- Reuse `check_page_budget` from `packages/export`; do NOT reimplement page counting.
- Resolve the shape policy (`load_shape_policy`) to get `max_pages`, as the perfect/fit path already
  does; render, then gate.
- Return the failure the same way other hard gates do (failed report → CLI non-zero via the existing
  `_run_gate`/exit-code plumbing).
- Add the override field to the export request model and thread it through CLI/MCP/API.
- Add a `SurfaceCase` (or extend the export case) in `tests/interface/test_surface_parity.py`.

### Dependencies
- [[RIT-I-0021]] `check_page_budget` module.
- Existing export capability + CLI/MCP/API export surfaces.

### Risk Considerations
- Do NOT change the renderer output; only gate around it.
- Ensure the override is recorded (auditable), not silent.
- Keep default fail-closed so the doc claim holds by default.

### Recommended Agent
`opus + medium` — cross-surface behavior change on the export hard-gate path with parity tests.
