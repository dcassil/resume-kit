# T2: Realize no-custom Flow 1 output (OMIT policy + dedupe skills)

## Parent Initiative **[REQUIRED]**

[[RIT-I-0024]]

## Objective **[REQUIRED]**

Make Flow 1's "no-custom, no duplicate Skills section" premise actually take effect. RIT-T-0169 added
`CustomHandoffPolicy.OMIT_AND_LEDGER_TO_EVIDENCE` and `handoff_custom_section_to_evidence()`, but the
default is `PRESERVE_IN_CANONICAL_CUSTOM` and the Flow 1 `build-structure` path never passes OMIT.
`parse-resume` also still tells agents to write skills into BOTH `additional.technicalSkills` and
`customSections`, causing a duplicate Skills section and inflated page count.

## Acceptance Criteria **[REQUIRED]**

- [ ] The Flow 1 `build-structure` path passes `OMIT_AND_LEDGER_TO_EVIDENCE` to
      `apply_shape_transforms(...)` so the prepared artifact omits canonical custom sections.
- [ ] Non-Flow-1 callers keep the `PRESERVE_IN_CANONICAL_CUSTOM` default (no behavior change elsewhere).
- [ ] The content ledger records the omitted content as `PRESERVED_IN_EVIDENCE`; `content_ledger_ok`
      still holds (nothing silently dropped).
- [ ] `parse-resume` guidance no longer double-writes skills; one canonical representation is chosen
      (flat `additional.technicalSkills` for ATS, categories rendered from a single source — not a
      duplicate `customSections` block).
- [ ] If any capability materializes both, it dedupes before render.
- [ ] Fixture test: the exported Flow 1 prepared resume has exactly ONE Skills section and no custom
      holding section; omitted custom content is present in learning/evidence.

## Implementation Notes **[REQUIRED]**

### Technical Approach
- Thread the policy through the Flow 1 builder (`resume_kit_facade` baseline → `apply_shape_transforms`);
  gate the OMIT on the Flow 1 / prepare-base-resume caller so other structure builds are unaffected.
- Verify `handoff_custom_section_to_evidence` ledger rows appear and `content_ledger_ok` passes.
- For skills dedupe: pick the canonical source; update `parse-resume/SKILL.md`; if a build/export path
  can still produce duplicates, dedupe deterministically before render.

### Dependencies
- [[RIT-I-0023]] RIT-T-0169 OMIT policy + evidence handoff.
- [[RIT-I-0019]] shape pass + content ledger.

### Risk Considerations
- Do NOT drop ambiguous content to satisfy no-custom — it must be ledgered into evidence.
- Do NOT flip the global default policy; scope OMIT to the Flow 1 path.

### Recommended Agent
`opus + medium` — touches the shape/ledger handoff and the parse→render skills representation.
