# Seed aliases.json curated lexicon + format doc + loader tests

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0008]]

## Objective **[REQUIRED]**

Author the curated **alias lexicon** shipped as versioned package data (`aliases.json`) in
`resume-kit-terms`, plus a short format doc and loader/round-trip tests. This is the true-synonym layer
that stemming cannot bridge — canonical-skill → alias set. Seed it with the high-frequency tech
vocabulary surfaced by the real ATS run and common knowledge:

- k8s ↔ Kubernetes, JS ↔ JavaScript, TS ↔ TypeScript, Node ↔ Node.js ↔ NodeJS,
  Postgres ↔ PostgreSQL ↔ Postgresql, RLS ↔ row-level security, CI/CD ↔ continuous integration /
  continuous delivery, GH Actions ↔ GitHub Actions, Go ↔ Golang, etc.

The lexicon format must be **append-only and extensible** — RIT-I-0009 (agent-grown index) appends to
the same file/format without schema change.

      different canonicals (deterministic, unambiguous).
- [ ] `mypy --strict` + `ruff` clean; new tests green; full suite stays green.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + low` — Small task touching a data file, a format doc, and a test file. Design (format + loader)
is already fixed by RIT-T-0062; the work is curating the seed set correctly and proving it loads. Low
cross-file invariant surface, but judgment is needed on which synonyms are genuinely safe (no
over-matching) so not `sonnet`.

### Technical Approach
- Follow the loader contract and default path constant established in RIT-T-0062 exactly.
- Store canonicals in their normalized form OR document that the loader normalizes on load — pick one
  and be consistent (recommended: store human-readable, normalize on load, so the file stays readable
  and RIT-I-0009 appends readable entries).
- Only include synonyms that are genuinely unambiguous and safe; when in doubt, leave it out (the
  anti-over-match guards in RIT-T-0066 will catch bad entries, but prefer not to add them).

### Dependencies
- Depends on: RIT-T-0062 (loader, default path, `AliasIndex` API).
- Blocks: RIT-T-0064/0065 (they rely on real aliases to prove synonym hits), RIT-T-0066 (integration).

### Risk Considerations
- **Ambiguous aliases** (an alias mapping to two canonicals) would make matching non-deterministic —
  the dedup/uniqueness test guards this.
- **Over-broad synonyms** (e.g. treating "Java" as an alias of "JavaScript") — explicitly excluded;
  the anti-over-match guards protect this but curation should not introduce them.

### Verification Steps
1. `uv run pytest packages/terms` — loader/round-trip/uniqueness tests green.
2. `uv run ruff check packages/terms && uv run mypy packages/terms/src` clean.
3. `uv run pytest` — full suite green.

## Status Updates **[REQUIRED]**

**2026-08-04 — COMPLETE.** Authored the seed lexicon + format doc + tests:
- `data/aliases.json` (`version: 1`) with 27 curated groups: k8s/Kubernetes, JS+ECMAScript/JavaScript,
  TS/TypeScript, Node+nodejs/Node.js, Postgres/PostgreSQL, Mongo/MongoDB, RLS/row-level security,
  CI/continuous integration, CD+continuous deployment/continuous delivery, cicd/CI/CD, GH Actions/GitHub
  Actions, go/Golang, AWS/Amazon Web Services, GCP+google cloud/Google Cloud Platform, azure/Microsoft
  Azure, IaC, ML, AI, NLP, UI, UX, TDD, OOP, CLI, API, **mentorship/mentoring** (the derivational bridge
  from RIT-T-0062), **ESLint/linting** (tool↔activity).
- `data/FORMAT.md` — documents the schema, the stemming-vs-alias boundary, the four load-time rules
  (append-only, no-ambiguous-alias, no-empty-normalization, conservative curation), and exactly how
  RIT-I-0009 appends to the same format.
- `test_seed_lexicon.py` — 20 tests: real-file round-trip/unambiguity, 13 target-synonym bridges
  (incl. mentorship↔mentoring, ESLint↔linting), 4 anti-over-match guards (Java≠JavaScript, React≠Vue,
  Go≠Golfing, Python≠PyTorch), and the merged continuous-delivery/deployment group.

**Design note surfaced during authoring:** `cd` was initially ambiguous (continuous delivery vs
deployment) — the RIT-T-0062 dedup guard correctly rejects that. Resolved by merging both into one group
(`"continuous delivery": ["cd", "continuous deployment"]`), documented as the canonical resolution
pattern in FORMAT.md rule 2. This validates the guard end-to-end.

**Gate:** `ruff` + `mypy --strict` clean; full suite **2497 passed, 1 skipped** (was 2478). No
regressions. The seed is now live at the default lexicon path, ready for RIT-T-0064/0065 to prove
alias hits and RIT-T-0067 to ship in the wheel.
