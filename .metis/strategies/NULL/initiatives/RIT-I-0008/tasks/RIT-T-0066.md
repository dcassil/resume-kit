# Integration test on resume-d/Staff-FS + anti-over-match guards

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0008]]

## Objective **[REQUIRED]**

Prove the initiative's exit criteria end-to-end with an integration test on the real `resume-d` vs
Staff Full-Stack fixture, and lock in **anti-over-match guards** so synonym awareness cannot silently
start producing false positives.

This is the "honest score" verification: the specific real-world misses now match, true gaps and
unrelated terms still do NOT, and the composite ATS score moves in the right direction deterministically.

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] Integration test using the real `resume-d` + Staff-FS `JobDescription` fixture asserts:
      `analyze_keyword_gaps` no longer lists `mentorship`/`linting` as gaps; `skills_coverage` and
      `keyword_match` rise vs the pre-synonym baseline; results are deterministic across runs.
- [ ] Anti-over-match guard tests: `React ≠ Vue`; a truly-absent `Kubernetes` stays a gap; `Java` is not
      collapsed into `JavaScript`; distinct skills are not merged by aggressive stemming.
- [ ] Match `kind` is asserted end-to-end: a stem hit reports `stem`, an alias hit reports
      `alias:<canonical>`, an exact hit reports `exact`.
- [ ] Cross-package consistency test: for the same term pair, `matching` and `ats` agree on match +
      kind (no divergence).
- [ ] `mypy --strict` + `ruff` clean; full suite green (2356+ existing tests still pass).

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + medium` — Integration/verification reasoning across both rewired packages and the real fixture,
including judgment on what score movement is "correct" and which over-match guards matter. Not core
architecture, but needs good cross-context reasoning, so medium.

### Technical Approach
- Locate/reuse the existing `resume-d` and Staff-FS fixtures already referenced by the ATS run that
  motivated the initiative (search `tests/` and package fixture dirs); do not fabricate new resume data.
- Capture a pre-change baseline conceptually (the initiative cites `skills_coverage` 89.1 with false
  gaps) and assert the post-change direction (fewer gaps, coverage up), avoiding brittle exact-number
  asserts where the seed lexicon could evolve — assert the specific gap removals + monotonic direction.
- Put anti-over-match guards as focused unit-level assertions so a bad future alias entry fails fast.

### Dependencies
- Depends on: RIT-T-0064 (matching rewire) AND RIT-T-0065 (ats rewire) — this is the join point after
  both parallel rewires land.
- Blocks: RIT-T-0067 (packaging) can proceed independently; initiative exit needs this green.

### Risk Considerations
- **Brittle numeric assertions**: pin behavior (gap present/absent, kind) rather than exact float scores
  that the lexicon could shift.
- **Fixture drift**: reuse canonical fixtures; if the motivating fixture isn't checked in, add a minimal
  representative one and note it.
- **False confidence**: ensure the guard tests would actually FAIL if over-matching were introduced
  (verify by temporarily loosening — mentally or in a scratch run — then revert).

### Verification Steps
1. `uv run pytest tests -k "synonym or over_match or resume_d"` (new integration/guard tests) green.
2. `uv run ruff check packages tests && uv run mypy packages` clean.
3. `uv run pytest` — full suite green.
