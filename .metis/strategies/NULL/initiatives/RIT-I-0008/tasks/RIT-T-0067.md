# Wire resume-kit-terms into umbrella wheel + snowball dep + attribution

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0008]]

## Objective **[REQUIRED]**

Make the new `resume-kit-terms` package ship correctly in the published umbrella `resume-kit` PyPI
wheel, add its one external runtime dependency (`snowballstemmer`) at the umbrella level, ensure the
`aliases.json` data file is included in the built wheel, and add license attribution.

Context (verified): the umbrella `resume-kit` wheel (root `pyproject.toml`) **vendors** every package's
source tree via `[tool.hatch.build.targets.wheel.force-include]` and does NOT emit internal
`resume-kit-*` Requires-Dist — so external deps of any vendored package must be surfaced in the root
`dependencies`. `snowballstemmer` is currently absent from `uv.lock`.

## Acceptance Criteria **[REQUIRED]**

- [ ] Root `pyproject.toml` `[tool.hatch.build.targets.wheel.force-include]` adds
      `"packages/terms/src/resume_kit_terms" = "resume_kit_terms"`.
- [ ] Root `dependencies` adds `snowballstemmer>=2.2` (external dep of the vendored `terms` package),
      and `uv.lock` resolves it.
- [ ] `aliases.json` is included in the built wheel (force-include maps whole dirs, so confirm the data
      file lives under `packages/terms/src/resume_kit_terms/` and is picked up; verify via a built-wheel
      inspection, e.g. `python -m zipfile -l dist/*.whl | grep aliases.json`).
- [ ] `NOTICE`/attribution updated for `snowballstemmer` (BSD-3) as required by the existing attribution
      convention in the repo.
- [ ] A build smoke check passes: `uv build` (or the repo's build command) produces a wheel that
      imports `resume_kit_terms`, loads the lexicon, and runs `match()` — confirming the vendored module
      + data resolve at runtime from the umbrella wheel.
- [ ] `ruff` + `mypy --strict` clean; full suite green.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`sonnet + medium` — Mechanical packaging edits following the exact established vendoring pattern (14
existing force-include entries to copy), plus a build smoke check. All reasoning is fixed; the work is
careful, single-file config edits + verification. Not `haiku` because the wheel-inclusion verification
and NOTICE convention need a little judgment.

### Technical Approach
- Copy the existing force-include line pattern for the 14 vendored packages; add the `terms` entry in
  the same alphabetical/logical position.
- Add `snowballstemmer>=2.2` to root `dependencies` (NOT optional-extras — it's always needed by the
  synonym-aware engine).
- Ensure the data file path chosen in RIT-T-0062/0063 is INSIDE the vendored `resume_kit_terms/` tree so
  force-include (whole-dir map) carries it; if package-data globbing is used anywhere, mirror it.
- Follow the repo's existing NOTICE format for third-party attributions.

### Dependencies
- Depends on: RIT-T-0062 (package exists) and RIT-T-0063 (aliases.json exists at its final path).
- Independent of RIT-T-0064/0065/0066 (can run in parallel once 0062/0063 land), but the initiative's
  publish/exit should confirm all are green together.

### Risk Considerations
- **Data file silently missing from wheel**: whole-dir force-include should catch it, but the explicit
  built-wheel `zipfile -l | grep aliases.json` check is the guard — do not skip it.
- **Missing external dep in shipped metadata**: because internal deps are vendored (no Requires-Dist),
  forgetting `snowballstemmer` in root deps would make the published wheel import-fail at runtime —
  the build smoke import check guards this.
- **License compliance**: BSD-3 requires attribution; update NOTICE.

### Verification Steps
1. `uv sync --all-packages` resolves `snowballstemmer`.
2. `uv build` (repo build command) → `python -m zipfile -l dist/resume_kit-*.whl | grep -E "resume_kit_terms|aliases.json"` shows both.
3. Fresh-venv install of the built wheel: `python -c "from resume_kit_terms import match; print(match('k8s','Kubernetes'))"` works.
4. `uv run ruff check packages && uv run mypy packages && uv run pytest` green.
