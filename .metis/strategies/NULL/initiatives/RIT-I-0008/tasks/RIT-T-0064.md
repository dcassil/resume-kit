# Rewire matching to synonym-aware normalizer + thread match kind

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0008]]

## Objective **[REQUIRED]**

Rewire `packages/matching` to compare terms via the shared `resume-kit-terms` normalize+stem+alias
matcher, and thread the match **kind** (`exact` | `stem` | `alias:<canonical>`) through the keyword/gap
outputs so downstream (RIT-I-0010) can distinguish exact from synonym hits.

Concrete integration points (from the initiative):
- `keywords.py`: `_keyword_in_text` (:44), `_normalize_skill_key` (:58), `_extract_jd_skill_keys`,
  `calculate_keyword_match` (:196), `analyze_keyword_gaps` (:232).

After this task, `calculate_keyword_match`, `analyze_keyword_gaps`, and `check_job_match` reflect the
synonym-aware result: e.g. a JD keyword "mentorship" matches resume "mentoring" (stem), "k8s" matches
"Kubernetes" (alias), and `analyze_keyword_gaps` no longer reports those as missing (REQ-805).

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + medium` — Substantive multi-function rewire within one package that must preserve existing
behavior (characterization) while adding synonym awareness and threading a new annotation through
result structures. Fits a known pattern (shared normalizer defined in RIT-T-0062) but touches several
interlocking functions and a possible schema field.

### Technical Approach
- Build one `AliasIndex` instance at module load (or lazily-cached) and reuse it; do not reload per call.
- Replace whole-term casefold comparisons with `resume_kit_terms.match(...)`, capturing the returned
  `kind`. Where the code compares a JD key against many resume tokens, keep the first/highest-precedence
  match (exact > stem > alias).
- For the `kind` annotation: prefer adding an optional field to the existing keyword/gap result model in
  `resume-kit-schemas` (coordinate the field name with RIT-T-0065 so ats and matching agree); if a
  schema change is undesirable, carry it in the existing structure and document.
- Preserve public function signatures where possible; if a return shape must grow, keep it additive.

### Dependencies
- Depends on: RIT-T-0062 (normalizer/match API), RIT-T-0063 (real aliases to prove alias hits).
- File-disjoint from RIT-T-0065 (ats) — the two rewires can run in parallel; they must agree on the
  shared `kind` field name/shape (coordinate via the schema change).
- Blocks: RIT-T-0066 (integration test).

### Risk Considerations
- **Characterization drift**: existing tests encode current match behavior; run them first, understand
  any diffs, and only accept diffs that are genuine synonym improvements (not regressions).
- **Schema field coordination** with ats (RIT-T-0065): agree on one field name/shape to avoid divergence
  (the whole point of the initiative).
- **Performance**: precompile the alias index; matching is O(terms).

### Verification Steps
1. `uv run pytest packages/matching` — existing + new synonym tests green.
2. `uv run ruff check packages/matching && uv run mypy packages/matching/src` clean.
3. `uv run pytest` — full suite green.
