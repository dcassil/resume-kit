# Rewire ats keyword/skills_coverage paths to shared normalizer

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0008]]

## Objective **[REQUIRED]**

Rewire `packages/ats` keyword and skills-coverage paths to use the shared `resume-kit-terms`
normalize+stem+alias matcher, so `skills_coverage` and `keyword_match` agree with `matching` and become
synonym-aware and consistent (the core "no divergent matching between the two packages" guarantee).

Concrete integration points (from the initiative):
- `engine.py`: `_keyword_in_text` (:69), `_compute_skills_coverage` (:82). `compute_ats_score` weights
  keyword_match 0.55 / skills_coverage 0.25 / section_completeness 0.20 — both keyword paths must use
  the same normalization so the composite score is consistent.

After this task, the real-world case reproduces: on `resume-d` vs the Staff-FS posting, `skills_coverage`
rises appropriately (mentoring/linting/k8s no longer counted as absent) while remaining deterministic.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + medium` — Substantive rewire of the scoring engine's keyword paths that must stay consistent
with the `matching` rewire and preserve the composite-score weighting and determinism. Fewer functions
than RIT-T-0064 but higher blast radius (feeds `compute_ats_score`), so medium not low.

### Technical Approach
- Reuse a single module-level `AliasIndex` instance.
- Swap casefold/substring comparisons in `_keyword_in_text` / `_compute_skills_coverage` for
  `resume_kit_terms.match(...)`, capturing `kind`.
- Use the SAME `kind` field name/shape RIT-T-0064 introduces (coordinate; do not invent a second one).
- Do not alter the `compute_ats_score` weights — only the term-comparison substrate changes.

### Dependencies
- Depends on: RIT-T-0062 (normalizer/match API), RIT-T-0063 (aliases), and coordination with RIT-T-0064
  on the shared `kind` field shape.
- File-disjoint from RIT-T-0064 (matching) — can run in parallel.
- Blocks: RIT-T-0066 (integration test).

### Risk Considerations
- **Score divergence from `matching`** if a different normalization slips in — the whole initiative
  exists to prevent this; both must call the identical `resume-kit-terms` primitives.
- **Substring vs whole-term semantics**: `_compute_skills_coverage` may currently use substring
  containment; ensure the normalized/stemmed comparison preserves intended semantics without new
  over-matching (guarded by RIT-T-0066).
- **Determinism**: no set-ordering leakage into scores; sort where iteration order could matter.

### Verification Steps
1. `uv run pytest packages/ats` — existing + new synonym tests green.
2. `uv run ruff check packages/ats && uv run mypy packages/ats/src` clean.
3. `uv run pytest` — full suite green.
