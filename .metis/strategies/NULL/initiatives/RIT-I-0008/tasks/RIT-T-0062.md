# Scaffold resume-kit-terms package: normalize + AliasIndex + match

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0008]]

## Objective **[REQUIRED]**

Create the new workspace package **`resume-kit-terms`** (`packages/terms`) that is the single source
of truth for deterministic term normalization and synonym matching. It exposes three primitives that
both `matching` and `ats` will consume in later tasks:

- `normalize(term: str) -> str` — Unicode/ASCII fold → casefold → punctuation/whitespace normalize →
  Snowball stem, producing a canonical comparison form.
- `AliasIndex` — loads the curated alias lexicon (data file added in RIT-T-0063) and expands a term to
  its canonical + alias-canonical set; built once, precompiled for O(terms) lookup.
- `match(a: str, b: str) -> MatchResult` — returns whether two terms match and the **kind**
  (`exact` | `stem` | `alias:<canonical>`), the explainability primitive REQ-804 depends on.

This task establishes the package, its dependency wiring, the `snowballstemmer` dependency, the API
surface, and the loader mechanism (fed by the seed data in RIT-T-0063). It does NOT rewire `matching`
or `ats` (RIT-T-0064 / RIT-T-0065) and does not ship the full seed lexicon (RIT-T-0063 owns the data).

## Acceptance Criteria **[REQUIRED]**

- [ ] `packages/terms/` exists as a workspace member: `pyproject.toml` (name `resume-kit-terms`,
      dependencies `pydantic>=2`, `resume-kit-schemas`, `snowballstemmer>=2.2`), `py.typed`, wheel
      target `src/resume_kit_terms`, and is added to the root workspace members + `uv.lock` resolves.
- [ ] `normalize(term)` implements, in order: `unicodedata` NFKD ASCII-fold (so `·`, curly quotes,
      en/em dashes are neutralized), casefold, punctuation/whitespace collapse, Snowball English stem.
      Pure function, deterministic, O(len(term)).
- [ ] `AliasIndex` loads from a lexicon data path (default = package data file created in RIT-T-0063;
      an empty/minimal fixture is acceptable for THIS task's tests), builds a precompiled
      canonical→aliases and reverse alias→canonical index, and exposes `expand(term) -> set[str]` and
      `canonical_for(term) -> str | None` operating on normalized forms.
- [ ] `match(a, b) -> MatchResult` where `MatchResult` carries `matched: bool` and
      `kind: Literal["exact","stem","alias"] | None` plus `canonical: str | None` (populated for alias
      hits). `exact` = raw casefold-equal; `stem` = equal only after stemming; `alias` = equal only via
      the alias index. Precedence exact > stem > alias.
- [ ] `snowballstemmer` is confined to this package (no other package imports it directly).
- [ ] `mypy --strict` + `ruff` clean on `packages/terms`; unit tests for `normalize`, `AliasIndex`,
      and `match` pass; full existing suite stays green (no behavior change elsewhere yet).

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + high` — Core architecture task: it defines the package layout, the public API surface, and the
`MatchResult` contract that RIT-T-0063/0064/0065 all consume. A wrong shape here creates compounding
rework across the whole initiative.

### Technical Approach
- Model the package on existing members (`packages/ats`, `packages/core`) for `pyproject.toml`,
  `py.typed`, `[tool.uv.sources]` workspace wiring, and `[tool.hatch.build.targets.wheel]`.
- `resume_kit_terms/__init__.py` exports `normalize`, `AliasIndex`, `match`, `MatchResult`.
- Put stemming behind a tiny module-level cached `snowballstemmer.stemmer('english')` instance; do not
  re-instantiate per call.
- `MatchResult` as a frozen pydantic model (consistent with the codebase's pydantic-v2 convention).
- Define a stable lexicon file path constant + loader (`load_alias_lexicon(path=None)`), so RIT-T-0063
  drops in the real `aliases.json` at the default path without changing the loader.
- Keep `normalize` and the alias index acyclic and dependency-free beyond stdlib + snowballstemmer +
  schemas.

### Dependencies
- Blocks: RIT-T-0063 (seed lexicon uses the format/loader defined here), RIT-T-0064 (matching rewire),
  RIT-T-0065 (ats rewire), RIT-T-0067 (packaging).
- Depends on: none (first task of the initiative).

### Risk Considerations
- **Over-aggressive stemming collapsing distinct skills** (e.g. `architecture`/`architect` is fine, but
  guard against pairs the later anti-over-match tests care about). Keep stemming English-only and rely
  on the alias layer for true synonyms rather than looser stemming.
- **Dependency cycle**: `terms` must depend only on `schemas` (never `ats`/`matching`/`core`) to keep
  `schemas ← terms ← {ats, matching}` acyclic.
- **ASCII-fold data loss**: NFKD + encode/decode ascii ignore is lossy by design; unit-test that
  intended folds happen and that legitimate distinct tokens survive.

### Verification Steps
1. `uv sync --all-packages` resolves with the new package + `snowballstemmer`.
2. `uv run ruff check packages/terms && uv run mypy packages/terms/src` clean.
3. `uv run pytest packages/terms` (new unit tests) green.
4. `uv run pytest` — full suite still green (2356+ passing, no regressions).

## Status Updates **[REQUIRED]**

**2026-08-04 — COMPLETE.** Scaffolded `packages/terms` (`resume-kit-terms`):
- `pyproject.toml` (deps: `pydantic>=2`, `resume-kit-schemas`, `snowballstemmer>=2.2`), `py.typed`,
  wheel target `src/resume_kit_terms`. Auto-included via `packages/*` workspace glob; `uv.lock`
  resolves `snowballstemmer==3.1.1`.
- `normalize.py`: `normalize()` (ascii-fold → casefold → punct/space collapse → Snowball stem) +
  `surface_form()` (same, minus stemming) so `match` can distinguish exact from stem hits. Module-level
  cached English stemmer; `@lru_cache` on both.
- `aliases.py`: `AliasIndex` (bidirectional, precompiled, rejects ambiguous alias→two-canonicals at
  build time) + `load_alias_lexicon()` + `LexiconError`. Default path `data/aliases.json`.
- `match.py`: frozen pydantic `MatchResult` (`matched`, `kind` ∈ exact|stem|alias, `canonical`) +
  `match(a, b, alias_index=None)` with precedence exact > stem > alias.
- `data/aliases.json`: minimal placeholder (`Kubernetes: [k8s]`); full seed is RIT-T-0063.
- 34 unit tests (normalize/surface/aliases/match) green. Registered `terms` in the
  `test_known_packages_present` boundary guard.

**Two findings worth carrying forward (into RIT-T-0063):**
1. Snowball strips *inflectional* suffixes (`-ing`, `-ed`) but NOT *derivational* ones like `-ship`:
   `mentoring`↔`mentorship` does **not** collapse via stemming and MUST be an alias-lexicon entry.
   (The initiative lists it as a target case — it belongs in `aliases.json`, not the stemmer.)
2. Fold order matters: ascii-fold now strips combining marks (so `café`→`cafe`) and leaves
   non-decomposing punctuation (`·`, en/em dashes, curly quotes) for the punctuation regex to turn into
   separators — otherwise `Node·js` fused to `nodej`. Fixed + tested.

**Gate:** `ruff` + `mypy --strict` clean on `packages/terms`; full suite **2478 passed, 1 skipped**
(was 2356; +122 from new tests + package now importable). No regressions.

**Note for RIT-T-0064/0065:** `snowballstemmer` import carries `# type: ignore[import-untyped]` (repo
convention, matches reportlab in `packages/export`); it is confined to `resume_kit_terms.normalize`.
