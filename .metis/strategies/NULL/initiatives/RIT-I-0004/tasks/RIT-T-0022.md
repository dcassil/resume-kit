# Implement Explainable Job-Match Scoring

## Parent Initiative

[[RIT-I-0004]] — Phase 3 — Matching & Deterministic Analysis

## Objective

Build the deterministic resume-vs-job analysis engine that composes keyword matching, requirement coverage, evidence placement, and ATS scores into a reusable explainable report.

## Acceptance Criteria

- [ ] `resume_kit_matching.match` exposes `check_job_match(resume, job)` returning the new canonical job-match report schema.
- [ ] Scoring dimensions include keyword coverage, required requirement coverage, preferred requirement coverage, evidence strength/placement, ATS contribution, confidence, missing evidence, and recommendations.
- [ ] Tests prove keyword repetition alone does not increase score after first presence; support and placement drive additional credit.
- [ ] `packages/matching/pyproject.toml` explicitly depends on `resume-kit-ats`, and dependency direction remains acyclic: matching -> ats, ats -> schemas/core only.

## Implementation Notes

Recommended Agent: opus + medium. This is New scoring logic plus adaptation of the upstream match-scoring concept (`services/refiner.py:641` and web-coupled `routers/resumes.py:462` rebuilt, not imported). Use `resume_kit_matching.keywords` for whole-term presence, `resume_kit_ats.engine.compute_ats_score` for ATS contribution, and existing `JobDescription`/`RequirementKind`. Keep all scoring deterministic and explainable; never count repeated keyword occurrences as repeated evidence. Add modified-source marker only if code is materially adapted from upstream; otherwise mark as original.
