# Implement Resume Selection and Version Comparison

## Parent Initiative

[[RIT-I-0004]] — Phase 3 — Matching & Deterministic Analysis

## Objective

Add the deterministic engines behind future `select-best-resume` and `compare-resume-versions` interfaces using the job-match and ATS primitives already in place.

## Acceptance Criteria

- [ ] `select_best(resumes, job)` ranks multiple resume variants with stable tie-breaking and per-variant explanations.
- [ ] `compare_versions(base, candidate, job)` returns score deltas across ATS, keyword, and job-match dimensions.
- [ ] Tests cover ranking, ties, before/after improvements, regressions, and deterministic output ordering.
- [ ] Implementation reuses canonical schema result types from `resume_kit_schemas`; no local duplicate Pydantic result schemas.

## Implementation Notes

Recommended Agent: opus + medium. Build new deterministic logic in matching. Use `check_job_match`, `compute_ats_score`, and keyword gap/match helpers rather than reimplementing scoring. Treat resume identifiers as caller-provided labels or stable list positions; do not add persistence ids. This task is not upstream-derived except for the concept of before/after comparison from `services/ats.py:171` + `services/refiner.py:641`; add source markers only where code is adapted.
