# Plugin skills wiring the loop + integration test + registration

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0013]]

## Objective **[REQUIRED]**

Wire the deterministic preference-learning loop into the plugin: a suggest/rank skill (enumerate → RAG →
features → rank → present-with-explanation) and a feedback-logging skill (record outcome → update
preferences), plus an integration test proving the loop is reproducible for a fixed log. Human-in-loop,
gated, reusing the truth gate.

## Acceptance Criteria **[REQUIRED]**

- [ ] `plugins/resume-intelligence/skills/rank-edits/SKILL.md` (slug `rank-edits`, or a clearer verb-noun):
      ONE job — for a pending improvement, ENUMERATE truthful candidates from the existing improve skills
      (`inject-keywords`/`update-terminology` strategies), retrieve the Preference-RAG context
      (RIT-T-0086), extract features + RANK (RIT-T-0087), and PRESENT the top candidate(s) WITH the
      explanation. Human-in-loop: it presents, the user chooses; it never silently applies. Prerequisites
      gate (resume + job JSON + candidates). Honors `alias_file`.
- [ ] `plugins/resume-intelligence/skills/log-edit-feedback/SKILL.md` (slug `log-edit-feedback`): ONE job —
      record the user's outcome (accepted / accepted_modified / rejected / undone, + optional reason + the
      term diff) to `resume-kit/learning/edit-feedback.jsonl` (RIT-T-0085 log), store the `PreferencePair`,
      and refresh `resume-kit/learning/preferences.json` (RIT-T-0086). Gate on an in-flight suggestion.
- [ ] Both skills reference the working-dir convention + `_shared/prerequisites.md`, mirror sibling
      frontmatter, and are workflow/agent-driven (EXEMPT from the `EXPECTED_CLI_OR_MCP` mapping like
      `manage-synonyms`/`resume-workflow`). Register both in `EXPECTED_SKILL_SLUGS`.
- [ ] `resume-workflow` guide updated: reference the rank/feedback loop as an OPTIONAL part of the Improve
      phase (rank candidates → apply chosen via the truth-gated improve skills → log the outcome), clearly
      optional; the flow still reads if skipped.
- [ ] README capability map + Workflow section updated; plugin version bumped.
- [ ] Integration test (`tests/integration/`): drive the loop over a FIXED synthetic feedback log —
      derive preferences, retrieve context, rank a small candidate set, log an outcome, re-derive — and
      assert reproducibility (identical ranking/reasons/preferences on two runs) + the truth hard-block
      (a fabricated candidate never ranks) + that logging an outcome updates preferences deterministically.
- [ ] `claude plugin validate` passes; plugin skill suite + full `uv run pytest` green; `ruff` +
      `mypy --strict` clean.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + medium` — Skill markdown + an integration test wiring the RIT-T-0085/0086/0087 pieces end-to-end;
the loop wiring + human-in-loop + reproducibility assertions matter, but the hard logic is in the prior
tasks. Medium.

### Technical Approach
- Read the landed `resume_kit_feedback` public API (log, derive_preferences, retrieval, features, ranker)
  + sibling skills (`inject-keywords`, `update-terminology`, `manage-synonyms`, `resume-workflow`) for
  conventions.
- The rank skill orchestrates: candidates (from the improve skills) → RAG context → features → rank →
  present + explanation. The log skill records outcome → preferences. Keep them single-purpose + gated.
- Integration test mirrors `tests/integration/test_*_integration.py` style; use a fixed log + fixed `now`
  for determinism; assert truth hard-block + reproducibility.

### Dependencies
- Depends on: RIT-T-0085, 0086, 0087 (all must land). This is the initiative exit + wiring.
- Orchestrator will have reconciled `packages/feedback/__init__.py` exports (+ pyproject deps) from the
  parallel 0086/0087 before this runs.

### Risk Considerations
- **Silent apply**: the rank skill presents; application stays with the truth-gated improve skills the user
  chooses — never auto-apply.
- **Reproducibility**: integration test must fix the log + `now`.
- **Slug/README/version reconciliation**: register both new slugs (exempt) + update README + bump version.
