# Preference memory derivation + Preference-RAG retrieval

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0013]]

## Objective **[REQUIRED]**

Turn the raw edit-feedback log into (a) a derived `UserPreferenceProfile` with confidence + decay, and
(b) deterministic Preference-RAG retrieval that surfaces the most relevant past outcomes + preferences for
a given edit context. Both live in `resume_kit_feedback`, deterministic + offline.

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `derive_preferences(records, *, now, base_path=None) -> UserPreferenceProfile` (module e.g.
      `preferences.py`): deterministically aggregates the log into preferred tone/length/edit-strength,
      accepted_phrases, rejected_phrases, disliked_patterns, max_length_growth, etc. Applies CONFIDENCE
      thresholds (≈1 weak / ≈3 moderate / ≈7+ strong — document exact rule) so a single action never sets a
      preference, and EXPONENTIAL time DECAY of older signals (decay based on the record timestamps vs the
      passed `now`; `now` is an input, not a call to the clock — determinism). Persist to
      `resume-kit/learning/preferences.json` (human-readable, prunable). Reproducible for a fixed log+now.
- [ ] `undone` outcomes weigh as STRONGER negative than immediate `rejected` (REQ-1306 alignment); document
      the weighting.
- [ ] Preference-RAG (module e.g. `retrieval.py`): `retrieve_preference_context(context, records,
      profile, *, k) -> PreferenceContext` where `context` describes the pending edit (section, target
      terms, edit_type, aggressiveness). Scores past records by DETERMINISTIC similarity — section match +
      target-term overlap + edit_type match + aggressiveness-bucket closeness — returns the top-K relevant
      accepted/rejected edits + the relevant preference summary as a COMPACT, injectable context block
      (the improve skills will paste it). NO embeddings, NO model, NO network.
- [ ] Determinism (NFR-1301): fixed inputs → identical profile, identical retrieval + ordering (stable
      tie-breaks). Empty/малformed log tolerated (empty profile / empty context, no crash).
- [ ] Export the new public functions from `resume_kit_feedback` (coordinate `__init__` with the
      orchestrator — see Dependencies). Tests: threshold tiers, decay ordering, undone-vs-rejected
      weighting, retrieval relevance + top-K + determinism, empty-log behavior. `ruff` + `mypy --strict`
      clean; full suite green.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + high` — The confidence/decay math + deterministic retrieval scoring are the learning core; a wrong
decay or nondeterministic tie-break undermines the whole premise (reproducibility). Reuses RIT-T-0085
schemas + log; substantive deterministic logic.

### Technical Approach
- Read RIT-T-0085's `EditFeedback`/`UserPreferenceProfile`/log I/O first. Build `preferences.py` +
  `retrieval.py` as separate modules.
- Confidence: count corroborating signals per phrase/pattern; map counts→tiers with a documented rule.
  Decay: weight each signal by `exp(-lambda * age)` (age from record.timestamp vs `now`), document lambda.
- Retrieval similarity: a transparent additive score over (section==, term-overlap ratio, edit_type==,
  aggressiveness bucket distance); sort desc with a stable secondary key (e.g. recency then edit_id).
- Pure/deterministic: `now` and timestamps are DATA passed in; no clock/random.

### Dependencies
- Depends on: RIT-T-0085 (schemas + log I/O). Parallel-safe with RIT-T-0087 (different modules —
  preferences.py/retrieval.py vs features.py/ranker.py) PROVIDED you do NOT edit
  `packages/feedback/src/resume_kit_feedback/__init__.py` (the orchestrator wires all new exports at the
  wave gate to avoid a collision with RIT-T-0087). Export intent: list your new public symbols in your
  report so the orchestrator adds them.
- Blocks: RIT-T-0088 (skills consume preferences + RAG).

### Risk Considerations
- **Nondeterminism**: no clock/random; stable sort tie-breaks; `now` as input.
- **Over-eager learning**: enforce confidence thresholds; single action = weak/no preference.
- **__init__ collision** with the parallel RIT-T-0087: do NOT edit `__init__.py`; report exports instead.
