# CandidateFeatures extraction + pluggable heuristic ranker (truth hard-block)

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0013]]

## Objective **[REQUIRED]**

Given candidate edits, extract deterministic `CandidateFeatures` (reusing existing scorers + the truth
gate) and rank them with an explainable, pluggable heuristic ranker — unsupported claims hard-blocked.
Lives in `resume_kit_feedback`, deterministic + offline.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] Feature extraction (module e.g. `features.py`): `extract_features(candidate, context, *, profile)
      -> CandidateFeatures` computing — ATS/keyword gain (via `resume_kit_ats` / `resume_kit_matching`
      scorers), unsupported_claim_risk (via `resume_kit_evidence.validate_resume_truth`), voice/preference
      match (against the `UserPreferenceProfile`), length_delta, specificity, repetition, section_fit,
      historical_success (from the log). REUSE existing scorers — do NOT reimplement or change scoring math.
- [ ] Pluggable ranker: a `Ranker` Protocol + a `HeuristicRanker` implementation with a TRANSPARENT
      weighted formula (documented default weights) producing a score AND a per-candidate reason string
      (which features drove it — "explain every suggestion"). `rank(candidates, context, *, profile) ->
      list[RankedCandidate]` sorted deterministically (stable tie-break).
- [ ] TRUTH HARD-BLOCK (REQ-1305 / NFR-1303): any candidate whose unsupported_claim_risk indicates a
      truth-gate failure is EXCLUDED regardless of score — the ranker can never surface a truth-failing
      candidate. Identity/employer/date edits are out of bounds (candidates come from the truth/policy-gated
      improve skills; the ranker additionally refuses truth-failing ones).
- [ ] Multi-objective: the weighted score balances predicted-acceptance / ATS / fact-support / readability
      / voice (documented weights) — never acceptance alone.
- [ ] Pluggability (NFR-1302): callers depend on the `Ranker` Protocol so a learned ranker can replace the
      heuristic later without changing callers. Export the protocol + heuristic + feature extractor from
      `resume_kit_feedback` (coordinate `__init__` — see Dependencies).
- [ ] Determinism: fixed inputs → identical features, scores, ordering, and reasons. Tests: each feature's
      computation, truth hard-block excludes a fabricated candidate, weighting/ordering, reason strings
      present, determinism. `ruff` + `mypy --strict` clean; full suite green.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + high` — The decision-making core; correctness of the truth hard-block (safety) + reusing the right
scorers + a clean pluggable interface are load-bearing. Substantive integration across ats/matching/
evidence.

### Technical Approach
- Read RIT-T-0085's `CandidateFeatures`/`UserPreferenceProfile` + the public scorers: `resume_kit_ats`
  (`compute_ats_score`/`check_ats_structure`), `resume_kit_matching` (`calculate_keyword_match`,
  `analyze_terminology_alignment`), `resume_kit_evidence` (`validate_resume_truth`,
  `build_candidate_evidence`). Compute features by CALLING these; do not duplicate logic.
- `HeuristicRanker`: additive weighted score over normalized features; emit a reason listing the top
  contributing (+/-) features. Truth failure → exclude before scoring (hard block).
- Keep the `Ranker` a `typing.Protocol`; the heuristic is one implementation.
- Pure/deterministic; stable sort tie-breaks.

### Dependencies
- Depends on: RIT-T-0085 (schemas). Uses `UserPreferenceProfile` (the TYPE from 0085), not RIT-T-0086's
  derivation code — so parallel-safe with RIT-T-0086 PROVIDED you do NOT edit
  `packages/feedback/src/resume_kit_feedback/__init__.py` (orchestrator wires exports at the gate). Report
  your new public symbols. Add any needed resume-kit deps (ats/matching/evidence) to

- Blocks: RIT-T-0088.

### Risk Considerations
- **Truth-block bypass**: the hard block is safety-critical — test that a fabricated candidate is excluded
  regardless of score.
- **Scoring-math drift**: reuse existing scorers; do not change engine math.
- **__init__/pyproject collision** with parallel RIT-T-0086: do NOT edit `__init__.py`; report exports +
  any pyproject deps you add so the orchestrator reconciles.
- **Nondeterminism**: stable ordering; no random.
