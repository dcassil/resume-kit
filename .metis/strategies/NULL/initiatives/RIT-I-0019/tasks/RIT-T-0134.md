# ResumeShapePolicy in resume-kit-policy

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0019]]

## Objective **[REQUIRED]**

Phase 2 of RIT-I-0019. Add a `ResumeShapePolicy` to `packages/policy` (`resume_kit_policy`)
that expresses the canonical section order, the keyword→canonical-section alias/mapping table,
the allowed `other`/custom fallback behavior, and **informational-only** budget fields — as
**data, not heuristics**. This policy is configuration consumed by the analyzer (Phase 3) and
canonicalizer (Phase 4); it contains **no trimming/deletion/ranking rules** (budgets belong to
the future `perfect`/`fit` pass and here are informational only).

## Acceptance Criteria **[REQUIRED]**

- [ ] `ResumeShapePolicy` defined in `resume_kit_policy` (alongside `path_policy.py` /
      `skill_targets.py`) carrying: `section_order` (canonical ordering of sections), an
      alias/mapping table `dict[str, CanonicalSection]` (keyword/heading → canonical section),
      `other` fallback behavior, and budget fields explicitly flagged **informational-only**.
- [ ] The alias/mapping table is **seeded from** the ATS engine's existing
      `_CONVENTIONAL_SECTION_KEYWORDS` (in `resume_kit_ats/engine.py`), promoted from a flat set
      into a `dict[str, CanonicalSection]` mapping. The seed source is referenced, not
      duplicated by hand where avoidable; if copied, a comment records the origin.
- [ ] `CanonicalSection` is an enum (or equivalent) whose members correspond to the canonical
      `Resume` top-level collections (basics/work/skills/projects/education/certifications/
      awards/publications/volunteer/languages/interests/references) plus an `other` fallback.
- [ ] Budget fields (e.g. max skills, summary length) are present but carry **no fix/trim
      affordance** and are documented as informational-only for this stage.
- [ ] The policy is **project-overridable via `config.json`** following the same override
      pattern as existing policies in `resume_kit_policy` (default policy + project overlay).
- [ ] Unit tests in `packages/policy/tests/` cover: default policy loads; the alias table maps
      known headings (e.g. "Technical Skills" → skills, "Certifications" → certifications);
      unknown headings resolve to `other`; a project override overlays the default.
- [ ] No deletion/trim/ranking logic anywhere in the policy.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Model `ResumeShapePolicy` as a pydantic/dataclass structure consistent with existing policy
objects. Provide a `default_shape_policy()` constructor and a project-overlay path mirroring how
`path_policy`/`skill_targets` load defaults and apply `config.json` overrides. Import
`CanonicalSection` from the canonical schema types added in RIT-T-0133 if a shared enum is
cleaner; otherwise define locally and keep names aligned. Promote
`_CONVENTIONAL_SECTION_KEYWORDS` into a mapping — do NOT modify `engine.py` behavior in this
task (the ATS retirement is RIT-T-0140); reading/copying the seed is fine.

### Dependencies
- Independent of RIT-T-0133 for scheduling, but references the canonical section vocabulary; if
  a shared `CanonicalSection` enum lives in schemas (RIT-T-0133), import it. Coordinate so the
  enum is defined once. (Analyzer/canonicalizer are blocked on BOTH this and 0133.)

### File claims (exclusive)
- `packages/policy/src/resume_kit_policy/**` (new shape policy module + exports)
- `packages/policy/tests/**` (new tests)

### Risk Considerations
- **Scope creep into heuristics** — this is a data table, not logic. No detection here.
- **Enum drift** — canonical section names must match the schema's collections exactly.
