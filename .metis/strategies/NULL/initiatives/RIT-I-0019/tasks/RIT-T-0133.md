# Canonical Resume schema + shape schemas in packages/schemas

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0019]]

## Objective **[REQUIRED]**

Phase 1 (foundational) of RIT-I-0019. Transcribe the authoritative canonical `Resume`
definition in `references/jsonresume.md` into first-class pydantic v2 schema types in
`packages/schemas` (`resume_kit_schemas`), and add the new shape-pass schema types
(`ShapeReport`, `ShapeFinding`, `SectionMapping`, `ContentLedger`, `ShapeFixResult`). Every
later phase of this initiative consumes these types, so getting the shape and the cardinality
rules right is load-bearing. This task is **schema-only**: no analyzer, no canonicalizer, no
facade wiring.

## Acceptance Criteria **[REQUIRED]**

- [ ] New module(s) under `packages/schemas/src/resume_kit_schemas/` define the canonical
      `Resume` model and its sub-models per `references/jsonresume.md`: `Resume`, `Basics`,
      `Location`, `Experience`, `Achievement`, `Metric`, `SkillGroup`, `Project`, `Education`,
      `Certification`, `Link`, `ResumeDate`, and the remaining optional collections
      (`awards`, `publications`, `volunteer`, `languages`, `interests`, `references`).
- [ ] Cardinality / `oneOrMore` rules from the spec are enforced at validation time:
      `basics.name` required; at least one of `email`/`phone` present; `Experience.organization`
      and `Experience.title` required; other required fields per the spec. Violations raise
      pydantic `ValidationError`.
- [ ] `Achievement` supports a verbatim `text` field plus **optional** `action`/`result`/
      `metrics`/`skills`/`keywords` fields that default empty — the structure pass populates only
      `text`; the richer fields exist for future work but are never required.
- [ ] Shape-pass schemas added: `ShapeFinding` (family/code enum, section ref, message,
      optional proposed target + confidence), `ShapeReport` (list of findings + summary),
      `SectionMapping` (source section → canonical target + status), `ContentLedger` (per-token
      fate with states `present_after | moved | deduped | dropped_as_heading |
      dropped_as_parser_artifact | dropped_by_explicit_decision | unresolved`), and
      `ShapeFixResult` (resulting `Resume` + ledger + applied/deferred findings).
- [ ] Finding-family codes are defined as an enum covering `CUSTOM_SECTION_MAPPED`,
      `CUSTOM_SECTION_UNMAPPED`, `REDUNDANT_SECTION`, `DUPLICATE_SECTION_CONTENT`,
      `CANONICAL_FIELD_DUPLICATE`, `EMBEDDED_HEADING_LINE`, `SECTION_ORDER_VIOLATION`, plus an
      informational `BUDGET_INFO` family.
- [ ] New types are exported from the package's public `__init__`/exports consistent with how
      existing schemas (e.g. `ScoreDoc`, `ResumeDocument`) are exported.
- [ ] Unit tests in `packages/schemas/tests/` cover: a valid canonical `Resume` round-trips;
      each cardinality rule has a failing case; `Achievement` accepts text-only; each new shape
      schema constructs and serializes.
- [ ] No dependency on http/provider code (respect the schemas boundary test
      `tests/boundary/test_boundary_schemas_no_http.py` — never let a source line START with
      `from <word>` inside a docstring).

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Read `references/jsonresume.md` in full as the source of truth. Model each entity as a pydantic
v2 `BaseModel` with explicit field types and validators for the `oneOrMore`/required rules
(use `model_validator(mode="after")` where a cross-field rule is needed). Mirror existing
schema conventions in `resume_kit_schemas` (field naming, `Field(default_factory=...)` for
collections, docstrings). Keep the canonical model faithful and strict but do not add semantics
the spec does not state. The shape schemas are plain data containers consumed by later phases —
keep them minimal and serializable.

### Dependencies
- No task dependencies (foundational). Consumes only `references/jsonresume.md`.

### File claims (exclusive)
- `packages/schemas/src/resume_kit_schemas/**` (new canonical + shape modules, exports)
- `packages/schemas/tests/**` (new tests)

### Risk Considerations
- **Over-modeling** — do not invent fields beyond the spec. Rule of thumb: if it is not in
  `references/jsonresume.md`, it is not a canonical field.
- **Boundary test** — schemas must remain import-clean of http/provider modules.
