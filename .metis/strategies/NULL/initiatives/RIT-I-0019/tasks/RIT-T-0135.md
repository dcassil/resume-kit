# Read-only deterministic shape analyzer

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0019]]

## Objective **[REQUIRED]**

Phase 3 of RIT-I-0019. Implement `analyze_resume_shape(resume, policy) -> ShapeReport` in
`packages/scoring/src/resume_kit_scoring/shape_analyzer.py`: a deterministic, side-effect-free
classifier that reports how a resume's actual shape diverges from the canonical shape. It
**never mutates** and **never writes** — pure analysis producing a `ShapeReport` of findings.

## Acceptance Criteria **[REQUIRED]**

- [ ] `analyze_resume_shape(resume, policy)` exists in `resume_kit_scoring/shape_analyzer.py`,
      is deterministic and side-effect-free, and returns a `ShapeReport` (RIT-T-0133 schema).
- [ ] Emits findings for every family: `CUSTOM_SECTION_MAPPED` (custom section confidently maps
      to a canonical field, with proposed target + confidence), `CUSTOM_SECTION_UNMAPPED`
      (no confident mapping), `REDUNDANT_SECTION` / `DUPLICATE_SECTION_CONTENT` (two sections
      overlap by token-set), `CANONICAL_FIELD_DUPLICATE` (a custom section duplicates a
      canonical field, e.g. a "Technical Skills" section vs `additional.technicalSkills`),
      `EMBEDDED_HEADING_LINE` (first list item equals the section heading/key),
      `SECTION_ORDER_VIOLATION` (order differs from policy `section_order`).
- [ ] Redundancy / duplicate-content detection **reuses the matching tokenizer** in
      `resume_kit_matching/keywords.py` (token-set overlap) — no bespoke tokenizer.
- [ ] Section→canonical classification uses the RIT-T-0134 `ResumeShapePolicy` alias table;
      unknown headings yield `CUSTOM_SECTION_UNMAPPED`.
- [ ] Budget conditions (skills count, summary length, etc.) are surfaced as **informational
      `BUDGET_INFO` findings only**, carrying no fix affordance.
- [ ] Determinism: given a fixed input the report is byte-identical across runs (stable finding
      ordering). No LLM, no network, no randomness.
- [ ] Unit tests in `packages/scoring/tests/` are table-driven: each finding family has ≥1
      positive case and ≥1 clean (no-finding) case; the redundant Core/Technical Skills +
      Domains & Industries scenario produces the expected `REDUNDANT_SECTION` /
      `CANONICAL_FIELD_DUPLICATE` findings; a fully-canonical resume yields an empty/clean
      report.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Iterate the resume's sections (including `customSections`). For each: resolve against the
policy alias table → mapped/unmapped; compute token sets via the matching tokenizer and compare
against other sections and canonical fields for overlap thresholds → redundancy/duplicate; check
first-list-item vs heading → embedded heading line; compare observed order against
`policy.section_order` → order violation. Produce `ShapeFinding`s with stable sort keys
(e.g. by family then section name). Keep everything pure — return the report, mutate nothing.
This task does NOT apply any transform (that is RIT-T-0136).

### Dependencies
- **Blocked by [[RIT-T-0133]]** (canonical + shape schemas) and **[[RIT-T-0134]]** (policy).
- Reuses `resume_kit_matching/keywords.py` tokenizer (read-only).

### File claims (exclusive)
- `packages/scoring/src/resume_kit_scoring/shape_analyzer.py` (new)
- `packages/scoring/tests/test_shape_analyzer*.py` (new)
- scoring package exports (add `analyze_resume_shape`)

### Risk Considerations
- **Non-determinism** — stabilize all ordering; never rely on set iteration order in output.
- **Over-eager redundancy** — pick overlap thresholds conservatively; prefer flagging as a
  finding (later deferred) over asserting a merge the analyzer cannot justify.
