# Non-destructive canonicalizer + content ledger + two hard gates

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0019]]

## Objective **[REQUIRED]**

Phase 4 (load-bearing correctness) of RIT-I-0019. Implement the strictly non-destructive
canonicalizer `apply_shape_transforms(resume, report, decisions=None) -> ShapeFixResult` in
`packages/scoring/src/resume_kit_scoring/shape_fix.py`, together with the `ContentLedger`
accounting and the two hard write gates: `content_ledger_ok(ledger)` and
`claims_preserved_across_sections(before, after)`. The invariant: the pass can move content into
canonical shape but can **never** add, drop, reword, interpret, trim, or lose a substantive
token or a claim.

## Acceptance Criteria **[REQUIRED]**

- [ ] `apply_shape_transforms(resume, report, decisions=None)` in `shape_fix.py` performs only
      **lossless** moves: map clean skill/certification/award custom sections into their
      canonical fields; merge/dedupe redundant sections and canonical-field duplicates; strip
      embedded heading-line artifacts; normalize section order. Each source bullet moves
      **verbatim** into `Achievement.text` (no `action`/`result`/`metric` parsing).
- [ ] Ambiguous / prose-heavy sections (e.g. "Core Skills" prose, "Domains & Industries") are
      **never blindly coerced or dropped** — they become `unresolved` mapping candidates
      (surfaced `needs_user_input`) or are preserved verbatim as deliberate `other`/custom
      content. Explicit `decisions` (from Phase 6 skill) resolve unresolved mappings.
- [ ] A `ContentLedger` records every substantive input token's fate with a state in
      `present_after | moved | deduped | dropped_as_heading | dropped_as_parser_artifact |
      dropped_by_explicit_decision | unresolved`.
- [ ] `content_ledger_ok(ledger)` passes **only** when every substantive input token is
      `present_after` or accounted for by an allowed non-lossy reason. `dropped_by_budget` is
      **not** a permitted reason at this stage. A ledger with an unaccounted token fails.
- [ ] `claims_preserved_across_sections(before, after)` extracts each claim type (skills,
      employers, titles, degrees) from **wherever it lives in the whole resume** (not a single
      field) and passes iff no claim is added/dropped/altered. Moving a "Technical Skills"
      custom section into canonical `skills` must **not** read as added claims.
- [ ] The existing field-scoped `claims_preserved` predicate is **left unchanged** (base/standard
      keep using it); the new across-sections predicate gates `structure` only.
- [ ] `apply_shape_transforms` itself does not write files (Phase 5 owns the write); it returns a
      `ShapeFixResult` carrying the new `Resume`, the ledger, and applied/deferred findings.
- [ ] Unit tests (adversarial): a transform that drops a token FAILS `content_ledger_ok`; a
      merge that loses a skill FAILS; moving a "Technical Skills" section into canonical `skills`
      PASSES `claims_preserved_across_sections`; each gate has ≥1 pass and ≥1 refuse case; clean
      canonicalization of the redundant-sections fixture is fully accounted in the ledger.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Consume the `ShapeReport` from RIT-T-0135. Apply only the auto-safe transforms the report
justifies; for `unresolved`/ambiguous items, defer unless a matching `decisions` entry is
supplied. Build the `ContentLedger` as you go: tokenize source content (reuse the matching
tokenizer) and record where each token lands. `dropped_as_parser_artifact` defends against the
[[RIT-T-0131]] phantom-token symptom. Gate failure is a **bug, not user data** — return the
result but let the gate predicates report False so Phase 5 refuses the write and surfaces the
report. Keep everything deterministic; no LLM.

### Dependencies
- **Blocked by [[RIT-T-0135]]** (analyzer / `ShapeReport`).
- Reuses matching tokenizer and canonical/shape schemas (RIT-T-0133).
- Related: [[RIT-T-0131]] (faithfulness phantom ADDED_TOKENS) — `dropped_as_parser_artifact`
  mitigates the same symptom; do not depend on 0131 landing.

### File claims (exclusive)
- `packages/scoring/src/resume_kit_scoring/shape_fix.py` (new: transforms + `ContentLedger` +
  `content_ledger_ok` + `claims_preserved_across_sections`)
- `packages/scoring/tests/test_shape_fix*.py` (new)
- scoring exports (add the new functions/predicates)

### Risk Considerations
- **Silent loss** — the entire point is that this cannot happen; the ledger gate is the guard.
  Prefer `unresolved` over any lossy shortcut.
- **False claim add/drop** — the across-sections predicate must extract claims globally; test
  the re-bucketing case explicitly.
