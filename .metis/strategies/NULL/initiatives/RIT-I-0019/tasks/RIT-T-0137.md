# build_structure stage + config lineage + projection bridge

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0019]]

## Objective **[REQUIRED]**

Phase 5 of RIT-I-0019. Wire the structure pass into the facade lineage: add `build_structure`,
extend `ProjectConfig` with `structure_*` pointers, update `set_version`/`resolve_active_resume`,
add the deterministic `project_builddoc_from_canonical` projection, and change **only**
`build_standard`'s input resolution to prefer `structure`. All additive and backward-compatible;
`base` and the `standardize` wording logic stay behaviorally unchanged.

## Acceptance Criteria **[REQUIRED]**

- [ ] `build_structure(root, *, answers=None, decisions=None) -> BuildStructureResult` added to
      `packages/facade/src/resume_kit_facade/baseline.py`, mirroring `build_base`/`build_standard`:
      resolve `base ?? original`, run `analyze_resume_shape`, apply `apply_shape_transforms` with
      accepted `decisions`, run **both** gates (`content_ledger_ok` +
      `claims_preserved_across_sections`), and on pass write `<name>-structure.json` (canonical
      schema) then `set_version(structure=…, structure_derived_from=source)`. On gate failure the
      write is refused and the report is returned.
- [ ] `ProjectConfig` (in `resume_kit_facade/project_config.py`) gains optional
      `structure_resume` + `structure_derived_from` fields; `set_version` gains
      `structure=`/`structure_derived_from=` params with the same "derived_from without pointer =
      error" guard the base/standard pointers use. Atomic write + unknown-key round-trip preserved.
- [ ] `resolve_active_resume` resolution order becomes `standard ?? structure ?? base ?? original`.
- [ ] `project_builddoc_from_canonical(Resume) -> BuildDoc/ResumeDocument` added as the
      inverse-direction analogue of `project_scoredoc` ([[RIT-A-0002]]), housed alongside the
      existing projection code. Pure, deterministic, no side effects.
- [ ] `build_standard` changes **exactly one thing**: its source resolution from
      `base ?? original` to `structure ?? base ?? original`, projecting the canonical structure
      via `project_builddoc_from_canonical` before its existing analyzer runs. Its wording logic
      is otherwise untouched.
- [ ] Backward compatibility: a project with only `original`/`base` still works; `structure` is
      optional; all existing `base`/`standard` tests still pass.
- [ ] Unit/integration tests: `build_structure` writes canonical structure + sets pointers;
      lineage resolution honors the new order; `project_builddoc_from_canonical` round-trips the
      redundant-sections fixture into a valid BuildDoc; `build_standard` produces `standard`
      unchanged when seeded from `structure`.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Copy the `build_base`/`build_standard` structure closely for `build_structure` (same resolve →
analyze → apply → gate → write → set_version spine). Extend `ProjectConfig` exactly like the
`base`/`standard` pointer pair (RIT-T-0113 pattern), including the lineage guard. For the
projection, mirror `project_scoredoc`'s module placement and purity; map canonical
`work[]`/`Achievement.text`/`SkillGroup`s back into the `BuildDoc`/`ResumeDocument` fields
`standardize` already consumes. Touch `build_standard` minimally — one resolution line + a
projection call. Do NOT alter `base`, ingest, or the faithfulness contract.

### Dependencies
- **Blocked by [[RIT-T-0136]]** (canonicalizer + gates).
- Builds on [[RIT-T-0113]] (version-lineage substrate) and [[RIT-A-0002]] projection pattern.

### File claims (exclusive)
- `packages/facade/src/resume_kit_facade/baseline.py` (add `build_structure`; change
  `build_standard` resolution only)
- `packages/facade/src/resume_kit_facade/project_config.py` (`structure_*` fields, `set_version`,
  `resolve_active_resume`)
- projection module (alongside `project_scoredoc`) — add `project_builddoc_from_canonical`
- `packages/facade/tests/**` + scoring projection tests as needed

### Risk Considerations
- **Behavioral drift in standardize** — keep the diff to the single resolution line + projection
  call; run the full existing standard test set to prove parity.
- **Config back-compat** — unknown keys must round-trip; only-`original` projects must not break.
