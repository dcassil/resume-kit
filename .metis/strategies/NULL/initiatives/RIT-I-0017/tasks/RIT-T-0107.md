# Repoint matching onto ScoreDoc

## Parent Initiative

[[RIT-I-0017]]

## Objective **[REQUIRED]**

Rewire `packages/matching/keywords.py` (job-match / keyword coverage) to read the ScoreDoc zoned keyword
index instead of walking the raw resume dict, and apply zone weights (experience > skills_list > summary)
plus recency weighting. This is the change that structurally fixes the 85.8->75.8 bug.

## Context

Today `keywords.py` hardcodes `additional.technicalSkills` and friends (`keywords.py:197-213`) and builds
an undifferentiated text blob (`_extract_all_text_cached`, `:157`). That flat read is exactly why
categorized skills were under-counted. ScoreDoc's zoned index makes zone-weighted, dynamic harvesting
possible.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `keywords.py` consumes the ScoreDoc zoned index; no literal reads of `additional`/`technicalSkills`/
      `workExperience`/`customSections` remain in the matching scoring path (grep-clean).
- [ ] Zone weighting implemented: a keyword proven in an experience bullet counts more than the same token
      in a bare skills list, which counts more than one only in the summary; weights are named constants.
- [ ] Recency weighting applied using ScoreDoc entity dates (more recent experience weighted higher),
      deterministic against a caller-supplied reference date.
- [ ] Existing `calculate_keyword_match` / `analyze_keyword_gaps` public behavior preserved in shape;
      numbers change only where the old flat read was wrong.
- [ ] Unit tests: zone-weight ordering; the categorized-skills token now counts; determinism.

### Technical Approach

comparison already used (`_match_keyword_in_text`), but source candidate tokens from the zoned index.
