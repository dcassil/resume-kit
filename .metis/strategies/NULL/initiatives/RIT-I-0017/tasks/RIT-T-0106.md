# project_scoredoc(BuildDoc) -> ScoreDoc

## Parent Initiative

[[RIT-I-0017]]

## Objective **[REQUIRED]**

Implement the pure deterministic projection `project_scoredoc(resume, *, reference_date) -> ScoreDoc`:
canonical section segmentation, entity extraction incl. date->YoE, `customSections`->zone mapping, and
the zoned keyword index. This is the single new load-bearing component.

## Context

Per [[RIT-A-0002]] scoring must read a derived ScoreDoc, not BuildDoc fields. The projection replaces the
ad-hoc dict-walking in `ats/engine.py:93` and `matching/keywords.py:157` with one canonical producer.
Determinism is a hard contract: no clock reads — the reference "now" for YoE is caller-supplied.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `project_scoredoc` lives in the home package chosen by [[RIT-T-0104]] and returns a `ScoreDoc`.
- [ ] Sections: `summary`, `workExperience`, `education`, `personalProjects`, `additional`, and each
      `customSections` entry are segmented into canonical `ScoreSection`s; `customSections` map to zones
      by `SectionType` per the 0104 mapping table.
- [ ] Entities: name/email/phone/links from `personalInfo`; per `Experience` the title/company/`years`
      parsed to start/end and a computed duration; total YoE computed against `reference_date`;
      degrees/institutions from `education`.
- [ ] Zoned keyword index: every surfaced token is attributed to the zone(s) it appears in
      (experience / skills_list / summary / education / projects / other).
- [ ] **Determinism**: identical `(resume, reference_date)` yields byte-identical `ScoreDoc`; no clock or
      network reads. Open-ended ("Present") and missing dates handled per the 0104 rule.
- [ ] Golden-fixture tests: a known BuildDoc (including a categorized-skills custom section) projects to
      an asserted ScoreDoc; a determinism test asserts repeated projection is identical; YoE edge cases
      covered.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Reuse the shared normalizer/alias tooling already used by matching/ats where tokenizing, so ScoreDoc
tokens align with how scoring compares them. Keep date parsing tolerant but deterministic; centralize the
accepted formats. Pure function; no I/O.
