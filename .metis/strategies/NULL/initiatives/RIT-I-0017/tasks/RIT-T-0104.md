# Design: projection home package + ScoreDoc schema shape + projection contract

## Parent Initiative

[[RIT-I-0017]]

## Objective **[REQUIRED]**

Lock the load-bearing design decisions every downstream task consumes: (1) where the projection lives
(new `packages/scoring` vs. inside `packages/ats`), (2) the exact `ScoreDoc` schema shape
(sections/entities/zoned index), and (3) the `project_scoredoc` contract — especially the deterministic
date->YoE reference-time input and the `customSections`->zone mapping rules.

## Context

Per [[RIT-A-0002]] the base is a deterministic projection `BuildDoc -> ScoreDoc`. Getting the package
boundary and schema contract right first prevents compounding rework across the schema, projection,
matching/ats repoints, and the report. Today `packages/ats` and `packages/matching` both walk the raw
resume dict independently (`ats/engine.py:93` `_extract_all_text`, `matching/keywords.py:157`
`_extract_all_text_cached`); both must end up depending on the projection without creating an import
cycle.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Compare a dedicated `packages/scoring` package (cleanest boundary; `ats` and `matching` both import it)
against folding into `ats` (fewer packages, but `matching` importing `ats` for the projection is an odd
dependency). Recommendation leans to the dedicated package. Enumerate `ScoreSection`, `ScoreEntities`,
`ZonedKeywordIndex`, `KeywordZone` fields concretely.

### Dependencies
First task of the initiative; blocks [[RIT-T-0105]] and everything after. Sequenced after [[RIT-I-0015]].

### Risk Considerations
Highest-leverage task — a wrong boundary or schema shape compounds across 7 downstream tasks. Worth the
extra design rigor before any code.

### Recommended Agent
**opus + high** — load-bearing architecture and contract design that all downstream work depends on.

## Status Updates **[REQUIRED]**

- 2026-08-05: Created as part of RIT-I-0017 decomposition.
- 2026-08-05 — **Design decided.**
  - **Projection home package:** a new dedicated `packages/scoring` package owns `project_scoredoc`. Rationale: both `resume_kit_ats` and `resume_kit_matching` must depend on the projection; putting it in either would force an ats↔matching edge (cycle risk). `packages/scoring` depends only on `resume_kit_schemas` + `resume_kit_terms` (for tokenization/alias-aware zoning); `ats` and `matching` depend on `scoring`. The `ScoreDoc` **schema** lives in `packages/schemas/scoredoc.py` (pure data, no logic) so every layer can type against it without importing the projection.
  - **`ScoreDoc` field list:** `schema_version:int`, `sections:list[ScoreSection]`, `entities:ScoreEntities`, `zoned_index:ZonedKeywordIndex`.
  - **`ScoreSection`:** `name:str` (canonical), `zone:KeywordZone`, `text:str`, `source_section_type:str|None`.
  - **`KeywordZone` (StrEnum):** `experience`, `skills_list`, `summary`, `education`, `projects`, `other`.
  - **`ScoreEntities`:** `name`, `email`, `phone`, `links:list[str]`; `roles:list[ScoreRole]` where `ScoreRole = {title, company, start_date:str|None, end_date:str|None, duration_months:int|None}`; `total_years_experience:float`; `education:list[ScoreDegree]` where `ScoreDegree = {degree, institution}`.
  - **`ZonedKeywordIndex`:** `token_zones:dict[str,list[KeywordZone]]` and `zone_tokens:dict[KeywordZone,list[str]]` (both directions for cheap lookups).
  - **Projection contract:** `project_scoredoc(resume: ResumeDocument, *, reference_date: date) -> ScoreDoc`. Pure/deterministic — NO clock reads inside; `reference_date` is caller-supplied and used for open-ended date→YoE. Identical `(resume, reference_date)` → byte-identical `ScoreDoc`.
  - **`customSections` `SectionType`→`KeywordZone` mapping:** SKILLS→`skills_list`; EXPERIENCE/WORK→`experience`; EDUCATION→`education`; PROJECTS→`projects`; SUMMARY/OBJECTIVE→`summary`; everything else→`other`.
  - **date→YoE rule:** accept `YYYY`, `YYYY-MM`, `Mon YYYY`/`Month YYYY` (case-insensitive); `Present`/`Current`/empty end → `reference_date`; a role's duration = months between parsed start and end (min 0); **total YoE = union of role intervals** (overlapping roles counted once) in months / 12, rounded to 1 decimal; unparseable dates → that role contributes `duration_months=None` and is excluded from the union.
  - **Purely additive confirmed:** no change to `resume.py`, renderer, or export. Downstream 0105/0106 notes are consistent with this shape (0105 already lists these zones/entities; reconciled — added `projects` zone + `ScoreRole`/`ScoreDegree` naming).
