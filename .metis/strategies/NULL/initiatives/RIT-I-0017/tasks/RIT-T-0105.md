# ScoreDoc schema in packages/schemas

## Parent Initiative

[[RIT-I-0017]]

## Objective **[REQUIRED]**

Add the `ScoreDoc` domain schema and its sub-models to `packages/schemas` per the shape finalized in
[[RIT-T-0104]] — the canonical ATS-view representation that scoring reads from.

## Context

`ScoreDoc` is the derived, ATS-view counterpart to `ResumeDocument` (BuildDoc). It must carry canonical
sections, extracted entities (incl. computed YoE), and a zoned keyword index. It is a pure Pydantic
domain model like the existing `resume.py` — transport-agnostic, no clock reads.

## Acceptance Criteria **[REQUIRED]**

- [ ] New module `packages/schemas/src/resume_kit_schemas/scoredoc.py` defines: `KeywordZone` (StrEnum:
      `experience`, `skills_list`, `summary`, `education`, `projects`, `other`), `ScoreSection`,
      `ScoreEntities` (name, email, phone, links; per-role title/company/parsed dates/duration; total
      computed YoE; degrees/institutions), `ZonedKeywordIndex` (token -> set/list of zones + per-zone
      token lists), and `ScoreDoc` composing them.
- [ ] Models are frozen/deterministic, default-populated, and carry no clock reads; any date fields are
      caller-supplied values (computed durations stored as data, not derived at read time).
- [ ] Public exports updated in `packages/schemas/.../__init__.py`.
- [ ] Additive and backward-compatible: no change to `resume.py`; existing schema consumers unaffected.
- [ ] Unit tests: construct/round-trip each model; JSON serialize/deserialize stable; enum values pinned.

## Test Cases **[CONDITIONAL: Testing Task]**

### Test Case 1: Round-trip stability
- **Test ID**: TC-001
- **Steps**: build a `ScoreDoc`, dump to JSON, reload.
- **Expected Results**: reloaded model equals the original; field order/enum values stable.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Mirror the conventions in `resume.py` (Pydantic BaseModel, `Field(default_factory=...)`, StrEnum). Keep
the zoned index representable both as token->zones and zone->tokens if the design task calls for both.
