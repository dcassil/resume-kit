# Repoint ats engine onto ScoreDoc

## Parent Initiative

[[RIT-I-0017]]

## Objective **[REQUIRED]**

Rewire `packages/ats/engine.py` scoring paths — `_compute_skills_coverage`, `_compute_section_completeness`,
and `check_ats_structure` — to read ScoreDoc sections/entities/zoned index instead of raw BuildDoc fields.

## Context

`engine.py` reads `additional.technicalSkills` (`:215`), checks `workExperience` presence (`:256`,
`:386`), and walks the whole dict (`_extract_all_text`, `:93`). ScoreDoc gives it canonical sections and
extracted entities so structure/coverage reflect what an ATS would segment, and share the substrate with
matching.

## Acceptance Criteria **[REQUIRED]**

- [ ] `_compute_skills_coverage`, `_compute_section_completeness`, and `check_ats_structure` read from
      ScoreDoc; no literal `additional`/`technicalSkills`/`workExperience` reads remain in the ats scoring
      path (grep-clean).
- [ ] `check-ats-structure` (parse-safety) uses ScoreDoc detected sections + entities (e.g. presence of
      name/contact, detected Experience/Education/Skills, computed YoE availability).
- [ ] Recommendation generation continues to work, sourced from ScoreDoc-derived signals.
- [ ] The two scores keep their identity: `check-ats-structure` structural, `check-job-match` content;
      both now read the shared ScoreDoc.
- [ ] Unit tests: section-completeness and skills-coverage over ScoreDoc fixtures; structure check flags a
      missing canonical section.
