# "What the ATS sees" report capability (cross-surface)

## Parent Initiative

[[RIT-I-0017]]

## Objective **[REQUIRED]**

Expose a read-only "what the ATS sees" report — detected sections, extracted entities + computed YoE, and
the zoned keyword breakdown — across facade + CLI + MCP + API, with cross-surface parity tests. This is
the most user-visible payoff of the ScoreDoc split.

## Context

Once `project_scoredoc` exists, the report is nearly free: it renders a ScoreDoc read-only. It follows the
existing capability-facade + CLI/MCP/API parity norm used throughout prior phases (e.g. `resume_export`,
`resume_check_ats_structure`).

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [x] A facade capability (e.g. `ats_view` / `resume_ats_view`) returns a structured report derived from
      ScoreDoc: detected sections, entities (name/contact/links, per-role title/company/dates, total YoE),
      and the zoned keyword breakdown.
- [x] CLI command, MCP tool, and API route expose the same capability with consistent inputs/outputs.
- [x] Cross-surface parity test asserts identical report content for the same input across facade / CLI /
      MCP / API.
- [x] Read-only: the capability never mutates the resume; deterministic against a caller-supplied
      reference date.
- [x] Public exports and the capability `REGISTRY` updated.
- [x] The report output carries the standing disclaimer that **an ATS score does not guarantee recruiter
      advancement** (a stable, non-alarming note in the report payload/copy). This is the shared surface on
      which [[RIT-I-0018]]'s "don't imply the score guarantees advancement" guidance lands — see
      [[RIT-A-0004]] lane routing. Keep it deterministic copy, not a computed value.
