# "What the ATS sees" report capability (cross-surface)

## Parent Initiative

[[RIT-I-0017]]

## Objective **[REQUIRED]**

Expose a read-only "what the ATS sees" report — detected sections, extracted entities + computed YoE, and
the zoned keyword breakdown — across facade + CLI + MCP + API, with cross-surface parity tests. This is
the most user-visible payoff of the ScoreDoc split.

## Context

Once `project_scoredoc` exists, the report is nearly free: it renders a ScoreDoc read-only. It follows the
existing capability-facade + CLI/MCP/API parity norm used throughout prior phases (e.g. `resume_export`,
`resume_check_ats_structure`).

## Acceptance Criteria **[REQUIRED]**

- [ ] A facade capability (e.g. `ats_view` / `resume_ats_view`) returns a structured report derived from
      ScoreDoc: detected sections, entities (name/contact/links, per-role title/company/dates, total YoE),
      and the zoned keyword breakdown.
- [ ] CLI command, MCP tool, and API route expose the same capability with consistent inputs/outputs.
- [ ] Cross-surface parity test asserts identical report content for the same input across facade / CLI /
      MCP / API.
- [ ] Read-only: the capability never mutates the resume; deterministic against a caller-supplied
      reference date.
- [ ] Public exports and the capability `REGISTRY` updated.

## Test Cases **[CONDITIONAL: Testing Task]**

### Test Case 1: Cross-surface parity
- **Test ID**: TC-001
- **Expected Results**: facade/CLI/MCP/API return byte-equivalent report payloads for one fixture.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
Add the facade capability first (single source of behavior), then thin CLI/MCP/API adapters over it,
mirroring the existing check capabilities. Reuse the parity-test harness from prior phases.
