# Plugin skills: truth-gated propose→confirm→append alias workflow

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0009]]

## Objective **[REQUIRED]**

Add the agent-side growth loop (REQ-902/903/904): when an ATS/match/gap run shows a JD keyword as
"missing" that the resume plausibly satisfies under a DIFFERENT term, the agent PROPOSES an alias —
truth-gated — and, on user confirmation, APPENDS a justified entry to the project alias file
(`resume-kit/learning/synonyms.json`) so future deterministic runs match it automatically. The agent
writes DATA; scoring stays deterministic and provider-free.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] The relevant plugin skills — `check-resume-ats`, `check-resume-job-match`, `identify-resume-gaps`
      — gain a documented step: after computing gaps, for each "missing" JD keyword the resume plausibly
      satisfies under another surface term, run the truthfulness gate and (if it passes) offer to record
      an alias. A shared reference (a small `manage-synonyms` skill OR a shared reference doc the three
      skills link) holds the workflow so it is defined once, not copy-pasted.
- [ ] **Truthfulness gate (REQ-903), enforced in skill instructions:** propose an alias ONLY for genuine
      synonyms of the SAME underlying skill/fact (e.g. NetSuite↔SuiteCommerce where true). NEVER equate
      distinct skills (React≉Vue), NEVER broaden scope, NEVER let an unsupported claim score as present.
      Ambiguous → do NOT add; surface to the user instead. Include the React≈Vue rejected example in the
      skill text (Testing Strategy requirement).
- [ ] Each recorded alias carries `{canonical, alias, why}` (one-line justification) and is appended to
      the project file in the RIT-T-0068 format (project entries union with the seed). Appends are
      idempotent (no duplicate entries) and human-readable/prunable.
- [ ] A run that adds aliases REPORTS what it added (canonical, alias, why) and never adds silently
      (REQ-904). Recording requires explicit user confirmation (human-in-loop), consistent with the
      plugin's human-in-control posture.
- [ ] Skills instruct running in a SUBAGENT where the established convention applies, and reading/writing
      under the `resume-kit/learning/` working-dir convention (consistent with resume-to-json/job-to-json).
- [ ] `claude plugin validate` passes; the plugin skill test set stays green; if a new `manage-synonyms`
      skill slug is introduced, it is registered wherever skills are enumerated and covered by the tests.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + medium` — Skill markdown, but the truthfulness gate is load-bearing product policy (the guardrail
preventing score inflation) and must be worded precisely and consistently across three skills plus a
shared reference. Needs judgment on same-fact synonym vs distinct skill, and coordination with the file
format from RIT-T-0068. Not `high` (no core engine), not `low` (policy wording + multi-file consistency
+ validation).

### Technical Approach
- Read the existing `plugins/resume-intelligence/skills/{check-resume-ats,check-resume-job-match,identify-resume-gaps}/SKILL.md`
  and the resume-to-json/job-to-json SKILLs for the learning-dir + subagent + config conventions to mirror.
- Define the workflow once (shared reference or a `manage-synonyms` skill) and link it from the three
  scoring skills to avoid divergence.
- Specify the exact append target/format matching RIT-T-0068's project-file schema (incl. the `why`
  justification channel) and the idempotent-append rule.
- Bake the truthfulness gate as explicit DO/DON'T with concrete accept (NetSuite↔SuiteCommerce) and
  reject (React≈Vue; claiming absent Kubernetes) examples.

### Dependencies
- Depends on: RIT-T-0068 (project-file format + merge — the append target and its schema).
- File-disjoint from RIT-T-0069 (surfaces/engine code) — markdown under `plugins/`; can run in parallel
  with 0069 once 0068 lands.
- Coordinate the written file format with RIT-T-0071 (which asserts a project file matches).

### Risk Considerations
- **Score inflation via bad aliases** — the whole truth posture. The gate wording must make equating
  distinct skills clearly forbidden and default ambiguous cases to "don't add".
- **Silent growth** — appends must be confirmed + reported; never auto-append.
- **Divergent workflow copies** — define once, link from the three skills.
- **Validation breakage** — run `claude plugin validate`; keep frontmatter/format correct.

### Verification Steps
1. `claude plugin validate` (or the repo's plugin validation command) passes.
2. `uv run --no-sync pytest plugins tests -k "skill or plugin"` (the plugin/skill test set) green.
3. Manual read-through: the three skills link the shared workflow; the gate + accept/reject examples are
   present; the append format matches RIT-T-0068.
