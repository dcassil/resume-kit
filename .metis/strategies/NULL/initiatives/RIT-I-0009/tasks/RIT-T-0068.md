# Engine merge hook: project alias file over seed lexicon (terms + matching/ats)

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0009]]

## Objective **[REQUIRED]**

Give the deterministic matcher the ability to load a **project alias file** and MERGE it on top of the
packaged seed lexicon (RIT-I-0008), so a user/project vocabulary compounds over time. This is the
load-bearing substrate for RIT-I-0009: the file format, the merge semantics, and the loader hook that
`matching` and `ats` use to build their effective `AliasIndex`.

Scope is the engine only (no surfaces, no plugin skills — those are RIT-T-0069/0070). The change to the
matcher internals is deliberately minimal, as the initiative's non-goals require: add a
project-alias-file MERGE hook, nothing more.

Concrete anchor points:
- `packages/terms/src/resume_kit_terms/aliases.py` — `load_alias_lexicon(path)` (returns
  `dict[str, list[str]]`), `AliasIndex` (built from that mapping), `AliasIndex.load(path)`,
  `DEFAULT_LEXICON_PATH`.
- `packages/matching/src/resume_kit_matching/keywords.py:72` — `_alias_index()` currently
  `AliasIndex.load()`.
- `packages/ats/src/resume_kit_ats/engine.py:39` — `_alias_index()` currently
  `AliasIndex(load_alias_lexicon())`.

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `resume_kit_terms` gains a documented project-alias-file format: same JSON shape as the seed
      (`{"version": 1, "aliases": {canonical: [alias, ...]}}`) with an OPTIONAL per-entry justification
      channel. Because the seed schema maps `canonical -> [alias]`, the `why` justification is carried in
      a separate, back-compatible way (e.g. a sibling `"justifications": {canonical: "why"}` object OR a
      richer entry form) — pick ONE, document it in `data/FORMAT.md`, and keep `load_alias_lexicon`
      able to read BOTH seed and project files. Justifications are metadata: they never affect matching.
- [ ] A merge/loader API in `resume_kit_terms` builds an **effective** `AliasIndex` from the packaged
      seed PLUS an optional project file: e.g. `load_effective_alias_index(project_path: Path | None)` or
      `AliasIndex.load_merged(project_path=...)`. Conflict semantics are UNION by default (project
      aliases are added to the seed groups / new groups created); if a project entry would merge two
      existing seed canonicals it is resolved deterministically and documented (reuse the existing
      `LexiconError` "term maps to two canonicals" guard where a true conflict is ambiguous, OR define
      and document a deterministic winner). Document the chosen rule in FORMAT.md.
- [ ] A missing / absent project file is a NO-OP (effective index == seed); an empty/whitespace path is
      also a no-op. Malformed project file raises `LexiconError` (same as the seed loader) — never a
      silent partial load.
- [ ] Path resolution: the engine reads the project-alias path from an explicit argument AND, when not
      passed, from an env var (e.g. `RESUME_KIT_ALIAS_FILE`). The env indirection keeps
      `calculate_keyword_match` / `compute_ats_score` signatures unchanged while letting surfaces point
      at the file (RIT-T-0069 sets it). Document precedence: explicit arg > env > seed-only.
- [ ] `matching._alias_index()` and `ats._alias_index()` build the EFFECTIVE (seed + project) index via
      the new API. Both remain module-cached, but the cache must key on the resolved path (or be
      invalidatable) so tests with different project files don't get a stale index — document the caching
      approach; determinism for a FIXED file/path is preserved.
- [ ] Determinism (NFR-902): for a fixed seed + fixed project file, the effective index and all matches
      are reproducible; no set-ordering leaks into group membership or provenance.
- [ ] New tests in `packages/terms/tests` (merge/union, conflict rule, missing-file no-op, malformed
      raises, env-var resolution, determinism) AND a matching + ats test each proving a project-file
      alias produces a match that the seed alone would miss. Existing terms/matching/ats tests stay green.
- [ ] `ruff` + `mypy --strict` clean; full suite green.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + high` — Core substrate for the whole initiative: defines the project-file format, the merge
semantics, the caching/determinism contract, and the loader hook that RIT-T-0069/0070/0071 all build on.
A wrong choice here (conflict rule, cache keying, env precedence) compounds across every downstream task
and every surface. This is the initiative's foundational task.

### Technical Approach
- Extend `load_alias_lexicon` (or add a sibling loader) to accept the project file and to tolerate the
  justification channel; keep the seed path working unchanged.
- Add `load_effective_alias_index(project_path=None)` in `resume_kit_terms` that: loads the seed mapping,
  loads the project mapping if the resolved path exists, unions them into one mapping, and constructs a
  single `AliasIndex`. Resolve `project_path` from arg, else `os.environ.get("RESUME_KIT_ALIAS_FILE")`,
  else None (seed-only).
- Export the new symbol(s) from `resume_kit_terms.__init__` and add to `__all__`.
- In `matching`/`ats`, replace the `_alias_index()` bodies to call the effective loader. Handle caching
  so a changed env/path is respected in tests (e.g. cache keyed by resolved path string, or a small
  `functools.lru_cache` over the path).
- Update `packages/terms/src/resume_kit_terms/data/FORMAT.md` with the project-file format,
  justification channel, merge/conflict rule, and env-var precedence.

### Dependencies
- Depends on: RIT-I-0008 (terms package, seed lexicon, AliasIndex) — DONE.
- Blocks: RIT-T-0069 (surfaces set the path), RIT-T-0070 (skills append to the file), RIT-T-0071
  (integration proof).
- Coordinates with RIT-I-0008-owned files `matching/keywords.py` + `ats/engine.py` — the merge hook is
  the ONLY allowed change to matcher internals (initiative non-goal).

### Risk Considerations
- **Non-determinism via cache**: a module-level cache that ignores the path returns a stale index across
  tests/surfaces. Key the cache on the resolved path and document it. (NFR-902 is load-bearing.)
- **Silent partial merge**: a malformed project file must raise, not partially load — reuse the seed
  loader's validation + `LexiconError`.
- **Conflict ambiguity**: two canonicals colliding must resolve deterministically or raise; never
  order-dependent. Document the rule and test it.
- **Over-reach**: do NOT change matching/ats matching logic beyond the index construction (stemming
  stays OFF — `allow_stem=False` is unchanged; RIT-I-0008 decision).
