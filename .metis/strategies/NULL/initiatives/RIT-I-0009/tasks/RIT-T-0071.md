# Integration test: project-added domain synonym matches end-to-end

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0009]]

## Objective **[REQUIRED]**

Prove the initiative's exit criteria end-to-end: a domain synonym NOT in the packaged seed (e.g.
NetSuite↔SuiteCommerce), added to a project alias file, makes a previously-MISSED JD keyword match —
deterministically, and with a missing-file no-op baseline. This is the "it compounds" proof.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] Integration test (under `tests/integration/`) that: (a) confirms a domain pair NOT in the seed is
      a GAP/absent with seed-only scoring (baseline, no project file); (b) writes a temp project alias
      file adding that pair with a `why`; (c) with the project file active (via the RIT-T-0068 path/env
      hook), the previously-missing JD keyword now matches and is no longer reported as a gap, and
      `keyword_match`/`skills_coverage` rise vs the baseline (assert direction, not brittle floats).
- [ ] Missing-file no-op assertion: no project file → results identical to seed-only baseline for
      matching AND ats.
- [ ] Determinism: with the fixed project file, two runs yield identical scores + `matched_keywords`
      (kind reported as `alias:<canonical>` for the project-added synonym).
- [ ] At least one surface-level assertion (through the facade or an adapter) that honoring the config
      `alias_file` (RIT-T-0069) produces the same match — proving the grown index reaches surfaces, not
      just the engine. (If 0069 is not yet merged when this runs, cover the engine + env path and note
      the surface assertion as depending on 0069.)
- [ ] Anti-inflation guard: a project file that (incorrectly) tried to alias two DISTINCT skills is
      rejected/raises per the RIT-T-0068 conflict rule, OR — since the file is user-authored — a test
      documents that only genuine same-group unions take effect (mirrors the truth posture; distinct
      skills never silently merge).
- [ ] `ruff` + `mypy --strict` clean; full suite green.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`sonnet + medium` — Test-authoring task following the RIT-T-0066 integration pattern; the reasoning
(what to assert, baseline vs project-file direction, determinism, no-op) is defined here. Needs to wire
the RIT-T-0068 path/env hook and possibly a surface call, so `medium` not `low`; no core design.

### Technical Approach
- Mirror `tests/integration/test_synonym_integration.py` (RIT-T-0066) for fixture + assertion style;
  build a synthetic resume/JD where the resume uses one domain term and the JD uses its synonym.
- Use a `tmp_path` project alias file and point the engine at it via the RIT-T-0068 mechanism (explicit
  arg preferred; `RESUME_KIT_ALIAS_FILE` if that's the only path — set/reset in a fixture to avoid
  leakage).
- Assert gap-present/absent + kind + monotonic score direction rather than exact floats (seed/lexicon
  may evolve).
- Avoid any docstring/comment line STARTING with `from <word>` (boundary-test regex false-positive; see
  RIT-I-0008 landmine in `.agents/work-log.md`).

### Dependencies
- Depends on: RIT-T-0068 (engine hook + format) — required. RIT-T-0069 (surfaces) — needed for the
  surface-level assertion; degrade gracefully if not yet merged. RIT-T-0070 format alignment for the
  file the test writes.
- This is the join-point / exit proof for RIT-I-0009.

### Risk Considerations
- **False confidence**: the baseline (no project file) must genuinely show the gap, else the test proves
  nothing — assert the baseline miss explicitly.
- **Env leakage across tests**: scope `RESUME_KIT_ALIAS_FILE` in a fixture with teardown.
- **Cache staleness**: if the RIT-T-0068 index cache keys on path, ensure the test's temp path is
  respected (distinct path per test).

### Verification Steps

2. `uv run --no-sync ruff check packages tests && uv run --no-sync mypy packages`.
3. `uv run --no-sync pytest packages integrations plugins tests` — full suite green.
