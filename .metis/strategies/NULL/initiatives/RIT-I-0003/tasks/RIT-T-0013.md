# Define parser result models

## Parent Initiative

[[RIT-I-0003]] — Phase 2 — Document Extraction & Parsing

## Objective

Create the package-local result contracts for extracted text, structured parse output, confidence, warnings, and provenance. This is new resume-kit surface area and should compose existing core and schemas types rather than duplicating them.

## Acceptance Criteria

- [ ] Result models represent extracted Markdown text, optional `ResumeDocument`, confidence in `[0.0, 1.0]`, warnings, and provenance for deterministic and LLM-produced parts.
- [ ] Models reuse `resume_kit_core.errors.CoreWarning` and `resume_kit_core.response.ProvenanceRef` where practical, and `resume_kit_schemas.ResumeDocument` for structured resumes.
- [ ] No upstream attribution marker is used for wholly new result models, but docstrings make the deterministic-vs-LLM provenance methods clear.
- [ ] Tests cover defaults, confidence bounds, no-LLM unavailable signaling, and serialization via Pydantic v2.

## Implementation Notes

Recommended Agent: sonnet + medium
Implement new models in `results.py`; likely shapes: `ParseMethod` enum (`deterministic`, `llm`), `TextExtractionResult`, `StructuredParseResult` or unified `ParseResult`. Prefer Pydantic v2 `BaseModel`/`Field`, strict types, and frozen value objects only where useful. Keep warnings as `CoreWarning` to satisfy the initiative's core taxonomy requirement; use `ProvenanceRef` for source lineage metadata such as filename, method, and upstream-derived parser identifiers.
