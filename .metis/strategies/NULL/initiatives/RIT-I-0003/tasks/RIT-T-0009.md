# Scaffold document-parser workspace package

## Parent Initiative

[[RIT-I-0003]] — Phase 2 — Document Extraction & Parsing

## Objective

Create the new `packages/document-parser` package first so all later tasks can add modules and tests against a real workspace member. This is mostly mechanical and should mirror `packages/core` and `packages/schemas` conventions.

## Acceptance Criteria

- [ ] `packages/document-parser` builds as package name `resume-kit-document-parser` with import package `resume_kit_document_parser`.
- [ ] Package depends only on `resume-kit-core`, `resume-kit-schemas`, `markitdown[docx]`, and `pdfminer.six` as runtime dependencies.
- [ ] `__init__.py` imports cleanly without importing heavy parser modules eagerly if avoidable.
- [ ] `py.typed` is present and included in the wheel.

## Implementation Notes

Recommended Agent: haiku + low
Mirror `packages/core/pyproject.toml` and `packages/schemas/pyproject.toml`: `hatchling`, Python `>=3.12`, workspace sources for `resume-kit-core` and `resume-kit-schemas`, wheel package path `src/resume_kit_document_parser`. The root workspace already uses `members = ["packages/*"]`, so avoid root `pyproject.toml` edits unless verification proves they are required. Keep `__init__.py` minimal now; the public API exports are completed in the structured adapter task.
