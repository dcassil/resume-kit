# Implement core provider, response, and artifact contracts

## Parent Initiative

[[RIT-I-0002]] — Phase 1 — Clean Core & Canonical Schemas

## Objective

Implement the Phase 1 `core` package as dependency-inversion contracts only. This package defines provider/storage Protocol boundaries and shared response/error abstractions used by later phases, but it must not implement concrete LiteLLM, parsing, matching, scoring, ATS, alignment, export, persistence, CLI, MCP, API, or frontend behavior.

## Acceptance Criteria

- [ ] `StructuredCompletionProvider` is a `Protocol` with async `complete_json(request: StructuredCompletionRequest) -> dict[str, Any]` or an equivalently typed JSON-object result.
- [ ] An LLM-agnostic completion boundary exists with typed request metadata, provider/model options, deterministic test hooks, timeout/retry metadata as data only, and no concrete provider imports.
- [ ] Artifact/storage Protocols exist for writing/reading generated artifacts or artifact references without persistence implementation details leaking into core.
- [ ] A generic `InterfaceResponse[T]` envelope exists with `data`, `warnings`, `errors`, `requires_human_input`, `questions`, `artifacts`, and `provenance` fields; it is typed, documented, serializable, and usable with schema payloads.
- [ ] Core warning/error/provenance/question/artifact value types are Pydantic v2 models or typed dataclasses with strict mypy-compatible annotations.
- [ ] A fake in-memory structured completion provider exists under `resume_kit_core.testing` or package-local tests and is used by contract tests; tests make no network or LLM calls.
- [ ] `resume_kit_core.__init__` exports the public Protocols and value types.
- [ ] No concrete LiteLLM, provider SDK, database, filesystem persistence, parser, matching, scoring, ATS, alignment, export, CLI, MCP, API, frontend, or upstream `app.*` import is introduced.

### Technical Approach
Use `typing.Protocol`, `TypeVar`, `Generic`, `Mapping`, and explicit Pydantic v2 models where they improve validation. Keep provider outputs JSON-compatible and deterministic. The upstream direction to invert is from `upstream/apps/backend/app/llm.py` and services that call `app.llm.complete_json`, but do not port `llm.py` in Phase 1; only define the contract that Phase 2+ adapters will implement. Core may depend on `resume_kit_schemas` for shared schema payload/provenance/artifact model types if the scaffold has declared that dependency, but avoid requiring schema implementation details in provider contracts so this task can be worked in parallel with schemas.
