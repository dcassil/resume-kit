# Implement canonical schemas and upstream schema characterization

## Parent Initiative

[[RIT-I-0002]] — Phase 1 — Clean Core & Canonical Schemas

## Objective

Implement the Phase 1 `schemas` package. It must define canonical Pydantic v2 domain models separated from transport/HTTP DTOs, while porting/adapting only the upstream schema material classified Extract in Phase 0. The upstream file `upstream/apps/backend/app/schemas/models.py` mixes reusable domain models with web/API DTOs; split it so `resume_kit_schemas` contains domain contracts only.

## Acceptance Criteria

- [ ] Canonical documented Pydantic v2 models exist for `ResumeDocument`, `JobDescription`, `CandidateEvidence`, `AnalysisReport`, `ChangeProposal`, diff/change-set models, `ClaimProvenance`, warning models, artifact metadata, and generic interface payload primitives needed by Phase 1.
- [ ] Ported/adapted schema behavior is protected by characterization tests for upstream validation/coercion behavior: description string/list coercion, `descriptionStyles` alignment, optional text coercion, `ResumeData`/`ResumeDocument` default filling, `ResumeChange`/`ChangeProposal` list-original validation, and refinement schema bounds/defaults.
- [ ] HTTP/web/application DTOs from upstream are explicitly excluded: do not port `ResumeUploadResponse`, `ResumeFetchResponse`, `ResumeListResponse`, `JobUploadRequest`, `JobUploadResponse`, config/API-key DTOs, health/status DTOs, application tracker DTOs, interview-prep DTOs, router persistence DTOs, or frontend-specific response wrappers.
- [ ] Package exports in `resume_kit_schemas.__init__` expose the public canonical model surface and do not expose upstream `app.*` names as the primary API.
- [ ] Every upstream-derived or adapted schema source/test file includes the attribution comment block required by `references/attribution.md`, with upstream path and pinned SHA `116f9cc3b00e1ac91734a6c2679bf41ea64a0edc`.
- [ ] `references/attribution.md` is updated with the concrete new `packages/schemas` files that port or adapt schema material.
- [ ] No scoring, matching, ATS algorithms, parsing, alignment application, export, storage, CLI, MCP, API, persistence, frontend, network, or LLM behavior is implemented.
