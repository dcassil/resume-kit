# Implement Resume Tool CLI

## Parent Initiative

[[RIT-I-0006]] — Phase 5 — Interfaces

## Objective

Implement packages/cli as a thin Typer adapter over resume_kit_facade. The CLI command names from RIT-I-0006 are extract, extract-job, check-ats, match, select, compare, identify-gaps, align, validate-truth, and build-evidence, corresponding to the 10 facade capabilities. The package must install the resume-tool entry point from packages/cli/pyproject.toml and must never call engine packages directly; all work goes through resume_kit_facade and returns or formats resume_kit_core.InterfaceResponse.

## Acceptance Criteria

- [ ] resume-tool exposes exactly the 10 Phase 5 commands and no deferred Phase 6 commands or stubs.
- [ ] Every command supports --output {json,text,md}, --no-llm where applicable, --strict, --human-in-loop/--non-interactive where applicable, --evidence <path> where applicable, and --config <path> without persisting configuration or resume/job content.
- [ ] Commands read file/JSON inputs into facade request models, call only resume_kit_facade capability functions, and render the returned InterfaceResponse without redefining response, warning, error, provenance, artifact, or question shapes.
- [ ] Exit status comes exclusively from the core exit-code map; requires_human_input uses the reserved human-input exit code, provider-not-configured uses the provider error exit code, and warnings alone remain success unless --strict intentionally maps them through the shared substrate.
- [ ] No-LLM deterministic contract tests pass for text extraction, job text parsing, ATS, job match, select, compare, gaps, truth validation, and evidence building with no provider and no network.
- [ ] Provider-requiring paths without configured provider return the structured provider-not-configured error in JSON output and never raise a traceback in normal usage.
- [ ] Typer CliRunner tests cover command registration, JSON/text/Markdown output, strict mode, human-in-loop surfacing for align, and representative success/error exit codes.

## Implementation Notes

Keep parsing and formatting helpers inside packages/cli only, for example io.py and formatters.py, but do not put business rules there. Use ResumeDocument.model_validate_json/model_validate and JobDescription.model_validate_json/model_validate for JSON inputs. For align, wrap the facade async path with asyncio.run if the facade exposes async functions. Do not construct a real LLM provider in Phase 5; tests should use facade seams or FakeStructuredCompletionProvider only.
