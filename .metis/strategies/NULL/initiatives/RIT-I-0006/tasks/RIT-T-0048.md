# Wire Public Interface Exports

## Parent Initiative

[[RIT-I-0006]] — Phase 5 — Interfaces

## Objective

Finish public API wiring after the substrate, facade, transports, bridge, and plugin files exist. Existing package roots such as packages/core/src/resume_kit_core/__init__.py export stable symbols, and Phase 5 should follow that pattern for new public entry points without forcing implementation tasks to fight over __init__.py files. This task exports the shared interface substrate, facade callables/models, transport app/server objects, and job-hunter bridge callables, plus public export smoke tests.

## Acceptance Criteria

- [ ] resume_kit_core exports the new interface mapping helpers, exit-code map/type, and provider-not-configured helpers added by Extend Core Interface Substrate without dropping existing exports such as InterfaceResponse, Question, StructuredCompletionProvider, and FakeStructuredCompletionProvider compatibility.
- [ ] resume_kit_facade package root exports the 10 facade capability callables, request/options models, and capability registry intended for transports.
- [ ] resume_kit_cli package root exports the Typer app and main entry point used by resume-tool.
- [ ] resume_kit_mcp package root exports the MCP server factory/object and direct handler registry intended for tests/in-process use.
- [ ] resume_kit_api package root exports create_app and app.
- [ ] resume_kit_job_hunter_bridge exports analyze_resume_for_job, align_resume_for_job, validate_truth, and build_evidence or the final stable bridge names.
- [ ] Public export tests import all intended symbols from package roots and assert no unbuilt Phase 6 capability is exported.
- [ ] Final interface-local mypy and pytest commands pass after exports are wired.

## Implementation Notes

This is intentionally late because every package scaffold creates __init__.py but behavior lands in separate module tasks. Keep __all__ explicit and stable, following existing package root style. Do not add business logic in __init__.py files. If a transport module chose slightly different stable function names, export those names and update the tests in this task, but do not rename CLI commands or MCP tool names from the initiative.
