# Add Cross Surface Parity Tests

## Parent Initiative

[[RIT-I-0006]] — Phase 5 — Interfaces

## Objective

Add late parity tests for RIT-I-0006 REQ-508 after CLI, MCP, and API implementations exist. The goal is to prove that CLI, MCP, API, and the direct resume_kit_facade call all expose equivalent core data for the same deterministic inputs. Use Typer CliRunner for CLI, direct handler or in-memory MCP session for MCP, FastAPI TestClient for API, and no network or LLM.

## Acceptance Criteria

- [ ] Parity tests exercise representative deterministic inputs through direct facade, CLI, MCP, and API for check-resume-job-match, check-resume-ats, identify-resume-gaps, validate-resume-truth, and build-candidate-evidence at minimum.
- [ ] Parity tests include extract-job-description and extract-resume no-LLM paths where fixture shape makes deterministic comparison stable.
- [ ] For each tested capability, data payloads are equivalent after normalizing transport serialization differences, and warnings/errors/requires_human_input remain semantically equivalent.
- [ ] Provider-not-configured parity is asserted across CLI, MCP, and API for at least one LLM-requiring path invoked without --no-llm/provider.
- [ ] Human-in-loop align parity asserts each surface returns requires_human_input/questions rather than advancing an interactive loop.
- [ ] Tests are in-process only: CliRunner, MCP direct handler/in-memory session, and FastAPI TestClient; no server ports, provider SDKs, or network calls.

## Implementation Notes

Create local fixtures inside the parity test file or a private helper in tests/interface if needed, but avoid shared package code. Normalize InterfaceResponse JSON by loading into dicts and comparing data/errors/warnings/questions/provenance fields rather than comparing raw stdout or HTTP response objects. Do not change transport implementation files in this task unless a parity bug is found; if fixes are needed, coordinate serially with the relevant surface owner.
