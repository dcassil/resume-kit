# Build Capability Facade Package

## Parent Initiative

[[RIT-I-0006]] — Phase 5 — Interfaces

## Objective

Create the single in-process capability facade that all transports call. The facade cannot live in packages/core without creating dependency cycles because existing engine packages depend on resume-kit-core, so place it in a small dedicated workspace package packages/facade exposing resume_kit_facade. It must wrap exactly these engine public APIs: resume_kit_document_parser.parse_resume_structured and extract_resume_text_only, resume_kit_job_parser.parse_job_description and parse_job_description_text_only, resume_kit_ats.compute_ats_score, resume_kit_matching.check_job_match, select_best, compare_versions, and analyze_keyword_gaps, resume_kit_alignment.align_resume, and resume_kit_evidence.validate_resume_truth and build_candidate_evidence. Every callable returns resume_kit_core.InterfaceResponse via the core substrate from Extend Core Interface Substrate.

## Acceptance Criteria

- [ ] packages/facade is a typed Hatchling workspace package named resume-kit-facade with import package resume_kit_facade, py.typed, README, and package-local tests; uv sync can resolve it from the packages/* workspace wildcard.
- [ ] The facade provides one uniform callable per exposed capability: extract-resume, extract-job-description, check-resume-ats, check-resume-job-match, select-best-resume, compare-resume-versions, identify-resume-gaps, align-resume, validate-resume-truth, and build-candidate-evidence.
- [ ] Facade request/config models are transport-agnostic and typed with resume_kit_schemas models such as ResumeDocument, JobDescription, AlignmentResult, TruthReport, ATSScore, JobMatchReport, KeywordGapAnalysis, ResumeSelectionResult, ResumeComparisonResult, and CandidateEvidence.
- [ ] No-LLM deterministic mode works for extract-resume via extract_resume_text_only, extract-job-description via parse_job_description_text_only, ATS/matching/select/compare/gaps/truth/evidence via deterministic engine calls, and align-resume via an explicit deterministic no-change path only when no_llm is true.
- [ ] LLM-requiring calls made without a StructuredCompletionProvider return the stable provider-not-configured InterfaceResponse error from the core substrate instead of calling the engine or crashing.
- [ ] align-resume correctly awaits the async resume_kit_alignment.align_resume engine function; tests use FakeStructuredCompletionProvider from packages/core/src/resume_kit_core/testing.py for provider paths.
- [ ] Facade tests assert that the facade is the only place transport tasks need to call engine functions directly and that no transport dependency is imported by resume_kit_facade.

## Implementation Notes

Use a new package rather than core because core already sits below document-parser, job-parser, ats, matching, evidence, and alignment in the dependency graph. Suggested files are models.py for request/options models and capabilities.py for individual functions plus a stable capability registry. For check-resume-ats, compute KeywordGapAnalysis with analyze_keyword_gaps(job, resume, resume), pass gap.current_match_percentage, gap.non_injectable_keywords, and gap.injectable_keywords into compute_ats_score. Keep provider construction out of the facade; accept provider: StructuredCompletionProvider | None. Do not expose deferred Phase 6 capabilities or stubs.
