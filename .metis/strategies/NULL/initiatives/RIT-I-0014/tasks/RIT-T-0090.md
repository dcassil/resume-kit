# Add resume-tool extract-text deterministic extraction primitive across surfaces

## Parent Initiative

[[RIT-I-0014]]

## Objective **[REQUIRED]**

Expose a first-class, clearly-named deterministic extraction primitive `resume-tool extract-text` that returns the raw text of a resume/job file (docx/pdf/md/txt) with no LLM and no network. This is the EXTRACTION rail the rewritten ingest skills ([[RIT-T-0093]]) hand to the interpretation subagent, replacing agent raw-file-reading.

## Context

The engine already has the deterministic function (`extract_resume_text` / `extract_resume_text_only` in `packages/document-parser/src/resume_kit_document_parser/text_extraction.py`), but the only CLI exposure is `extract`, which is oriented at producing a structured `ResumeDocument` (and returns `document=None` on `--no-llm`). There is no obvious "just give me the text" command, so the skill routes around the CLI entirely. Naming the primitive `extract-text` makes the EXTRACTION step discoverable and unambiguous.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] New facade capability (e.g. `extract_resume_text`) in `packages/facade/src/resume_kit_facade/capabilities.py` returning a `TextExtractionResult` (text + warnings + method), delegating to the existing document-parser function — no LLM, no network.
- [ ] New CLI command `resume-tool extract-text <file>` (and, symmetric with `extract`/`extract-job`, accept `-` for stdin bytes) in `packages/cli/src/resume_kit_cli/app.py` that prints the result as JSON.
- [ ] MCP tool + API route added where the cross-surface parity norm applies (mirror how `extract`/`extract-job` are surfaced); if a surface is intentionally skipped, state why in Status Updates.
- [ ] Works deterministically for `.docx`, `.pdf`, `.md`, `.txt` with the base wheel only (no optional extras).
- [ ] Cross-surface parity test asserting CLI / facade (/ MCP / API) return equivalent extraction for the same input, consistent with existing parity tests.
- [ ] Public exports wired (mirroring prior "Wire Public Exports" tasks).

## Implementation Notes **[REQUIRED]**

### Technical Approach
Thin transport work: facade capability delegating to the existing text-extraction function, Typer command wrapping it, MCP/API adapters mirroring `extract-job`. Reuse the existing `TextExtractionResult`/result-envelope shape rather than inventing a new one. Follow the file-path/stdin handling already used by `extract`.

### Dependencies
Engine function already exists. No dependency on other tasks; [[RIT-T-0093]] depends on this. Ordering: do after/with [[RIT-T-0089]].

### Risk Considerations
Low–moderate. Main care point is matching the established cross-surface parity pattern so this doesn't become an outlier; follow the `extract-job` precedent closely.

### Recommended Agent
`opus + medium` — multi-file integration across facade/CLI/MCP/API with a parity-test norm to preserve; follows a known pattern but touches several surfaces and must stay consistent with existing conventions.
