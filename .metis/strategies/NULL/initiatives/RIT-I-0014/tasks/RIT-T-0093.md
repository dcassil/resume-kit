# Rewrite resume-to-json / job-to-json around the gated pipeline + workflow step

## Parent Initiative

[[RIT-I-0014]]

## Objective **[REQUIRED]**

Rewrite `resume-to-json` and `job-to-json` so they orchestrate the gated pipeline instead of making the agent the extractor+converter+self-checker. New contract: **`extract-text` (script) → agent maps text→JSON (confined subagent) → `validate-faithfulness` (script HARD GATE) → `set-active` (script)**, and name the gate as an explicit step in `resume-workflow`. Demotes the agent from "converter" to "interpreter between two deterministic gates."

## Context

`resume-to-json` currently says *"You (the agent) are the converter"* and folds extraction + interpretation + faithfulness self-check into one hand-authored step, with faithfulness enforced only by prose. This task lands the new rails from [[RIT-T-0090]] (extract-text), [[RIT-T-0091]] (init/set-active + source path), and [[RIT-T-0092]] (validate-faithfulness) into the skill flow. Resumes and jobs are handled symmetrically — `job-to-json` has the identical problem.

## Acceptance Criteria **[REQUIRED]**

- [ ] `resume-to-json/SKILL.md` rewritten to the pipeline: (1) call `extract-text` on the source; (2) hand the **extracted text + schema** to a confined interpretation subagent whose ONLY job is text→`ResumeDocument` mapping; (3) run `validate-faithfulness` as a blocking gate; (4) on pass, write `-original.json` and call `set-active` (recording the source path); on gate failure, hand the diff back to the subagent and loop **once**, then surface to the user if still failing.
- [ ] The existing prose Faithfulness Gates are retained but reframed as **guidance for the interpretation subagent**, with `validate-faithfulness` named as the authoritative machine gate.
- [ ] `job-to-json/SKILL.md` rewritten symmetrically for job descriptions.
- [ ] `resume-workflow/SKILL.md` steps 1–2 updated to name the extract-text → interpret → validate-faithfulness → set-active sequence and the gate.
- [ ] The subagent contract is documented: inputs = extracted text + schema + target save path; output = saved path + summary + gate result; must not write `-original.json` until the gate passes.
- [ ] No skill instructs the agent to read the raw binary file as the primary extraction path (fallback-only, with a note).
- [ ] `resume-kit/learning/*.md` guidance preserved/updated to point at the new flow.

## Implementation Notes **[REQUIRED]**

### Technical Approach
Skill-authoring task (prose + command wiring), not engine code. Keep the strong existing "learnings & gotchas" and schema reference — they become the interpretation subagent's brief. Make the pipeline the spine and the agent one confined step. Ensure the skill calls `set-active` rather than telling the agent to hand-edit config.json.

### Dependencies
Depends on [[RIT-T-0090]], [[RIT-T-0091]], [[RIT-T-0092]] (references their commands). Should merge after all three. [[RIT-T-0089]] is the interim doc fix this supersedes.

### Risk Considerations
Risk of the skill drifting from actual command signatures — mitigate by writing it against the merged CLI and doing the TC-002 dry-run. Keep the subagent guidance strong so interpretation quality doesn't regress now that the agent is more constrained.

### Recommended Agent
`opus + medium` — multi-file skill rewrite that must stay faithful to the new CLI contracts and preserve interpretation quality; substantive integration work following the now-known pattern.
