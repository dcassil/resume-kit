# Fix extraction docs/skill contradiction and steer to deterministic CLI

## Parent Initiative

[[RIT-I-0014]]

## Objective **[REQUIRED]**

Fix the documentation/skill contradiction that steers the ingest agent away from the deterministic extraction CLI, and correct the false claim that PDF extraction needs an optional extra. This is the fastest, highest-leverage fix — on its own it would have prevented the tester's raw-zip/XML improvisation incident — and it ships independently of any code change.

## Context

The `resume-to-json` skill tells the agent *"You (the agent) are the converter… no LLM provider and no PDF library required"* and, under "Optional: the deterministic text extractor", claims a **PDF** needs the optional `markitdown[pdf]` extra. This contradicts the README, which lists `markitdown`, `pdfminer.six`, and `python-docx` as **base** wheel dependencies — extraction of docx/pdf/md/txt is already deterministic and bundled (`packages/document-parser/src/resume_kit_document_parser/text_extraction.py`). The contradiction is the likely reason the agent never reached for `resume-tool extract` and hand-rolled zip/XML parsing instead. `job-to-json` and `commands/setup.md` have the same steering problem.

This task is documentation-only. It does NOT rewrite the pipeline (that is [[RIT-T-0093]]) — it only removes the contradiction and points the EXTRACTION step at the deterministic CLI so the skills are correct in the interim.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `plugins/resume-intelligence/skills/resume-to-json/SKILL.md` no longer claims PDF extraction requires `markitdown[pdf]`; it states docx/pdf/md/txt extraction is deterministic and bundled in the base install.
- [ ] The same skill steers the EXTRACTION step to the deterministic CLI (`resume-tool extract --no-llm`, or `extract-text` once [[RIT-T-0090]] lands) as the primary path, with agent file-reading as fallback only.
- [ ] `plugins/resume-intelligence/skills/job-to-json/SKILL.md` receives the equivalent correction.
- [ ] `plugins/resume-intelligence/commands/setup.md` "Optional: PDF support" section is corrected/removed so it does not imply base install lacks PDF/DOCX extraction.
- [ ] README wording (if it repeats the optional-extra claim anywhere) is reconciled with the base-deps list.
- [ ] A grep across `plugins/` and `README.md` for `markitdown[pdf]` shows only accurate, consistent statements (extra is genuinely optional only for whatever it actually adds, if anything, per the base deps).
