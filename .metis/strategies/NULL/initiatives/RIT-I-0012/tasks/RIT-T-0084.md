# Dev debug/refine runbook reusing the review step (codex option, findings→Metis)

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0012]]

## Objective **[REQUIRED]**

Author the lightweight, repo-level DEV debug/refine loop that reuses the `review-tailored-resume` step to
run trial pairs (real resume + JD) through the pipeline, critique the output (optionally with an
independent `codex exec` reviewer), and convert actionable findings into TOOLKIT improvements tracked in
Metis. "A simple thing that uses that" — a runbook, not new machinery, and NOT a shipped user skill.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `docs/dev/debug-refine.md` (repo-level; NOT under `plugins/.../skills/`, so it is not a shipped
      user skill) documents the loop end-to-end:
      1. Pick a trial pair (real resume + JD) placed under a dev fixtures dir (e.g. `.agents/trials/<name>/`
         with `resume.<ext>` + `job.txt`); note these are dev inputs, git-ignored if they contain personal
         data (state the .gitignore guidance).
      2. Run the pipeline: `resume-to-json` → `job-to-json` → check/gaps → improve
         (`inject-keywords`/`update-terminology`) → produce the tailored resume.
      3. Run `review-tailored-resume` on new+original+JD. Show BOTH the default subagent path and the
         optional independent reviewer via `codex exec` (exact command form: `codex exec -s workspace-write`
         style, stdin from the three artifacts) for a second-model perspective.
      4. Read the structured findings from `resume-kit/review/<session>.md` (the RIT-T-0082 layout).
      5. Triage: for each actionable finding that indicates a TOOLKIT gap (a skill missed something, a
         check is too weak/too strict, an engine capability is needed), file a Metis BACKLOG task
         (document the `mcp__metis__create_document` backlog usage); discard noise.
      6. Append a trial entry to a dev log (e.g. `.agents/refine-log.md`): trial name, date, scores
         before/after, key findings, and the Metis task ids filed.
- [ ] The runbook is explicit that this is dev-only and reuses the shipped review step (no new shipped
      skill); the "changes/additions" target is the TOOLKIT (skills/engine), not the candidate's resume.
- [ ] Include a short "first trial" checklist so the owner can run one real pair immediately (the actual
      run with real data is the owner's to perform; do not fabricate resume/JD data).
- [ ] Add `.agents/trials/` (and any personal-data paths) to `.gitignore` guidance so real resumes/JDs are
      not committed.
