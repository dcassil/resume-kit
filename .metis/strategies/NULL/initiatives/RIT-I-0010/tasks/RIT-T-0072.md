# TerminologyAlignment schema + deterministic analyzer over alias provenance

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0010]]

## Objective **[REQUIRED]**

Add the `TerminologyAlignment` result schema and a DETERMINISTIC analyzer that turns RIT-I-0008 match
provenance into "mirror the employer's exact wording" suggestions. Foundational data + logic task;
RIT-T-0073 (apply path), 0074 (surfaces), 0075 (skill), 0076 (integration) all build on it.

**Reconciliation (see initiative note):** stemming is OFF, so the ONLY non-exact match kind at runtime is
`alias`. The analyzer keys off `matched_keywords` entries with `kind == "alias"` — a JD keyword the resume
satisfies under a DIFFERENT surface form (the alias). Exact hits → no suggestion. No-match keywords → gaps
(NOT suggestions). No stem handling.

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] New `TerminologyAlignment` model in `resume_kit_schemas` (minimal, frozen): `jd_keyword: str`
      (employer's exact wording — the proposed target), `current_wording: str` (the resume's alias surface
      form), `locations: list[str]` (dot+bracket resume paths where the current wording occurs, e.g.
      `workExperience[0].description[1]`), `canonical: str` (alias group canonical, from provenance),
      `match_kind: Literal["alias"]` (only alias today; keep the field forward-compat). Exported from
      `resume_kit_schemas.__init__` + `__all__`.
- [ ] A deterministic analyzer (in `packages/matching`, e.g. `analyze_terminology_alignment(job, resume)
      -> list[TerminologyAlignment]`) that runs the synonym-aware keyword analysis (reusing RIT-I-0008
      provenance from `analyze_keyword_gaps`/`calculate_keyword_match`), and for each JD keyword matched
      via `alias`, LOCATES the resume occurrence(s) of the current surface form and emits a
      `TerminologyAlignment` with the JD keyword as the proposed wording.
- [ ] Only `alias` hits yield suggestions (REQ-1001): exact hits yield NONE; no-match keywords yield NONE
      (they remain gaps via `analyze_keyword_gaps`). The analyzer never invents a suggestion for a keyword
      the resume does not actually satisfy.
- [ ] Location-finding is deterministic and whole-term (reuse RIT-I-0008 normalization/surface-form + the
      same whole-term matching the engine uses — NOT substring), returns paths in stable sorted order, and
      handles a term occurring in multiple fields.
- [ ] If the resume's current wording is ALREADY the JD's exact wording (differ only by case/punct/space,
      i.e. an `exact` surface match), NO suggestion is produced (nothing to mirror).
- [ ] Deterministic: identical inputs → identical suggestion list. `mypy --strict` + `ruff` clean;
      existing matching/schemas tests stay green.
- [ ] Tests: alias hit → suggestion (correct jd_keyword/current_wording/canonical/locations); exact →
      none; no-match → none (still a gap); multi-location; already-mirrored → none; determinism.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + high` — Defines the new domain type + the deterministic analyzer every other task consumes (accept
path maps it to a ChangeProposal; surfaces expose it; skill presents it; integration asserts it).
Location-finding + the "only alias, never no-match" invariant are subtle and load-bearing (a wrong
emission could later drive a fabricated rewrite). Foundational → high.

### Technical Approach
- Reuse `packages/matching/src/resume_kit_matching/keywords.py` + its `matched_keywords` provenance
  (`resume_kit_schemas.MatchedKeyword{keyword, kind, canonical}`). Read it first. JD keyword =
  `MatchedKeyword.keyword`; the resume's current surface form is the resume token that matched via alias —
  locate it by walking resume dict fields, tokenizing with `resume_kit_terms.surface_form`, finding where
  the alias-group member appears.
- Use `resume_kit_terms` (`normalize`/`surface_form`/`AliasIndex`/`match(..., allow_stem=False)`) for the
  whole-term comparison + canonical resolution; do not reimplement.
- Put `TerminologyAlignment` in `schemas` (shared by surfaces + apply path); transport-free domain model.
- Analysis-only: NO mutation, NO policy/truth calls here (that is RIT-T-0073).

### Dependencies
- Depends on: RIT-I-0008 (provenance + terms) and RIT-I-0009 (alias index — grown aliases also produce
  `alias` hits, so terminology alignment benefits automatically) — both DONE.
- Blocks: RIT-T-0073, 0074, 0075, 0076.

### Risk Considerations
- **Emitting a suggestion for a non-satisfied keyword** would later enable a fabricated rewrite — emit
  ONLY for genuine `alias` hits; assert no-match/exact produce nothing.
- **Substring false-locations**: locate whole-term via the shared normalizer, not `str.find`.
- **Non-determinism**: sort locations + suggestions; no set-order leakage.
