# Accept suggestion → ChangeProposal → policy/apply/truth path + score deltas

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0010]]

## Objective **[REQUIRED]**

Turn an ACCEPTED `TerminologyAlignment` suggestion (from RIT-T-0072) into a truth-safe applied change:
map it to a `ChangeProposal` that swaps ONLY the surface term, route it through the existing Phase-4
alignment engine (policy gate → apply → truth validation), and report the deterministic before/after
score delta. This is the load-bearing truth-safety task — the invariant "no fabrication, no identity/date
edits, claim unchanged" must hold by construction and be adversarially tested.

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] A deterministic function maps an accepted `TerminologyAlignment` + target location to a
      `resume_kit_schemas.ChangeProposal` with `action="replace"`, `path` = the resume occurrence path,
      `original` = current wording (for the replace-verification gate), `value` = the JD's exact wording,
      `reason` = mirror-employer-terminology rationale. The swap changes ONLY the surface term; the
      surrounding text/claim is preserved.
- [ ] Acceptance runs through the EXISTING engine — `resume_kit_alignment.apply_diffs(...)` (which calls
      `resume_kit_policy.evaluate_change_policy` per change) at LOW freedom, then
      `resume_kit_evidence.validate_resume_truth(resume, evidence)` must still PASS (the claim is
      unchanged). No parallel truth/policy logic (NFR-1003). Identity/employer/date/name fields are never
      targeted (guaranteed by the policy gate rejecting blocked paths at every freedom level).
- [ ] REQ-1003 enforced: a JD keyword with NO match can NEVER become a terminology change — the accept
      path only accepts `TerminologyAlignment` records (which by RIT-T-0072 exist only for alias hits);
      there is no code path from a gap/no-match keyword to a `ChangeProposal` here.
- [ ] REQ-1005: report the deterministic before/after `keyword_match` + `skills_coverage` delta for an
      accepted suggestion (recompute with the deterministic scorers pre/post apply). The mirrored wording
      should keep OUR synonym-aware score ~equal while raising the literal-match likelihood (assert the
      swap happened + score does not drop; do not assert brittle exact floats).
- [ ] NFR-1001 adversarial tests (load-bearing): (a) an accepted terminology swap changes only the surface
      term and `validate_resume_truth` still passes; (b) attempting to route a no-match keyword (e.g. an
      absent `Kubernetes`) through the accept path produces NO change / is rejected — a fabricated term can
      never be produced; (c) a swap targeting a blocked factual field (employer/title/date) is rejected by
      the policy gate.
- [ ] Deterministic; `ruff` + `mypy --strict` clean; existing alignment/policy/evidence tests stay green.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Recommended Agent
`opus + high` — The truth-safety join between the analyzer and the Phase-4 alignment/policy/evidence gates.
The NFR-1001 invariant (no fabrication, claim unchanged, no identity edits) is the whole point of the
product's truth posture; getting the ChangeProposal shape, freedom level, and gate wiring right is
load-bearing. Reuses existing gates (no new truth logic) but the composition is subtle → high.

### Technical Approach
- Read `packages/alignment/src/resume_kit_alignment/apply.py` (`apply_diffs` signature: returns
  `(result_dict, applied, rejected)`; gates each change via policy; low `freedom`), `packages/schemas/.../change.py`
  (`ChangeProposal`: `path`, `action`, `original`, `value`, `reason`; `replace` action; list `original`
  only for reorder), `packages/policy/.../path_policy.py` (`evaluate_change_policy`), and
  `packages/evidence/.../truth.py` (`validate_resume_truth(resume, evidence) -> TruthReport`).
- Implement the mapper + an accept function (likely in `packages/alignment` or `packages/matching` —
  choose based on dependency direction; alignment already depends on schemas/policy). Use a LOW freedom
  level appropriate for surface wording (read the freedom ladder in policy; surface-term edits of a real
  skill are low-freedom allowed, identity/date always blocked).
- Compute before/after deltas by calling the deterministic scorers (`calculate_keyword_match` /
  `_compute_skills_coverage` via the ats/matching public paths) on pre/post resumes.
- Do NOT invoke any LLM/provider — the swap is a deterministic substitution.

### Dependencies
- Depends on: RIT-T-0072 (the `TerminologyAlignment` type + analyzer). Must land first.
- Blocks: RIT-T-0074 (surfaces expose accept + delta), 0076 (integration asserts truth-safety end-to-end).

### Risk Considerations
- **Fabrication leak** (NFR-1001): the ONLY input is a `TerminologyAlignment` (alias-backed); never accept
  a raw keyword. Adversarially test that a no-match keyword can't produce a change.
- **Claim drift**: the swap must be surface-only; `validate_resume_truth` must pass post-swap — test it.
- **Wrong freedom/blocked field**: verify the policy gate rejects identity/date/employer targets.
- **Non-determinism**: deterministic deltas; stable ordering.
