# Plugin skill: section-by-section terminology-alignment review (human-in-loop)

## Parent Initiative **[CONDITIONAL: Assigned Task]**

[[RIT-I-0010]]

## Objective **[REQUIRED]**

Add a plugin skill that presents terminology-alignment suggestions to the user section-by-section and
applies only the ones they accept — mirroring the employer's exact wording for skills the candidate
genuinely has, never fabricating. Consistent with the plugin's human-in-control posture and the RIT-T-0074
capability/surfaces.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] New skill `plugins/resume-intelligence/skills/align-terminology/SKILL.md` (slug `align-terminology`):
      run the terminology-alignment analysis (via the RIT-T-0074 CLI/MCP surface), present suggestions
      grouped by resume section, and for each ask the user to accept/skip; apply accepted ones via the
      surface and report the before/after keyword-match delta. Frontmatter mirrors sibling skills exactly.
- [ ] Truth posture in the skill text: only surface-term MIRRORS of skills the candidate genuinely has;
      a JD keyword with NO match is a GAP (surface it, never rewrite it in — link to identify-resume-gaps).
      Explicit DON'T: never turn an absent skill into a claimed one; never edit identity/employer/date
      fields. Note that acceptance is truth-gated by the engine (validate_resume_truth) regardless.
- [ ] Human-in-loop: nothing is applied without explicit per-suggestion user acceptance; a run reports what
      it changed (path, old→new wording, delta). Honor the RIT-I-0009 `alias_file` (read config.json
      `alias_file`, pass through) so grown aliases produce suggestions.
- [ ] Runs in a SUBAGENT per the established convention; reads/writes under the `resume-kit/` working dir;
      updates `active_resume` if it writes a revised resume (consistent with resume-to-json convention).
- [ ] Registered wherever skills are enumerated (e.g. `EXPECTED_SKILL_SLUGS` in the plugin skill tests);
      `claude plugin validate` passes; plugin/skill test set stays green.
