# T5: Flow 4 finalize-resume

## Parent Initiative **[REQUIRED]**

[[RIT-I-0023]]

## Objective **[REQUIRED]**

Create the standalone `finalize-resume` flow for the final job-aware budget/page fit and export. This flow
starts after a tailored resume exists and owns `perfect` plus `export-resume`.

## Acceptance Criteria **[REQUIRED]**

- [ ] New `finalize-resume` skill exists with frontmatter and clear gates.
- [ ] The flow gates on a tailored resume JSON and active job.
- [ ] The flow runs `perfect` / `resume-tool fit`, including decision-driven or explicit auto-fit behavior.
- [ ] The flow runs `export-resume` after `perfect`.
- [ ] Export enforces the rendered `max_pages` hard gate and explains that fit is not submission-ready until
      export passes.
- [ ] The flow does not run resume preparation, job ingest, or tailoring updates.
- [ ] README and workflow docs show this flow can be run independently after delayed tailoring.

## Implementation Notes **[REQUIRED]**

### Technical Approach
- Reuse the existing `perfect` and `export-resume` skills/capabilities.
- Keep the page hard gate in export; `perfect` may warn/fit, but rendered output is authoritative.

### Dependencies
- Existing [[RIT-I-0021]] perfect/export implementation.
- Tailored resume output from Flow 3.

### Risk Considerations
- Do not make `finalize-resume` mutate master lineage (`original`/`base`/`structure`/`refine`).
- Preserve explicit decision/accounting behavior for trims.

### Recommended Agent
`sonnet + low` — mostly skill/docs composition over existing capabilities.

## Verification Steps **[REQUIRED]**

- [ ] Existing perfect/export tests still pass.
