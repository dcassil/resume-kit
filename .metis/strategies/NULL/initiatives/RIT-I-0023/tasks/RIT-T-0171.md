# T3: Flow 2 ingest-job

## Parent Initiative **[REQUIRED]**

[[RIT-I-0023]]

## Objective **[REQUIRED]**

Create the standalone `ingest-job` flow. It assumes `prepare-base-resume` has run at least once and uses the
prepared resume/learning base to parse a job and grow terminology learning before any tailoring checks.

## Acceptance Criteria **[REQUIRED]**

- [ ] New `ingest-job` skill exists with frontmatter and clear gates.
- [ ] The flow gates on an active prepared resume or recorded override plus learning state from Flow 1.
- [ ] The flow composes `parse-job` and `seed-terminology` / `learn-terminology`.
- [ ] The flow creates or grows `resume-kit/learning/synonyms.json` without dropping prior aliases.
- [ ] The flow registers `alias_file` through the code-owned `set-active` path.
- [ ] It is safe to run repeatedly for multiple jobs to deepen terminology learning before tailoring.
- [ ] The skill spelling is `ingest-job`; any user-facing docs may note it covers the originally requested
      "injest-job" concept.

## Implementation Notes **[REQUIRED]**

### Technical Approach
- Keep job parsing faithful to the existing `parse-job` skill; do not add a job faithfulness validator here.
- Reuse the conservative seed-terminology truth gate and confirmation semantics.
- Make the first-score alias-awareness reason explicit in the skill text.

### Dependencies
- Flow 1 prepared resume/learning state.
- Existing `parse-job`, `seed-terminology`, `learn-terminology`, and `set-active --alias-file`.

### Risk Considerations
- Do not auto-accept synonym candidates.
- Do not require rerunning Flow 1 for every job.

### Recommended Agent
`sonnet + medium` — mostly skill composition and docs, with light tests.

## Verification Steps **[REQUIRED]**

- [ ] Plugin skill markdown tests include `ingest-job`.
- [ ] Fixture test or documented manual gate proves aliases append/dedupe across two job ingests.
