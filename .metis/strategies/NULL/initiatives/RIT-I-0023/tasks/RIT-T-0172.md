# T4: Flow 3 tailor-resume

## Parent Initiative **[REQUIRED]**

[[RIT-I-0023]]

## Objective **[REQUIRED]**

Create the standalone `tailor-resume` flow for job-specific tailoring after Flow 1 and Flow 2 have prepared
the resume, job, and learning state.

## Acceptance Criteria **[REQUIRED]**

- [ ] New `tailor-resume` skill exists with frontmatter and clear gates.
- [ ] The flow gates on a prepared resume (`refine`/canonical output or recorded override), active job, and
      available learning/evidence.
- [ ] The flow runs first scoring: `check-keywords` and `check-gaps`, using `alias_file` when present.
- [ ] The flow routes truthful improvements through `update-keywords`, `update-terminology`, optional
      `rank-changes`, and the shared edit-session apply runbook.
- [ ] The flow runs `validate-facts` after committed changes.
- [ ] The flow re-runs scoring and reports deltas.
- [ ] The flow includes the existing optional `review-resume` offer and optional
      `interview-missing-job-description` branch when the second scoring remains low or required coverage is
      incomplete.
- [ ] The flow writes a tailored working resume and does not run `perfect` or export.

## Implementation Notes **[REQUIRED]**

### Technical Approach
- Extract the job-specific steps from the current `resume-workflow` into this standalone runbook.
- Keep direct JSON edits unsupported except through `review-edits reconcile`.
- Make the dependency on Flow 1 learning explicit: learning/evidence can prove true additions, but every edit
  still passes the existing gates.

### Dependencies
- Flow 1 prepared resume and evidence.
- Flow 2 active job and alias file.
- Existing update/check/validate/review/interview skills.

### Risk Considerations
- Keep `perfect` and export out of this flow; those belong to Flow 4.
- Do not let learning evidence turn into ungated auto-insertion.

### Recommended Agent
`opus + medium` — no major engine work expected, but the flow touches the highest-risk truth/edit path.

## Verification Steps **[REQUIRED]**

- [ ] Plugin skill markdown tests include `tailor-resume`.
- [ ] Flow documentation names all gates and handoffs accurately.
- [ ] If a composite command is added, cross-surface parity tests cover it.
