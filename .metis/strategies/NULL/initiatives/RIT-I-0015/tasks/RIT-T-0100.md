# Rewire skills onto the orchestrator + gate + reason enum

## Parent Initiative

[[RIT-I-0015]]

## Objective **[REQUIRED]**

Rewrite the improve-phase skills so the human-in-the-loop UX is *driven by* the code-owned orchestrator
and its hard gate instead of being reconstructed from prose. `inject-keywords`, `rank-edits`, and
`log-edit-feedback` become thin drivers over the new CLI/MCP surfaces; `resume-workflow` names the
orchestrated loop (mode prompt → per-change decide → apply-gate → truth) as an explicit, non-optional
step. This is what makes "the plugin objects when you skip the loop" true in practice.

## Context

The skills currently describe the loop but don't enforce it (`inject-keywords/SKILL.md:118`,
`resume-workflow/SKILL.md:60`), and `rank-edits`/`log-edit-feedback` are agent-only. With [[RIT-T-0099]]
landing real surfaces and a hard gate, the skills should call them, present the [[RIT-T-0096]] reason
enum on every reject/modify, and stop instructing the agent to hand-edit the working JSON.

## Acceptance Criteria **[REQUIRED]**

- [ ] `inject-keywords/SKILL.md` rewritten to drive the `review-edits` command group (per [[RIT-A-0001]]):
      `open-edit-session` with a **mode prompt** (interactive / review-at-end / auto), then per change
      `session-prompt` → `decide-change` (**offering the `EditFeedbackReasonCode` enum**, not free text) →
      `commit-session` (hard gate) → truth. No instruction to bulk-edit the working JSON directly; direct
      hand-editing is removed or explicitly marked as unsupported (and will trip tamper detection). Mention
      `reconcile-session` as the sanctioned path if the user intentionally hand-edits.
- [ ] `rank-edits/SKILL.md` rewritten to call `rank-edit-candidates` (CLI/MCP), passing `alias_file`;
      removes the "no CLI/MCP" note now that surfaces exist.
- [ ] `log-edit-feedback/SKILL.md` rewritten to call `record-edit-feedback` (CLI/MCP) with the reason
      enum + optional note, and to record `PreferencePair` where applicable; removes the stale
      "no CLI/MCP" and the PreferencePair doc/impl mismatch.
- [ ] `resume-workflow/SKILL.md` improve step names the orchestrated loop and the mode prompt as the
      sanctioned path; preference learning is no longer described as trivially optional/skippable within
      the loop.
- [ ] Any skill referencing `add-evidence`/user-confirmation points at the new `add-evidence --confirmed`
      command from [[RIT-T-0097]].
- [ ] `resume-kit/learning/*.md` guidance and README improve-phase docs updated to the new flow.
- [ ] Read-through check: every command referenced by the rewritten skills exists (from RIT-T-0096/0097/
      0099); no contradictory hand-edit guidance remains.
