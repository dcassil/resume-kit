# EditFeedbackReasonCode enum + reason_note + PreferencePair persistence (backward-compatible)

## Parent Initiative

[[RIT-I-0015]]

## Objective **[REQUIRED]**

Standardize *why* a user rejected or modified a proposed edit by adding a defined `EditFeedbackReasonCode`
enum (with an optional free-text `reason_note` retained), and close the codex-found doc/impl gap where
`log-edit-feedback` claims to store a `PreferencePair` but no persistence path exists. This gives the
deterministic ranker a structured signal instead of unstructured prose.

## Context

`EditFeedback.rejection_reason` is `str | None` with no enum
(`packages/schemas/src/resume_kit_schemas/feedback.py:57`); the `log-edit-feedback` skill only asks for an
"optional short reason." The tester explicitly proposed an enum (fabrication / grammar / formatting /
not-my-voice). Separately, `log-edit-feedback/SKILL.md:124` says it stores a `PreferencePair`, but
`append_edit_feedback` writes only `EditFeedback` JSONL
(`packages/feedback/src/resume_kit_feedback/log.py:37`) — the `PreferencePair` model exists
(`feedback.py:144`) but is never persisted.

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] `EditFeedbackReasonCode` enum/Literal defined with at least: `fabrication`, `overclaim`,
      `unsupported`, `grammar`, `formatting`, `not_my_voice`, `too_verbose`, `too_vague`, `wrong_emphasis`,
      `duplicate`, `other`. (`overclaim` distinguishes "true but inflated" from outright `fabrication` —
      called out in the final session review.)
- [ ] `EditFeedback` gains `reason_code: EditFeedbackReasonCode | None` and `reason_note: str | None`.
      The legacy `rejection_reason` field remains loadable for backward compatibility (retained-and-
      deprecated, or mapped into `reason_note` on read); existing `edit-feedback.jsonl` lines still parse.
- [ ] A `PreferencePair` persistence path exists: append-only writer/reader (mirroring
      `append_edit_feedback`/`read_edit_feedback`) under `resume-kit/learning/` with a stable filename,
      pure/deterministic (caller-supplied timestamps, no clock/network).
- [ ] The preference-derivation path (`packages/feedback/preferences.py`) can consume persisted
      `PreferencePair` records where relevant.
- [ ] Unit tests: enum round-trips; a legacy record with only `rejection_reason` loads without error;
      `PreferencePair` append + read round-trips and never rewrites prior lines.
- [ ] `__init__` public exports updated for the new symbols.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Add the enum in `packages/schemas/.../feedback.py`; keep `EditFeedback` frozen. Prefer adding
  `reason_code`/`reason_note` and treating `rejection_reason` as deprecated-but-accepted (map it into
  `reason_note` on construction if needed) so no history is lost.
- Add `append_preference_pair` / `read_preference_pairs` to `packages/feedback/log.py` following the exact
  append-only JSONL pattern already there.

### Dependencies
Independent; feeds [[RIT-T-0097]] (record-edit-feedback surface offers the enum) and [[RIT-T-0100]]
(skills present the enum). Sequenced after [[RIT-I-0014]].

### Risk Considerations
Low/medium — additive schema change; the only real risk is breaking `edit-feedback.jsonl` compatibility,
covered by the backward-compat test.

### Recommended Agent
**opus + low** — a couple of files, clear design; the only judgment is the backward-compat strategy.
