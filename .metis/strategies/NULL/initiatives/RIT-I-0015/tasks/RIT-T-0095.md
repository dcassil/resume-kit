# Truth-semantics fix: CONTRADICTED vs UNSUPPORTED + reason_code + synonym-aware validation + align-terminology hard-gate

## Parent Initiative

[[RIT-I-0015]]

## Objective **[REQUIRED]**

Make `validate-truth` trustworthy by fixing the semantic conflation between "absent from evidence" and
"contradicts evidence," attaching a machine-readable `reason_code` to every claim classification, making
candidate truth validation synonym-aware, and converting `align-terminology` from a truth *reporter* into
a truth *hard-gate*. This is the highest-trust-impact fix in the initiative: the tester praised
`validate-truth` as "the hero of the run," but it labeled a new-but-true skill `CONTRADICTED` at
confidence 1.0, which makes the strongest gate cry wolf.

## Context

`packages/evidence/src/resume_kit_evidence/truth.py` classifies claims. For ordinary free-text claims,
a zero-overlap claim correctly returns `UNSUPPORTED` (`truth.py:252`). **But** for skill / certification /
company values, `_fabricated_values()` (`truth.py:100`) reconstructs a "master" resume from the evidence
set and treats any such value **absent** from it as fabricated; `_classify()` then returns `CONTRADICTED`
at confidence 1.0 (`truth.py:168`). `test_contradicted_from_fabricated_skill` locks this in
(`packages/evidence/tests/test_truth_validation.py:125`). The schema already distinguishes `UNSUPPORTED`
from `CONTRADICTED` (`packages/schemas/src/resume_kit_schemas/provenance.py:23`), so the bug is purely in
the classifier's treatment of absence-as-fabrication.

Two related correctness gaps (codex-surfaced):
- `rank-edits` says to honor `alias_file`, but `FeatureContext` has no alias file and candidate truth
  validation is synonym-unaware (`packages/feedback/src/resume_kit_feedback/features.py:83`), so a
  truthful terminology alias of a supported term can be falsely hard-blocked.
- `align-terminology` computes `truth_passed` but returns the updated resume + a boolean without
  rejecting/reverting on failure (`packages/alignment/src/resume_kit_alignment/accept.py:254`) — it
  reports, it does not gate.

## Acceptance Criteria **[REQUIRED]**

- [ ] A skill / cert / company value **absent** from the evidence set classifies as `UNSUPPORTED`
      (not `CONTRADICTED`). `CONTRADICTED` is reserved for: (a) structural-invariant violations
      (dropped section, changed identity) and (b) a claim actively refuted by an evidence record.
- [ ] `ClaimProvenance` gains a `reason_code` field with at least: `missing_evidence`,
      `structural_conflict`, `refuted_by_evidence`, `unknown_skill`. Every classification path sets it;
      `UNSUPPORTED` → `missing_evidence`, structural failure → `structural_conflict`, etc.
- [ ] `TruthReport` summary distinguishes "needs evidence" (unsupported count) from "contradiction"
      (contradicted count) so a downstream gate can treat them differently (e.g. offer
      `add-evidence --confirmed` for the former, hard-block the latter).
- [ ] Candidate truth validation is synonym-aware: an `alias_file` threads into the validation/
      `FeatureContext` path so a truthful alias of a supported term is not hard-blocked. The alias
      resolution reuses the existing `resume-kit-terms` normalizer (no reimplementation).
- [ ] Token comparison folds trivial **morphological variants** so brittleness like `code review` vs
      `code reviews` (plural/singular) no longer causes a false `UNSUPPORTED`/`CONTRADICTED`. Prefer
      reusing/extending the existing `resume-kit-terms` normalizer (e.g. light stemming or plural folding)
      over a bespoke rule; document the exact folding applied. (Observed in a live session: `code review`
      ≠ `code reviews`, and `web accessibility` failed where bare `accessibility` passed.) Alias-level
      cases (`web accessibility` → `accessibility`/`WCAG`/`ARIA`) are handled by the alias path above; this
      criterion covers only inflectional variants, not semantic aliases.
- [ ] `align-terminology` rejects/reverts a suggestion that fails truth validation (hard-gate) rather than
      returning it with `truth_passed=false`; the rejection is surfaced with the reason.
- [ ] Backward compatibility: `reason_code` is optional/defaulted so existing `TruthReport` consumers and
      serialized reports keep loading; the pre-existing `UNSUPPORTED`-for-free-text behavior is unchanged.
- [ ] The obsolete `test_contradicted_from_fabricated_skill` expectation is updated to assert
      `UNSUPPORTED` + `missing_evidence` for an absent-but-not-refuted skill, with a NEW test covering a
      genuinely refuted claim → `CONTRADICTED` + `refuted_by_evidence`.
- [ ] All affected surfaces (facade/MCP/API `validate-truth`) reflect the new field; parity tests updated.

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Split `_fabricated_values()` intent: distinguish "not present in evidence" (→ `UNSUPPORTED` /
  `missing_evidence`) from "conflicts with an evidence record / structural invariant"
  (→ `CONTRADICTED`). The `validate_master_alignment` critical-violation path should only feed
  `CONTRADICTED` when it represents a genuine conflict, not mere absence.
- Add `reason_code` to `ClaimProvenance` (`packages/schemas/.../provenance.py`) as an enum/Literal;
  thread it through every `return ClaimProvenance(...)` in `_classify` and the structural-failure branch.
- Thread `alias_file` into truth validation; resolve via `resume-kit-terms` before token comparison so
  aliases collapse to a canonical form.
- In `packages/alignment/.../accept.py`, when `truth_passed` is false, reject the change (mirror the
  existing rejection path / `PolicyReasonCode.TRUTH_VALIDATION_FAILED`) instead of returning it.

### Dependencies
Independent of other RIT-I-0015 tasks; consumed by [[RIT-T-0097]] (ranker's `unsupported_claim_risk`) and
[[RIT-T-0099]] (edit-session truth gate). Sequenced after [[RIT-I-0014]].

### Risk Considerations
Medium/High — existing tests and consumers depend on current statuses. Mitigate with backward-compatible
optional `reason_code`, and update the single locked-in fabricated-skill test deliberately (documenting
the semantic change). Do not proliferate top-level `ProvenanceStatus` values — use `reason_code`.

### Recommended Agent
**opus + high** — load-bearing semantics that every truth gate and the ranker depend on; a wrong contract
compounds across RIT-T-0097/0099/0100.
