# Auto-grow alias/synonyms index from accepted terminology edits (self-healing token matching)

## Parent Initiative

[[RIT-I-0015]]

## Objective **[REQUIRED]**

Let the project `alias_file` **self-heal**: when a terminology edit is *accepted* in the edit session
(the user chose the employer's wording over the resume's), deterministically record the
`original → accepted` mapping as a candidate alias and append it to the project alias index (which the
engine already merges over the seed lexicon). Over time this absorbs the token-matching brittleness the
agent currently has to massage by hand, without ever adding an unconfirmed alias.

## Context

The `alias_file`/synonyms index is supposed to absorb token-matching brittleness (`web accessibility` vs
`accessibility`/`WCAG`/`ARIA`, employer-specific wording), but nothing grows it automatically — so the
agent ends up hand-massaging tokens each session. Meanwhile the edit session ([[RIT-T-0099]]) already
captures accepted terminology changes as first-class, human-approved decisions. Those accepted edits are
exactly the trustworthy source for new aliases: they are confirmed by construction, so auto-appending them
does not repeat the (rejected) idea of unconfirmed auto-aliasing. This complements the existing truth-gated
manual alias workflow (RIT-I-0009 / `manage-synonyms`) rather than replacing it.

## Acceptance Criteria

## Acceptance Criteria

## Acceptance Criteria **[REQUIRED]**

- [ ] A deterministic step derives candidate aliases from **accepted / accepted_modified** terminology
      edits recorded in the session (source term → accepted term), reusing the `resume-kit-terms`
      normalizer for canonicalization. Rejected/undone edits never produce aliases.
- [ ] Candidate aliases are appended to the **project** `alias_file` (never the bundled seed lexicon),
      through the existing project-alias merge/loader path; append is idempotent (no duplicate entries)
      and preserves provenance (e.g. `source: "accepted_edit"`, timestamp supplied by caller).
- [ ] Surfaced as a capability + `review-edits`/CLI step (e.g. run automatically on `commit-session` of an
      accepted terminology edit, or an explicit `grow-aliases` command) with MCP/API parity where the
      norm calls for it.
- [ ] Guardrail: only terminology/wording edits (not arbitrary content edits) feed the alias grower; a
      malformed or empty mapping is skipped, not written. No network, no LLM.
- [ ] Round-trip test: an accepted terminology edit produces a project alias that then makes the
      previously-brittle token match end-to-end (e.g. accepting the employer's phrasing lets a later
      `match`/`validate-truth` recognize the resume term as equivalent).
- [ ] Docs: `manage-synonyms`/README note the auto-grow path and that it only learns from accepted edits.

## Test Cases **[CONDITIONAL: Testing Task]**

### Test Case 1: Accepted edit grows an alias
- **Test ID**: TC-001
- **Steps**: accept a terminology edit (resume term → employer term) in a session; inspect the project
  alias file.
- **Expected Results**: a new provenance-tagged alias entry; a subsequent match recognizes the pair.
- **Status**: Pass/Fail

### Test Case 2: Rejected edit grows nothing
- **Test ID**: TC-002
- **Steps**: reject a terminology edit.
- **Expected Results**: no alias written.
- **Status**: Pass/Fail

## Implementation Notes **[CONDITIONAL: Technical Task]**

### Technical Approach
- Reuse the project-alias merge hook and loader (RIT-T-0068/0069) for the write path; reuse
  `resume-kit-terms` normalization for canonical keys. Hook the derivation into the session's
  `decide-change`/`commit-session` path for accepted terminology actions.
- Keep it purely additive to the project alias file; the seed lexicon is never mutated.

### Dependencies
Blocked by [[RIT-T-0099]] (accepted-edit signal comes from the session). Relates to the existing
truth-gated alias workflow (`manage-synonyms`, RIT-I-0009).

### Risk Considerations
Medium — the main risk is polluting the alias index; mitigated by learning ONLY from human-accepted edits,
idempotent appends, provenance tagging, and confining input to terminology actions.

### Recommended Agent
**opus + medium** — integration across the session, the terms package, and the project-alias path; follows
established patterns.
